# 아기 울음 육아 도우미 보안 인수 시험

버전 1.1 · 2026년 9월 19일 · [보안 설계서](./보안%20설계서.md) 대응

이 문서는 구현 후 실행할 전체 시험 계획이다. 초기 작성 시 모든 항목은 미실행이었다. 2026-09-19 B-03과 9월 20일 B-04/B-09의 로컬 DB·RLS·STANDARD Storage·실제 Auth API 하위 시험 결과와 미실행 범위는 [Supabase 구현·검증 기록](../../supabase/README.md)에 분리해 남겼다. 그 하위 시험만으로 업무 API·브라우저·TUS·운영까지 포함한 개별 SEC 전체를 통과 처리하지 않는다. B-09는 폴링의 현재 권한 검사와 누락 복구만 검증했으며 Realtime을 켜지 않았으므로 SEC30·SEC31은 여전히 미실행이다. 설계서 작성, OpenAPI 구조 검사, 가상 응답 검사도 아래 실제 권한·저장소 시험의 통과를 대신하지 않는다.

## 1 시험 구성

개발 전용 환경과 합성 기록, 사용 권리가 확인된 테스트 음원만 사용한다. 외부 사람의 계정·데이터·실제 운영 주소에 시험 요청을 보내지 않는다.

| 시험 계정 | 조건 |
|---|---|
| owner_a | baby_a OWNER, baby_b CAREGIVER |
| caregiver_a | baby_a CAREGIVER |
| owner_b | baby_b OWNER, baby_a 비구성원 |
| invited_a | 지정 초대를 받았으나 미가입인 사용자 |
| removed_a | baby_a의 과거 구성원, 기존 기여와 동의 이력이 있는 사용자 |
| curator | 별도 검수 권한, 보호자용 전체 조회 권한 없음 |

같은 아기의 확정 기록, 작성자별 미확인 초안, 두 아기의 같은 종류 기록, 미보관 임시 음원, 7일 보관 음원, 30일 학습 사본, 삭제 및 철회 중인 자료를 준비한다. 시간 만료는 시험 환경의 통제된 시계·만료값으로 재현한다.

API 시험은 화면을 통하지 않고 HTTP 요청을 직접 보낸다. DB·Storage·Realtime 시험은 실제 일반 사용자 JWT와 publishable key로 실행한다. 모든 권한 시험을 service_role로 실행해서는 안 된다. 서버 자체의 RLS 우회 경로는 별도 묶음으로 시험한다.

각 시험에는 코드·DB migration·모델·정책 버전, 환경, 시각, 요청 ID, 사용자 역할, 입력 자료 출처, 기대값, 실제값, 증거 위치를 남긴다. 로그·증거 파일에는 살아 있는 토큰이나 개인정보 본문을 넣지 않는다.

## 3 실행 순서와 판정

총 62개 시험은 모두 설계된 항목이며 이 문서 작성 중 실행하지 않았다. 첫 통합에서는 SEC01~SEC24로 권한과 공유 기록을 확인한다. 파일·브라우저·외부 LLM·학습·삭제·운영 시험을 이어 수행하고, A의 기술 구성은 SEC57~SEC62로 보완한다. 기존 기능명세 AC01~AC44를 대체하지 않는다. 담당 업무별 순서는 [A·B 보안 작업 연결표](./AB%20보안%20작업%20연결표.md)를 따른다.

필수 경로 하나라도 권한 우회·다른 아기 노출·비밀키 노출·동의 없는 외부 전송·삭제 자료 재등장을 허용하면 해당 기능의 실제 데이터 사용은 출시 불가다. 단순 오류 문구나 폴링 성능 문제도 기록하되 같은 위험으로 합산하지 않는다.

외부 LLM 미사용 상태에서 SEC35는 통과할 수 있지만 SEC36이 미충족이면 외부 정규화를 활성화하지 않는다. Realtime 회수 시험을 통과하지 못했으면 폴링으로 공유 기록을 제공할 수 있다. 학습 내보내기 미검증이면 내보내기만 비활성화한다. 이 경우 전체 P0 완료 여부는 기능명세 기준으로 별도 보고한다.
