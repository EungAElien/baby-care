# A·B 보안 작업 연결표

2026년 9월 20일 · 보안 설계 1.1 부록 · B-04 로컬 구현 상태 반영

이 표는 [A 업무 분담 기준본](../baby-care-implementation-tasks-A-v2.md)의 A-01~A-11과 [B 업무 분담 기준본](../baby-care-implementation-tasks-B-v2.md)의 B-01~B-13에 원래 보안 작업을 연결했다. 업무 분담 v2.1이 추가한 A-12·A-13·B-14와 CHAT/CHAR는 두 기준본에서 미실행 후속 업무로 관리한다. 기존 역할을 유지한다. **A는 사용자 기기의 노출·수집·상태 전환을 맡고, B는 실제 권한·저장·외부 전송·삭제를 강제한다.** UI에서 버튼을 숨기는 것만으로 권한 검사가 끝나지 않는다.

세부 정책은 [보안 설계](./보안%20설계서.md), 검증 절차는 [62개 보안 인수 시험](./62개%20보안%20시험표.md)을 기준으로 한다. 이 표 전체가 보안 완료 보고는 아니다. 다만 재인증·세션 회수·아동 처리 확인의 B-04 하위 범위는 [개발계약 1.1.0](../../contracts/개발계약.md)과 [OpenAPI](../../contracts/openapi계약.json)에 확정하고 실제 로컬 API·DB·STANDARD Storage로 검증했다. 외부 처리 게이트·초안 자동 만료·상담과 운영/브라우저 시험은 계속 제안 또는 미실행으로 구분한다.

## 2 문서 사이의 차이와 적용 결정

| 쟁점 | 읽은 문서의 차이 | 이번 설계에서 적용할 기준 |
|---|---|---|
| 아기 전환 시 초안 | A-03은 폐기 원칙, 최신 팀 계약은 전환 전 저장·폐기 선택까지 구체화 | 계속 작성·개인 초안 저장 후 전환·버리고 전환 중 선택. 전환 후 이전 로컬 초안·조회 캐시·재생 URL·원시 음원 폐기. 저장한 서버 초안만 권한 확인 후 다시 조회 |
| Supabase 직접 접근 | A 문서는 RLS로 허용한 데이터까지 넓게 기술, 팀 계약은 업무 Data API/RPC 목록 비움 | Auth·등록된 Storage 업로드·서버 발급 재생·검증된 변경 신호만 직접 이용. A가 업무 테이블을 직접 조회하지 않음 |
| 즉시 권한 회수 | A의 완료 기준은 해제 후 재접근 금지, v2는 최대 60초 재생 링크 허용 | 새 API·업로드 허가·재생 링크는 차단. 기존 링크의 잔여 수명과 이미 전송한 바이트는 회수 한계로 명시. 즉시 파일 회수가 필수이면 인증 스트리밍으로 계약 변경 |
| Realtime | A/B 문서는 아기별 비공개 채널, 제공자는 연결 중 권한 캐시 가능 | 공용 baby 채널만으로 회수 보장 금지. 현재 구성원별 전송 시험을 통과시키거나 기존 changes 폴링 사용 |
| 외부 LLM | B-07에 store false와 제공자 정책 확인, 실제 승인 상태는 미확인 | 아동 개인정보 처리 조건·필요한 ZDR·모델/endpoint·국외 처리 조건 확인 전 실사용 외부 정규화 비활성. 선택지/MANUAL 및 합성 시연 유지 |
| API 보완 | 검토 당시 OpenAPI 1.0.0에는 최근 재인증·세션 회수·아동 처리 경로가 없었음 | 세 항목은 계약 1.1.0에 확정하고 B-04 로컬 구현 완료. 외부 처리·초안 만료 등 미채택 항목은 계속 제안으로 표시 |

아기 전환 전 초안 저장을 골랐는데 실패하면 전환을 완료하지 않고 재시도·폐기·계속 작성 경로를 보여준다. 권한을 잃은 경우 다른 아기에 대신 저장하지 않는다. 로그아웃·계정 변경·권한 해제 때는 미전송 입력을 자동 저장하지 않는다. 두 아기 화면을 동시에 사용해도 활성 아기 선택을 서버의 전역값으로 쓰지 않는다.

## 3 계약 1.1.0 반영 항목과 남은 제안

최근 재인증·세션 회수·아동 처리 확인은 OpenAPI 1.1.0에 경로·필드·오류를 확정했다. 업로드·변경 전송·삭제의 기존 조건은 유지하고, 외부 처리 게이트와 초안 자동 만료는 아직 확정 endpoint가 없는 제안이다.

| 추가 계약 | B의 보장 | A의 동작 |
|---|---|---|
| 최근 재인증 challenge — 1.1.0 확정·로컬 검증 | 사용자·세션·작업·아기에 묶은 일회용 증명, 단순 토큰 갱신과 구분 | REAUTH_REQUIRED를 받으면 새 OTP 확인, 본래 작업을 같은 범위에서 재시도 |
| 세션 회수 — 1.1.0 확정·로컬 검증 | 서버 회수 기록과 제공자 refresh 종료, DB/API/Storage 공통 검사 | 로컬 녹음·표시는 즉시 정리, 제공자 실패와 서버 완료 여부를 별도 표시 |
| 아동 정보 처리 확인 상태 — 1.1.0 확정·fail-closed | GuardianVerification 범위·버전·확인 이력에 따라 운영 처리를 허용 | 서비스 OWNER와 법정대리인 확인을 혼동하지 않고 미확인 수집 경로 차단 |
| 외부 정규화 이용 가능 상태 — 남은 제안 | 서버 설정만으로 실사용 전송을 허용, 요청의 DEMO 값으로 우회 불가 | 이유와 수동 경로 표시, 버튼 숨김만으로 전송 차단을 대신하지 않음 |
| 업로드 허가 | 고정 Storage 출처·정확한 경로·15분·25,000,000바이트 상한 | 지정 범위에만 사용자 JWT 사용, 만료·중단 후 임의 경로 생성 금지 |
| 변경 전송 방식 | 검증된 멤버십별 채널 또는 버전 기반 changes 조회 | 전송 방식과 무관하게 실제 데이터는 재인증된 API 조회 |
| 삭제 진행 세부 정보 | 접근 제외, 운영 사본 정리, 일부 실패, 백업 잔존, 모델 영향 구분 | 처리 중·일부 실패를 완료로 표시하지 않고 재시도 가능 상태 안내 |
| 초안 수명 — 남은 제안 | 서버 미확인 초안 최대 7일 제안, 만료·삭제 상태 반환 | 만료 안내와 복구 불가 상태 표현. 탭의 미전송 텍스트는 서버 보관과 구분 |

## 4 첫 통합에서 볼 실제 시나리오

1. B-01에서 오류·세션·직접 접근 범위를 고정하고 A-01·A-03이 합성 fixture로 화면을 만든다. 법정대리인 확인·외부 제공자 설정이 미완료인 동안 실제 가족 자료를 넣지 않는다.
2. OWNER와 CAREGIVER가 같은 아기 기록을 읽고 쓰며, 타인의 미확인 초안은 OWNER도 보지 못하는지 확인한다. 다른 아기의 ID로 바꾸는 요청은 별도로 직접 실행한다.
3. 짧은 음원을 업로드해 분석 또는 유보를 받고, 원문을 확인해 한 번만 저장한다. 다른 보호자는 변경 신호 또는 폴링 후 확정 기록만 받는다.
4. 업로드·정규화·수정 중 구성원을 제거한다. 오래된 JWT, 구독을 끊지 않는 클라이언트, 늦은 완료 응답, 기존 재생 링크를 각각 시험한다. 링크의 잔여 수명은 별도 기록한다.
5. 계정·아기를 바꾸고 다시 돌아온다. 이전 아기 기록·재생·미전송 내용을 다른 범위에서 표시하거나 자동 전송하지 않는지 확인한다.
6. 학습 동의를 철회하고 음원·원문·전체 아기를 각각 삭제한다. 화면 상태뿐 아니라 Storage·파생물·묶음·정리 Job 증거를 확인한다.

이 시나리오만으로 전체 P0가 끝나지는 않는다. A-02·A-10의 30분 전경 기기 시험, B-02의 권리·모델·외부 처리 검증, B-12의 학습 계보, B-13의 실패·복원 시험과 전체 기능 인수 기준을 이어 완료한다.

## 5 출시 때 제출할 증거

| 책임 | 제출할 결과 |
|---|---|
| A | 지원 기기·브라우저 버전표, 두 계정 Playwright 결과, 전환·마이크·CSP·캐시·오류 복구 증거 |
| B | API·DB·Storage 직접 허용/거부 결과, 서버 키·IAM 설정, 외부 처리 게이트, 삭제·철회·복원 결과 |
| A+B | SEC01~SEC62의 통과·실패·미실행·비활성 사유, AC01~AC44 결과, 남은 결함의 담당·조치 |
| 운영 책임자 | 실제 제공자·국가·보관·수탁 조건, 법정대리인 확인 절차, 개인정보 안내, 사고 연락 경로 |

문서만 완성되었거나 모의 응답 화면이 동작하는 상태는 보안 검증 통과로 표시하지 않는다. 외부 LLM과 학습 내보내기가 조건을 충족하지 못했다면 해당 기능은 꺼 둔 상태를 정확히 기록한다.
