담당: 예준님(B)

기준: [개발 원칙](../DEVELOPMENT_PRINCIPLES.md), [PRD v2](./baby-care-prd-v2.docx), [기능명세 v2](./baby-care-functional-spec-v2.docx), [개발계약 v1.1.1](../contracts/개발계약.md), [OpenAPI 계약](../contracts/openapi계약.json), [목 응답·시험 사용자 배치](../contracts/목%20응답과%20시험%20사용자%20배치.json)

이 문서는 구현 체크리스트다. 제품 범위는 PRD v2, 기능 동작과 인수 조건은 기능명세 v2, API 필드·상태·오류·권한의 구체값은 개발계약과 OpenAPI를 따른다. B는 FastAPI, Supabase 데이터·권한·Storage, PyTorch M2D, 정규화와 개인화 상담, 운영을 주도한다. A는 화면·브라우저·캐릭터 자산과 재생을 맡는다. P0에서 Spring, 별도 Redis·Kafka·벡터 DB, 자동 재학습은 추가하지 않는다.

## 이번 개정에서 달라진 일

업무 분담 v2.1과 API 계약 1.1.1은 별개다. 기존 B-01~B-13과 **B-14 개인화 상담**의 역할은 유지하면서 B-04의 로컬 구현·검증 및 B-09의 폴링 복구 상태를 반영했다. 체크는 계약, 로컬 서버, 브라우저·운영 완료를 구분한다. [A 실행 태스크](./baby-care-implementation-tasks-A-v2.md)의 변경 설명과 같은 분담을 따른다.

| 반영 영역 | B의 책임 | A와 주고받을 것 |
| --- | --- | --- |
| 개인화 상담 | B-14: 본인 대화와 권한 있는 아기 기록을 결합, 서버 조회 도구·LLM·근거·기억·삭제 구현 | A-13에 상담 계약·목 응답·오류/복구 상태 제공. A는 개인 채팅·근거·확인 카드 구현 |
| 부모·아기 캐릭터 | B-06·B-07: 분석 추정, 확인된 행동, 관찰 상태의 ID·버전·시각·출처 제공 | A-07·A-12와 의미 연결표 확인. 원본 그림·모션·웹 플레이어는 A 담당 |
| 보안 | B-01~B-13: 현재 권한, 세션 회수, Storage, 외부 처리 차단, 삭제·복원·운영 검증 | A는 브라우저 노출·전환·안내 확인, B는 서버·DB·Storage 증거 확인 |

현재 OpenAPI에는 상담 경로가 없다. B-14에서 계약·OpenAPI·목 응답·화면 매핑·관련 인수 조건을 함께 확장한 뒤 A-13과 실제 연동한다. B-04 재인증·세션 회수·아동 처리 게이트는 1.1.0에, B-09 변경 조회 의미는 1.1.1에 확정했다. 초안 자동 만료 등 나머지 제안은 계속 구분한다. 기존 P0와 AC01~AC44, 첫 통합 시연은 유지한다.

LLM 설계 재대조에서는 기존 B-14의 개인화·권한·기억·삭제 원칙을 유지하고, 분석 결과 없는 자유 질문, 조회 실패와 기록 없음의 구분, 대화 속 진술의 출처, 단계별 착수 조건을 보강했다. 사용자는 2026년 9월 20일 정규화·상담 LLM으로 **OpenAI GPT-5.6 Terra (`gpt-5.6-terra`)**를 선택했다. 이는 구현할 업무와 사용할 모델의 결정이며, 상담 API·DB·실제 제공자 연결·처리 조건의 검증 완료는 아니다.

모델 연결 기준은 OpenAI Responses API다. [공식 GPT-5.6 Terra 문서](https://developers.openai.com/api/docs/models/gpt-5.6-terra)에서 API 모델 ID와 Function calling·Structured Outputs 지원을 2026년 9월 20일 확인했다. 사용자가 생성할 API key는 B가 서버 비밀 저장소에 설정하며 프런트엔드·저장소·대화/로그에 기록하지 않는다. 실제 키 생성·서버 등록·계정별 모델 접근·호출 시험은 아직 확인하지 않았다. 정규화/상담은 같은 모델을 사용하되 프롬프트·도구·출력 형식·호출 한도·검증을 분리한다.

## 담당 표시와 완료 원칙

- **[Codex]**: 계약·구현·목 응답·관련 시험과 결과 정리를 맡길 수 있는 일.
- **[직접]**: B 또는 A/B·운영 책임자가 설정·정책·제품 판단과 실제 결과 확인을 책임지는 일. 조사·초안·자동화는 Codex가 지원할 수 있으며 승인된 작업을 다시 승인받는 표시는 아니다.
- **[Codex → 직접 확인]**: 구현·자동 검증 후 B가 실제 API·DB·Storage·모델 결과를, A가 관련 화면·브라우저를 확인할 일.

체크는 계약 작성, 코드 작성, 로컬 시험, 실제 서비스 시험을 구분한다. B-03/B-04가 일부 SEC의 로컬 DB·API·STANDARD Storage 하위 조건을 실행했지만 브라우저·운영·TUS·기존 재생 URL을 포함한 전체 SEC 통과는 아니다. CHAT/CHAR는 미실행이다. 사용자별로 모델을 따로 학습시키거나 API key를 발급하지 않는다.

## 기존에 확정한 계약과 A에게 전달할 것

- [x] **[계약 확정]** 아기·멤버십·초대·동의·음원·사건·분석·행동·정규화 초안과 B-04 재인증·회수·아동 처리 게이트는 개발계약 1.1.0과 OpenAPI에 정리돼 있다. 계약 확정과 각 후속 서버 구현은 구분한다.
- [x] **[계약 확정]** 업무 데이터는 FastAPI로 통일한다. 브라우저의 직접 연결은 Auth·등록된 private Storage 업로드·발급된 재생 URL·권한 있는 비공개 변경 신호에 한정한다. 업무 Data API·RPC 직접 접근 허용 목록은 비어 있다.
- [x] **[계약 자료]** 목 응답·시험 사용자 별칭과 REAL/STUB·USER/DEMO 구분이 있다. [정적 검증 기록](../contracts/validation.json)은 60개 경로·70개 작업·127개 스키마와 응답 예시 58개 등을 검사했으며 실제 API·RLS·기기·모델 검증은 아니다.
- [ ] **[Codex → 직접 확인]** 실제 FastAPI를 계약에 맞추고 A에게 개발 주소, 권한별 시험 계정의 로그인 방법·역할·아기 배치, Storage 시험 환경을 제공한다. 가상 `.invalid` 이메일이나 예시 UUID를 실제 계정으로 취급하지 않는다.
- [ ] **[Codex]** B-14 상담과 아직 남은 보안 확장에 필요한 계약 변경을 이유·화면 영향·호환성·기존 진행 요청 영향과 함께 작성한다. B-04 보안 변경은 1.1.0에서 OpenAPI·목 응답·생성 타입·A 인계를 함께 갱신했다.

## 보안 계약 확정 및 실제 데이터·기능 활성화 조건

이 조건은 실제 자료·외부 LLM·Realtime 등 해당 기능의 활성화 조건이다. 합성 자료, 목 화면, 계약 초안과 시험 준비를 중단하는 공통 착수 조건이 아니다.

| 작업 | B가 구체화할 계약·조건 | A의 연결 / 현재 상태 |
| --- | --- | --- |
| B-01·B-04 | 최근 재인증 challenge와 작업·아기·세션에 묶인 일회용 증명, 서버 세션 회수와 실패 응답 | 계약 1.1.0·로컬 API 반영. A-03 브라우저 OTP·캐시·상태 화면 확인 필요 |
| B-01·B-03 | 토큰 수명·브라우저 저장 방식과 실제 회수 적용 범위 | A-01·A-03. 탭 세션 저장·access token 15분·최근 인증 5분은 설계 제안값. 저장 방식 자체는 API가 아닌 구현 결정 |
| B-04 | 아동 정보 처리 확인의 범위·정책 버전·증빙·미확인 처리 | 1.1.0 게이트와 fail-closed 상태 반영. 실제 확인 수단·증빙 정책은 미결정 |
| B-02·B-07 | 기존 `normalizer_available`의 기술적 준비/외부 처리 허용 의미, 차단 사유와 서버 강제 | A-07. 필드가 없다고 새로 중복 정의하지 않음. 상담 허용은 B-14에서 별도 정의 |
| B-03·B-07 | 미확인 초안의 수명·만료·삭제·늦은 결과 차단 | A-07. 초안 최대 7일은 제안이며 음원 보관 7일·멱등성 최소 7일과 별개 |
| B-09 | 전경 5초 `/changes` 조회를 기본으로 제공, 회수 시험 통과 후 Realtime 활성화 | A-08. 숨김 중지·복귀 재조회·실제 반영 지연 측정 |
| B-12·B-13·B-14 | 외부 처리·학습·공개 시연별 권리, 삭제·백업 복원·대화 파생물 수명 | A-03·A-13. 실제 조건·증거를 기능별로 확인 |

B·운영 책임자는 내부 시험, 공개 시연, 외부 전송, 학습 이용의 권리를 각각 확인한다. 외부 LLM에는 제공자·모델·endpoint·보관·국외 처리·아동 정보 처리 조건과 필요한 ZDR 적용 여부를 실제 설정으로 확인한다. `store:false`, 가명 처리, DEMO 표시만으로 충족됐다고 보지 않는다. 미확정 동안 실사용 외부 전송은 차단하고 합성 자료나 해당 목적이 허용된 시험 자료를 사용한다. 참조 설계의 정책 설명은 구현 시 최신 공식 조건과 대조한다.

## B-01. 서버 기반과 계약

선행: 기존 계약 확보. A-01과 병행해 서버 기반과 추가 계약을 준비한다.

- [x] **[Codex]** FastAPI·Pydantic 프로젝트, API 버전, OpenAPI, 공통 오류와 `request_id`를 구성한다. 입력/출력 필드 허용 목록으로 작성자·권한·출처·내부 실행 토큰 조작과 노출을 막는다.
- [x] **[로컬 구현·검증]** 실제 로컬 Supabase JWT의 서명·허용 알고리즘·issuer·audience·만료·subject·session을 JWKS로 검증하고 현재 DB 멤버십·아기 상태·객체 권한을 공통 계층에서 검사했다. 운영 프로젝트의 키 교체·설정은 B-13에서 다시 확인한다.
- [x] **[로컬 구현·검증]** UUID 멱등 키, 기록 `version`, 입력 `input_revision`, 서버 실행 토큰을 분리했다. 같은 키의 다른 본문과 오래된 버전·revision은 409이며, 업무 변경과 멱등 결과 참조는 같은 DB 트랜잭션에 저장된다.
- [x] **[계약·로컬 구현]** 재인증·세션 회수·아동 처리 게이트를 계약 1.1.0과 실제 API·DB·STANDARD Storage에 적용하고 정상/거절/제공자 실패 목을 추가했다. 초안 자동 만료와 외부 처리 허용은 아직 후속 계약·구현이다.
- [x] **[Codex]** pytest, 정적 검사, 컨테이너 빌드, 잠금 파일, GitHub Actions를 구성한다. 일반 업무 API 인증 전에 디코딩·모델·LLM 같은 비용 큰 작업을 실행하지 않는다.

2026년 9월 19일에는 `/health/live`와 fail-closed `/health/ready`, 계약 1.0.0 공통 오류, 첫 공동 기록 모델과 CI 기반을 만들었다. 9월 20일 B-04에서 계약을 1.1.0으로 올리고 실제 로컬 JWT/JWKS·세션 회수·현재 DB 권한·DB 멱등성·충돌 처리를 연결했다. 운영 프로젝트 설정, 초안 만료, 외부 처리 게이트와 전체 SEC 인수는 남아 있으므로 B-01 전체 운영 완료로 확대하지 않는다.

완료 기준: A가 같은 계약·목으로 화면을 만들 수 있고 인증·권한·중복·오류의 서버 검증이 재현된다. 보안: SEC01~SEC12, SEC17~SEC20, SEC49~SEC52.

## B-14. 아기 기록 기반 개인화 상담 API·데이터·LLM

### ① 상담 계약과 데이터·권한

- [ ] **[Codex → 직접 확인]** 대화방·메시지·응답 실행·개인 기억·근거 ID/버전의 저장 구조와 생성/목록/조회/삭제·복구·중단 계약을 작성한다. 구체 경로·상태·전송 방식은 팀 계약·OpenAPI·목·화면 매핑·시험을 함께 갱신해 확정한다. 분석 상태 enum을 상담에 억지로 재사용하지 않는다.
- [ ] **[Codex]** 일반 육아 정보·간단한 고민 대화, 개인 기록 질문, 기록 남기기의 처리 흐름을 A-13과 맞춘다. 녹음·분석 이력 없이도 질문할 수 있고 일반 질문에 불필요한 개인 기록 조회를 강제하지 않는다. 답변 본문·개인 기록 근거·일반 정보 출처·조회 범위/한계·추가 질문·기록 후보를 구분해 전달할 계약과 샘플을 작성한다. 위험 질문은 기존 안전 안내 기준을 적용한다.
- [ ] **[Codex]** 대화방을 `user_id + baby_id` 범위에 연결하고 본인만 읽게 한다. OWNER도 다른 보호자의 대화·고민·기억은 볼 수 없다. 공유 확인 기록은 현재 멤버십으로 조회하며 초안·개인 알림·타인 상담을 섞지 않는다.
- [ ] **[Codex → 직접 확인]** 대화 원본과 개인 기억은 우리 DB에서 관리한다. 대화 요약은 보조 자료이며 아기 상태·기록은 매 요청에서 현재 값을 조회한다. 선호/기억은 본인이 저장·수정·삭제하고, 대화·기억·공동 기록 삭제 범위와 각각의 보관 기간을 계약에 명시한다. 초안 7일 제안을 상담 전체에 자동 적용하지 않는다.

### ② 맥락 조회·LLM·근거

- [ ] **[Codex]** 정규화와 상담 모두 OpenAI Responses API의 `gpt-5.6-terra`를 사용하되 프롬프트·허용 도구·출력 검사·실행 이력을 분리한다. 정규화에 상담 조회 권한을 넘기지 않는다. 서버 설정과 실제 응답의 모델·프롬프트/스키마 버전·사용량을 기록하고 미연결·실행 전 실패를 실제 실행 완료로 표시하지 않는다.
- [ ] **[Codex]** PostgreSQL의 날짜·기록 종류·사건 조회부터 시작한다. 허용 도구는 기간별 확인 기록, 서버 계산 집계, 적격 이전 사례, 검수된 육아 정보 검색으로 한정한다. 사용자·아기는 서버 인증 문맥으로 고정하고 모델이 넘긴 ID로 넓히지 않는다. 임의 SQL·외부 URL·자유로운 쓰기 도구는 제공하지 않는다.
- [ ] **[Codex]** 분석 없는 질문은 B-04의 확인 기록과 질문의 기간·종류를 이용해 조회한다. 기존 `getSimilarCases`는 `analysis_id`가 필수이므로 임의 ID를 만들거나 임의의 과거 분석에 질문을 연결하지 않는다. 분석과 무관한 검색이 필요하면 B-14의 서버 조회 도구/관련 계약으로 따로 정의하며 기존 분석 기반 사례 조회의 의미는 유지한다.
- [ ] **[Codex → 직접 확인]** 자료 조회 성공, 지정 범위의 기록 없음, 도구 미준비, 권한 거절·조회 실패를 구분해 반환한다. 실패·미구현을 빈 기록이나 실제 0으로 변환하지 않는다. 일부 조회가 실패하면 확인된 범위만 답하고 빠진 범위를 표시한다. 개인화 근거를 확보하지 못했을 때 일반 정보를 제공한다면 아기 기록을 확인한 답변처럼 표현하지 않으며 권한 회수·삭제 차단은 우회하지 않는다.
- [ ] **[Codex]** 최근 대화 + 필요한 이전 요약 + 질문에 관련된 최신 기록 + 본인 저장 선호 + 검수된 자료로 입력을 구성한다. 필요한 월령/기간 정보만 사용하고 계정 ID·이메일·원시 음원·전체 이력을 통째로 보내지 않는다. 입력 길이·조회 기간/건수·도구 횟수·동시 실행·출력·비용 상한을 서버에서 둔다.
- [ ] **[Codex]** 확인된 DB 기록, 대화 중 보호자 진술, LLM이 생성한 설명/추정, 사용자가 저장한 선호의 출처를 보존한다. 대화 진술은 해당 대화에서 진술로 활용하되 확인 기록·프로필·장기 기억으로 자동 승격하지 않는다. 앞선 LLM 답변을 새 사실의 근거로 삼지 않고, 기록과 진술이 상충하면 차이를 설명하고 필요한 확인을 요청한다. '그때', '지난번' 같은 후속 질문은 같은 대화의 대상을 확인하고 관련 최신 기록을 다시 조회한다.
- [ ] **[Codex → 직접 확인]** 답변의 근거 기록 ID·버전·관찰 시각·조회 기간, 일반 정보 출처·검토일을 보존한다. 수유 횟수·수면 시간 등 숫자는 서버 계산을 사용하고 기록 없음·미상·실제 0을 구분한다. 기록 부족·패턴 보류는 추가 질문/한계 표시로 반환하고 행동 후 반응을 인과관계나 진단으로 단정하지 않는다.

### ③ 기록 연결·복구·삭제와 외부 처리

- [ ] **[Codex]** ‘분유 먹이고 안아줬더니 진정됐어’에서 기존 정규화의 행동·관찰 초안만 만든다. A-13 확인 카드에서 수정·확인해야 기존 기록 API로 원자 저장한다. 일반 대화는 별도 확인 없이 진행하고 상담 권유·계획·부정은 수행 라벨이나 학습 자료로 만들지 않는다.

- [ ] **[Codex → 직접 확인]** 원본 수정·삭제·멤버십 회수 시 연결된 대화 요약·개인 기억·검색 자료·저장 답변/인용을 무효화·재계산·삭제/가림 처리한다. 인용 링크만 끊고 삭제한 사실의 복사본을 답변 본문에 남기는 방식은 허용하지 않는다. 아기 접근을 잃은 사용자의 과거 대화에서도 해당 아기 자료가 새로 제공되지 않게 하며 권리 요청 경로는 별도 유지한다.

## 첫 통합 시연 목표

B-03~B-07·B-09와 A의 대응 화면으로 **두 보호자 로그인 → 녹음 → 실제 분석 또는 정직한 유보 → 행동·상태 확인 기록 → 다른 보호자 화면 반영**을 먼저 완주한다. STUB/fixture는 개발 연결 확인이다. 상세 캐릭터와 신규 상담을 첫 시연의 추가 선행 조건으로 만들지 않는다. 활성 감지·요약·학습 후보와 내보내기는 이후에도 기존 P0 완료 전 모두 검증한다.

B-02의 권리·데이터 처리·모델 검증은 병행하되 해당 실제 자료·기능을 사용하기 전에 충족한다. 목·합성 자료 개발, 실제 API 인수, 실제 외부 LLM, 전체 P0 완료를 구분한다.

## 반영한 설계 대화

아래 대화 링크는 v2.1 업무가 만들어진 역사적 출처 기록이다. 현재 개발 기준은 위의 저장소 상대 링크로 연결한 기준본·계약·보안 문서다.

- [LLM 개인화 상담 기능 설계](thread://01a0b957-ac96-7bb0-982b-e647e71e023d?hostId=local): 권한 있는 아기 기록 + 본인 대화, 서버 조회 도구, 확인 후 기록 저장, 근거·기억·삭제.
- [아기 부모 캐릭터 애니메이션 설계](thread://01a0b874-f02e-7251-b0ed-dec540b067a9?hostId=local): 부위별 원본, Lottie Creator 우선 연결 시험/Rive 대안, 한 장면 검증, 추정·행동·관찰 분리.
- [프로젝트 보안 검토 설계](thread://01a0b8fc-8229-70d0-83ec-de680596a2c9?hostId=local): 보안 설계 v1.1과 후속 검토의 API/브라우저 결정 분리, 목적별 권리, 폴링 기본 경로, A/B 증거 분담.

대화의 설계와 후속 검토를 업무로 반영했으며 도구 연결·제공자 설정·실제 보안 시험 완료로 해석하지 않는다. [보안 자료](./security/)는 설계·시험 계획이며 확정 API 계약이나 통과 결과가 아니다.
