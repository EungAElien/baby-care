# B 실행 태스크 — API·데이터·ML (v2)

담당: 남자친구(B)  
협업 상대: 본인(A, 웹·브라우저)  
기준: [PRD v2](./baby-care-prd-v2.docx), [기능명세 v2](./baby-care-functional-spec-v2.docx)

이 문서는 구현 체크리스트다. 기능의 정확한 상태·필드·권한·인수 조건은 기능명세가 우선한다. B는 FastAPI, Supabase의 데이터·권한, PyTorch M2D, 정규화 어댑터와 운영을 주도한다. P0에서 Spring, 별도 Redis·Kafka·벡터 DB, 자동 재학습은 추가하지 않는다.

## 시작 전에 A와 확정할 계약

- [ ] 아기·멤버십·초대·동의·음원·사건·분석·행동·정규화 초안의 식별자와 상태 전이를 합의한다.
- [ ] FastAPI의 OpenAPI 요청·응답·오류 계약을 먼저 제공한다. 특히 분석 실패/유보, 충돌 409, 중복 요청, 삭제 중 상태를 화면에서 구별할 수 있게 한다.
- [ ] 브라우저 직접 접근 범위(Auth, RLS로 허용된 데이터·Storage)와 반드시 FastAPI를 거칠 동작(모델 분석, LLM, 관리·삭제 등)을 명시한다.
- [ ] A에게 개발용 샘플 응답, 권한별 시험 계정, 실제 모델/목/시연 자료의 출처 구분 규칙을 제공한다.

## B-01. 서버 기반과 계약

선행: 없음. A-01과 병렬 시작.

- [ ] FastAPI·Pydantic 프로젝트, API 버전, OpenAPI 문서, 공통 오류와 `request_id`를 구성한다.
- [ ] 인증 토큰 확인, 아기 멤버십 재확인, 멱등성 키와 변경 버전 처리의 공통 계층을 만든다.
- [ ] pytest, 정적 검사, 컨테이너 빌드, 잠금 파일과 GitHub Actions 기본 검사를 구성한다.

완료 기준: A가 계약을 보고 화면을 개발할 수 있고, 인증·오류·상태의 예제 요청과 응답이 준비돼 있다.

## B-02. 데이터·모델·LLM 위험 선검증

선행: 없음. 다른 기반 작업과 병렬로 즉시 시작.

- [ ] M2D 가중치·전처리·라벨 레지스트리를 한 컨테이너에서 적재해 샘플 추론을 재현한다.
- [ ] BABYCRY 등 학습/평가 자료의 이용 권리와 배포 가능 범위를 문서로 확인한다.
- [ ] 예열된 Cloud Run 환경에서 입력 길이·동시성·모델 버전을 기록하며 업로드 완료~결과 저장 p95 15초 목표와 45초 처리 기한을 시험한다.
- [ ] 자연어 정규화에 보낼 최소 데이터, 외부 제공자 보관·학습 설정, 비용·호출 한도를 검토한다. 모델 ID는 한국어 입력 평가 전까지 고정하지 않는다.

완료 기준: 각 항목에 통과/미통과, 측정값 또는 근거, 대체 경로가 있다. 미검증 모델 출력을 시연의 실제 검증 성능으로 주장하지 않는다.

## B-03. Supabase 스키마·RLS·Storage

선행: B-01의 데이터 계약.

- [ ] Baby, BabyMembership, Invitation, Consent, AudioAsset, Episode, Analysis 등 기능명세의 엔터티와 관계를 마이그레이션으로 만든다.
- [ ] `public` 등 노출 스키마의 테이블마다 필요한 GRANT와 아기별 RLS를 별도로 설정하고 허용/거부 테스트를 작성한다. 새 테이블의 Data API 노출 여부를 가정하지 않는다.
- [ ] OWNER 전용 관리, CAREGIVER 접근, 작성자 전용 초안, 탈퇴·삭제 직후 차단을 정책과 API 양쪽에서 검증한다.
- [ ] 음원은 private Storage에 두고 브라우저에 `service_role`/secret key를 노출하지 않는다. 서버 권한 키로 RLS를 우회하는 경로에서도 멤버십을 재검사한다.

완료 기준: 비구성원·다른 아기·탈퇴 계정·역할 위반·삭제된 자료에 대한 DB/Storage 접근이 거부되고 자동 시험으로 재현된다. 관련 인수 기준: AC01~AC03, AC41~AC44.

## B-04. 계정·공동양육·기록 API

선행: B-03.

- [ ] 아기 생성·선택, 지정 계정 초대·수락·만료·재사용 방지, 구성원 제거·탈퇴 API를 구현한다. (F01·F20)
- [ ] 보관 동의, 학습 참여, 전체 삭제와 공동양육자 나가기를 다른 동작으로 구현한다. (F02)
- [ ] 수유·수면 등 CareEvent의 생성·조회·수정·삭제, 진행 중 수면과 중복 기록 방지를 구현한다. (F09·F14)
- [ ] 버전 충돌에는 409와 최신 값을 반환하고, 수정·삭제가 요약·개인화 조회에서도 반영되게 한다.

완료 기준: 두 보호자 계정이 같은 아기의 공동 기록을 사용하면서 초안·관리 권한은 섞이지 않는다. 관련 인수 기준: AC13~AC16, AC21~AC22, AC39~AC44.

## B-05. 음원 수신·품질·보관 API

선행: B-03·B-04.

- [ ] 업로드 대상 아기·활성 구성원·파일 크기·형식·기간을 확인한 뒤 객체 경로를 발급하고 저장 완료 후 재검증한다. (F03)
- [ ] 인증된 직접 업로드와 6MB 초과/불안정 연결의 TUS 재개 업로드 계약을 A에게 제공한다.
- [ ] 실제 샘플 길이, 디코딩 성공, 무음·잘림·잡음과 시각 불명을 구분하고 품질 유보 사유를 반환한다. (F05)
- [ ] 재생 URL은 권한 재확인 후 짧게 발급하고 초기 상한을 60초로 둔다. 만료·삭제 작업의 실패 상태를 추적한다.

완료 기준: 부적합 음원에는 임의의 원인 후보를 만들지 않고, 권한 상실 후 새 업로드·재생 경로가 발급되지 않는다. 관련 인수 기준: AC04~AC05, AC08, AC41.

## B-06. M2D 분석 파이프라인

선행: B-02의 권리·성능 검증, B-05.

- [ ] PyTorch M2D, 고정 FFmpeg 전처리, 가중치 해시·라벨 레지스트리·임계값 버전을 컨테이너에 묶는다. (F06·F15)
- [ ] 시작 시 모델을 한 번 적재하고 준비 상태에서 일치 여부를 검사한다. 요청마다 학습하거나 가중치를 받지 않는다.
- [ ] 명세의 분석 상태 `READY → RUNNING → COMPLETE/ABSTAIN/FAILED`와 별도 `stage`, 처리 기한, 실행 토큰, 재시도·중복 요청 복구를 구현한다.
- [ ] 실제/목/시연 자료의 출처와 모델·데이터 버전을 결과에 남기고 평가 집계에서 섞지 않는다.

완료 기준: 정상 음원은 실제 후보 또는 근거 있는 유보를 반환하고, 모델 적재 실패·시간 초과에는 가짜 후보 없이 실패한다. 관련 인수 기준: AC09~AC10, AC23~AC25.

## B-07. 행동·상태 기록과 자연어 정규화

선행: B-04·B-06, A와 합의한 확인 화면 계약.

- [ ] 복수 행동·순서·관찰 시각·후속 상태, 기존 CareEvent 연결과 중복 저장 방지를 구현한다. (F10)
- [ ] 교체 가능한 `NormalizerAdapter`와 정규화 초안/확정 상태를 구현한다. OpenAI Responses API의 Structured Outputs는 첫 제공자 후보로 둔다. (F17)
- [ ] JSON 스키마뿐 아니라 수행/계획/부정, 허용 행동·상태, 시각, 근거 참조, 선택지와 글의 충돌을 서버에서 검증한다.
- [ ] 보호자 확인 전에는 확정 기록이나 학습 후보로 쓰지 않는다. 실패·시간 초과·한도 초과에는 원문을 보존하고 선택지로 복귀시킨다.
- [ ] 최소 데이터만 전송하고 원문·응답 전체를 일반 로그에 남기지 않는다. `store: false`를 적용하더라도 이를 ‘보관 0’ 보장으로 표현하지 않고 실제 데이터 정책을 확인한다.

완료 기준: 복합·부정·미래·과거 한국어 입력을 시험하고, 늦은 응답과 중복 확정을 막는다. 관련 인수 기준: AC15~AC16, AC29~AC33, AC38.

## B-08. 맥락·추천·이전 사례

선행: B-04·B-06·B-07.

- [ ] 분석 시점의 맥락 스냅샷과 수정 후 새 맥락을 구분해 저장한다. (F07)
- [ ] 버전 관리되는 돌봄 안내 규칙과 안전 우선순위를 구현하고, 추천 클릭과 실제 수행을 구분한다. (F08)
- [ ] 같은 아기의 적격 사례만 조회하며 타 아기 자료, 삭제 자료, 미래 정보는 배제한다. (F11)

완료 기준: 기록 수정 후 안내가 다시 계산되고 이전 안내 이력은 보존된다. 응급 관찰 문구가 일반 추천보다 우선한다. 관련 인수 기준: AC11~AC12, AC17, AC38.

## B-09. 공동 기록 변경 신호

선행: B-03·B-04.

- [ ] 아기별 비공개 Realtime 채널의 권한을 구성하고 변경 ID·버전 등 최소 신호만 발행한다. (F20)
- [ ] 신호 수신 후의 실제 데이터 조회에는 멤버십을 다시 확인한다. 연결 손실·이벤트 누락을 대비해 버전 기반 재조회 경로를 제공한다.
- [ ] 구성원 제거·아기 전환·탈퇴 후 구독과 신규 접근을 차단한다.

완료 기준: 두 보호자의 공동 변경은 반영되고 초안·다른 아기·탈퇴 계정 데이터는 전파되지 않는다. 관련 인수 기준: AC40~AC44.

## B-10. 활성 감지 세션의 서버 계약

선행: A-02 기기 검증, B-05·B-06.

- [ ] 감지 세션·공백·후보 구간·사건 ID를 기록하고 같은 울음의 자동 분석을 멱등 처리한다. (F04)
- [ ] 두 기기 또는 두 보호자가 동시에 감지를 시작할 때 중복 사건·분석을 방지한다.
- [ ] 중단 구간을 ‘울지 않음’ 관측 자료로 채우지 않는다.

완료 기준: 30분 전경 세션에서 같은 사건은 한 번만 분석되고, 숨김·잠금·통신 단절 후 공백과 재개가 보존된다. 관련 인수 기준: AC06~AC07, AC42.

## B-11. 오늘 요약과 준비 알림

선행: B-04·B-08.

- [ ] 날짜 경계·자정 통과 수면·양을 모르는 수유를 다루는 일별 집계를 구현한다. (F12)
- [ ] 기록에 근거한 준비 알림, 보류·미루기·만료·중복 방지 규칙을 구현한다. (F13)
- [ ] 수정·삭제 후 집계와 예정 알림을 재계산한다.

완료 기준: 누락값을 임의 수치로 채우지 않고, 이전 알림이 중복 발행되지 않는다. 관련 인수 기준: AC18~AC20.

## B-12. 학습 후보·동의 철회·내보내기

선행: B-03·B-07.

- [ ] 원문, 보호자 확인 라벨, 출처·수정 이력·동의 범위가 구분된 학습 후보를 구성한다. (F19)
- [ ] 적격성 검수, 버전 고정, 아기·시간 분리 정보가 포함된 내보내기를 구현한다.
- [ ] 기록 수정·삭제·동의 철회 후 기존 묶음을 무효화하고 사본·특징값 정리 상태를 추적한다.

완료 기준: 부적격 후보가 제외되고 철회된 자료가 다음 학습 묶음에 남지 않는다. 관련 인수 기준: AC36~AC37, AC43.

## B-13. 운영·배포·전체 인수 시험

선행: B-03~B-12의 P0 서버 경로.

- [ ] Cloud Run 서비스의 모델 예열, 동시 추론·인스턴스·요청량·파일 크기·LLM 호출 한도를 설정한다. (F16)
- [ ] Cloud Run Jobs·Scheduler로 만료 음원과 삭제 후속 작업을 재시도하고, 실패를 계측한다.
- [ ] 서버 비밀은 Secret Manager에 두고 개발/시연 환경의 DB·파일·키·도메인을 분리한다.
- [ ] pytest API·상태 시험, Supabase RLS/Storage 허용·거부 시험, 모델 smoke test, 중복 요청·응답 유실·롤백 시험을 자동화한다.
- [ ] A와 두 계정 실제 배포 시연 및 AC01~AC44를 전부 기록한다.

완료 기준: 실제 사용 기기, 입력 출처, 모델·데이터 버전, 지연·오류·삭제 상태가 남고 실패를 성공으로 표시하지 않는다. 관련 인수 기준: AC23~AC28 및 전체 AC.

## 첫 통합 시연 목표

B-03~B-07 및 B-09를 A의 대응 화면과 합쳐 **두 보호자 로그인 → 녹음 → 실제 분석 또는 정직한 유보 → 확인 기록 → 다른 보호자 화면 반영**을 먼저 완주한다. B-02의 권리·성능·데이터 처리 검증은 이 흐름과 병렬로 진행하되 최종 배포 판정 전에 반드시 끝낸다.
