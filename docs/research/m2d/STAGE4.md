# 4단계: M2D의 BABYCRY 예비학습

> 연구 문서 보관본입니다. 본문의 실행 명령·파일 경로는 별도 학습 프로젝트를 기준으로 합니다. 단계별 범위, 과거 기록과 외부 의존성은 [연구 문서 안내](README.md)를 먼저 확인합니다.

프로젝트 폴더에서 가상환경을 활성화한 뒤 실행합니다.

```sh
source .venv/bin/activate
caffeinate -i python train_stage4.py
```

## 이번 실행의 범위

학습 목록의 1,000개 음성(799명), 검증 분할에서 아기를 고르게 고른 200개 음성을 사용합니다. 학습 데이터를 최대 3회 반복합니다. 매번 음성을 가리는 위치를 바꾸며 M2D의 자기지도학습을 수행합니다. 시험 분할의 음성은 읽지 않습니다.

예비학습이 완료되어도 전체 BABYCRY 추가학습이나 Donate-a-Cry 지도학습이 끝난 것은 아닙니다. 기본 실행은 1,000개 실험까지만 진행합니다.

## 시작 설정과 이유

| 항목 | 설정 |
|---|---|
| 시작 모델 | 공식 AudioSet 사전학습 M2D/0.7, ViT-Base |
| GPU/계산 형식 | Apple MPS, float32 |
| 한 번에 계산하는 음성 | 1개 |
| 가중치 갱신 주기 | 8개의 기울기를 평균하여 한 번 갱신 |
| 입력 길이 | 실제 길이에 맞춰 16프레임 단위, 최대 608프레임 |
| 마스킹 | 패치의 약 70%, 반올림에 따른 차이 존재 |
| 최대 학습률 | 0.00001 |
| 학습률 일정 | 첫 5% 갱신 동안 증가, 이후 코사인 곡선으로 최대값의 10%까지 감소 |
| 최적화 | AdamW, betas 0.9/0.95, weight decay 0.05; bias/1차원 파라미터는 decay 제외 |
| 기울기 제한 | 전체 norm 1.0 |
| 목표 인코더 갱신(EMA) | optimizer 갱신마다 0.999에서 0.9999까지 선형 증가 |
| 정규화 | 사전학습 기준 평균 -7.1, 표준편차 4.2 유지 |
| 검증 | 고정된 200개, 고정된 가운데 구간과 마스크 |
| 조기 종료 | 검증 손실이 0.0001 이상 개선되지 않는 epoch가 3회 연속이면 종료 |

작은 배치에서 실행 가능한 예비 설정입니다. BABYCRY에 최적이라고 확인된 조합은 아닙니다. 기본 설정은 epoch당 125번, 3 epochs에 총 375번 가중치를 갱신합니다. 마지막 묶음이 8개 미만인 경우 실제 개수로 기울기를 평균합니다.

학습률 1e-5는 공식 기본 학습률의 배치 비례식(3e-4 × 8 / 256 ≈ 9.4e-6)과 가까운 시작점입니다. EMA 일정은 작은 예비 실험을 위한 설정이며, 공식 대규모 사전학습의 0.99995~0.99999를 재현하는 값은 아닙니다. 10,000개 실험으로 확대하기 전에 학습률, 유효 배치, EMA를 함께 검토합니다.

3단계에서 측정한 학습 데이터 통계는 약 -11.21/2.96입니다. 첫 실험은 사전학습 입력 기준을 유지하며, 이후 이 통계를 사용하는 실험을 비교할 수 있습니다. 정규화 선택과 값은 체크포인트에도 저장됩니다.

## 짧은 음성과 위치 정보

학습 분할의 약 81%가 608프레임보다 짧습니다. 빈 구간이나 같은 소리의 반복을 덧붙이지 않습니다. 실제 프레임 수를 16의 배수로 내리고, 남는 최대 15프레임은 crop 범위 밖에 둡니다. 긴 음성은 학습할 때마다 최대 608프레임의 다른 구간을 선택하고 검증할 때는 가운데 구간을 고정합니다.

인코더는 공식 `forward_encoder(adjust_short=True)`를 사용합니다. 디코더의 고정 위치 정보도 같은 주파수·시간 배열 순서로 잘라 맞춥니다. 학습 가능한 가중치의 형태나 M2D의 목표 표현·손실·EMA 방식은 유지합니다. 공식 소스 파일은 수정하지 않습니다.

추후 실사용 입력 처리도 이 정규화와 길이 정책을 따라야 합니다. 실사용에는 자기지도학습용 마스킹을 적용하지 않습니다.

## 실행 중 보이는 정보

처음에는 학습 전 검증 손실을 측정합니다. 이후 epoch, 처리 개수, 학습 손실, 음성 하나당 소요 시간이 출력됩니다. epoch가 끝날 때 검증 손실을 계산합니다. 표시되는 속도는 해당 묶음의 입력 읽기와 학습 계산 시간이며, 검증·체크포인트 저장 시간을 포함한 전체 완료 예상 시간은 아닙니다.

학습 전 기준 모델도 최저 검증 손실 후보로 보관합니다. 추가학습이 기준보다 개선되지 않으면 `best_epoch`가 0이고 `best_encoder.pth`에는 시작 모델의 인코더가 남습니다. 마지막으로 학습한 모델은 `last.pt`에 별도로 있습니다.

## 저장과 이어서 실행

기본 실행 폴더는 `runs/babycry_pilot_1000/`입니다.

- `last.pt`: 최근 모델, 목표 인코더, 예측기, Adam 상태, epoch/위치, 일정, 난수 상태. 25번 갱신마다 및 epoch 종료/정상 중단 시 저장.
- `best.pt`: 관측한 검증 SSL 손실이 가장 낮았던 시점의 전체 체크포인트.
- `best_encoder.pth`: 그 시점의 온라인 인코더와 입력/실험 설정. 울음 원인 분류기는 아직 없음.
- `best_files.json`: 최저 손실 모델과 인코더 파일의 해시. 여러 결과 파일을 저장하던 중 강제 종료되어도, 해당 시점의 `last.pt`가 있으면 재실행 시 복구.
- `config.json`, `train.csv`, `val.csv`: 실제 설정과 사용 목록.
- `steps.jsonl`: 가중치 갱신마다의 손실·학습률·EMA·소요 시간 기록.
- `progress.json`, `report.json`: 진행 상황과 최종 요약.
- 프로젝트 `reports/stage4_check.json`: 현재 또는 최종 상태.

중단하려면 `Ctrl+C`를 한 번 누르고 저장 완료 메시지를 기다립니다. 현재 기울기 누적 묶음의 갱신을 마친 뒤 저장합니다. 같은 명령을 다시 실행하면 이어갑니다. 강제 종료되었으면 마지막 정기 저장 시점부터 다시 처리하므로 최대 약 200개 음성을 다시 계산할 수 있습니다. 재시작 때 저장 시점 이후의 미확정 단계 로그도 정리합니다.

설정·코드·데이터가 달라졌으면 같은 체크포인트로 이어가지 않고 중단합니다. 새 실험은 다른 `--run-name`으로 구분해야 합니다. 원본 사전학습 가중치는 덮어쓰지 않습니다. 체크포인트를 위해 최소 10GiB의 여유 공간을 확인합니다.

## 결과를 해석할 때

SSL 손실은 가린 부분의 특징 예측 오차입니다. 울음 원인 분류 정확도가 아닙니다. 특히 이 검증은 매번 현재 EMA 목표 인코더를 사용하므로, 목표 모델 자체가 변한다는 한계가 있습니다. 최저 SSL 손실 모델이 최종 분류 성능도 가장 좋다고 단정할 수 없습니다.

고정된 검증 입력들에서 나온 표현의 다양성도 기록합니다. 이것이 급격히 감소하면 여러 음성을 비슷하게 표현하는 문제가 생겼는지 살펴야 합니다. 이 진단만으로 일반화 성능이 검증되는 것은 아닙니다.

4단계 완료 후에는 학습 시간, 메모리, 유한한 손실과 기울기, 검증 변화, 표현의 다양성을 확인합니다. 이후 10,000개 실험을 결정합니다. 최종적으로 추가학습 전후 모델에 동일한 Donate-a-Cry 지도학습과 분할을 적용해 Macro F1 등으로 비교해야 BABYCRY의 도움이 검증됩니다.
