# 4단계: BABYCRY 전체 자기지도 추가학습

> 연구 문서 보관본입니다. 본문의 실행 명령·파일 경로는 별도 학습 프로젝트를 기준으로 합니다. 단계별 범위, 과거 기록과 외부 의존성은 [연구 문서 안내](README.md)를 먼저 확인합니다.

## 범위와 완료 기준

1. 검증을 통과한 1,000개 예비학습의 최적 M2D 체크포인트에서 이어갑니다.
2. 학습 분할 85,953개 전부를 매 epoch 한 번씩 사용합니다. 아기가 분리된 검증 11,743개는 고정된 입력·마스크로 평가하고, 시험 9,358개의 음성은 읽지 않습니다.
3. 최대 3 epochs, 검증 SSL 손실이 0.0001 이상 좋아지지 않는 상태가 2회 이어지면 조기 종료합니다. 이는 실행 범위를 정한 추가학습이며, 수렴이나 울음 원인 분류 성능을 보장하는 기준은 아닙니다.
4. 저장된 모델·Adam 상태·전체 학습 이력을 검사하고, 선택한 인코더를 새 모델에 로딩하여 MPS 추론을 확인합니다. 완료 보고서가 만들어져야 4단계를 완료한 것으로 판단합니다.

## 설정

- 공식 M2D ViT-Base / FP32 / MPS, 70% 마스킹
- 한 번에 음성 1개, 8개의 기울기를 모아 갱신
- 새 AdamW: 최대 학습률 0.00001, 5% 준비 구간 후 cosine 감소, EMA 0.999 → 0.9999
- 예비학습과 같은 정규화 [-7.1, 4.2]
- 입력 최대 608 프레임. 짧은 음성은 16 프레임 배수로 잘라 실제 길이만 사용합니다. 긴 음성은 epoch마다 다른 구간을 뽑습니다.
- 500회 갱신마다, 매 epoch 종료 시, 정상 중단 요청 시 저장합니다. 예기치 않은 종료는 마지막 저장 지점부터 재개합니다.
- 표현 다양성이 초기의 20% 미만으로 떨어지면 결과 검토 상태로 중단합니다.

## 자동 실행

프로젝트 가상환경의 Python으로 `launch_stage4.py`를 실행하면 별도 로컬 프로세스가 시작됩니다.
학습 연산, 전원 점검, 저장·재개, 최종 파일 검증에는 OpenAI API 호출이 없습니다.
Codex의 상태 확인·오류 수정은 별도 사용량을 소비합니다.

전원이 분리되면 현재 갱신 또는 검증 구간을 마치고 저장한 뒤 대기합니다. 충전기를 다시 연결하면 이어갑니다.
Mac은 충전기에 연결하고 덮개를 열어두세요. `caffeinate`는 학습 중 유휴 잠자기를 막지만 수동 잠자기·덮개 닫기·재부팅을 막지 않습니다.
학습 프로세스는 대화 응답이 끝나도 실행됩니다. Codex의 예약 후속 확인에는 컴퓨터와 Codex 앱이 실행 중이어야 합니다.

## 파일

- `runs/babycry_full/supervisor_state.json`: 학습·전원 대기·검증·완료·오류 상태
- `runs/babycry_full/live.json`: 최근 학습 진척, `progress.json`: 저장된 체크포인트 진척
- `runs/babycry_full/training.log`, `steps.jsonl`: 학습 기록
- `runs/babycry_full/last.pt`: 전체 모델·Adam·난수 상태, 재개용
- `runs/babycry_full/best.pt`: 검증 손실 기준 선택한 전체 모델
- `runs/babycry_full/best_encoder.pth`: 이후 Donate-a-Cry 지도학습에 사용할 인코더
- `reports/stage4_full_completion_check.json`, `reports/STAGE4_RESULT.md`: 최종 검증 성공 후 생성

SSL 검증은 변하는 EMA 교사를 사용하므로 손실 감소만으로 분류 성능 향상을 주장하지 않습니다.
초기 예비학습 모델이 최적 상태로 남으면 결과는 `needs_review`로 표시하고 후속 검토합니다.
Donate-a-Cry 지도학습·시험 평가·서비스 배포는 이 단계에 포함되지 않습니다.
