# M2D 아기 울음 모델 · M1 Pro 로컬 학습 설계

> 연구 문서 보관본입니다. 본문의 실행 명령·파일 경로는 별도 학습 프로젝트를 기준으로 합니다. 단계별 범위, 과거 기록과 외부 의존성은 [연구 문서 안내](README.md)를 먼저 확인합니다.

작성일: 2026-09-15\
상태: 구현을 위한 설계. 모델 설치·학습·전체 데이터 다운로드는 수행하지 않았다. 아래 배치, 학습률, 반복 횟수는 첫 실험을 위한 제안이며 검증된 최적값이 아니다.\
대상: M1 Pro, 통합 메모리 16GB, 맥북 내부 드라이브. 사용자의 후속 지시에 따라 저장 위치와 주 학습 순서를 확정했다.

## 1. 목표와 학습할 대상

**사전학습 M2D → BABYCRY 자기지도 추가학습 → 그 인코더를 이어받아 Donate-a-Cry 지도학습 → 평가 → 서비스 전달.**

이 순서를 주 경로로 고정한다. BABYCRY를 거치지 않은 모델과의 비교 및 연구 특징 추가는 주 경로의 효과를 확인하는 별도 실험이다. 작은 동작 점검과 데이터 분할은 학습 전 준비 과정이다.

서비스 전체 흐름은 기존 `baby-care-mvp-spec-2026-09-15.md`를 따른다. 이번 문서는 주력 오디오 모델을 M2D로 구체화한다.

| 대상 | 학습·구현 방식 | 지금의 데이터로 할 수 있는 범위 |
|---|---|---|
| 울음인지 확인 | 울음/비울음 감지기와 품질 검사 | 별도 비울음 음원 확보 및 평가 필요 |
| 울음 원인 후보 | M2D 오디오 표현 + 작은 분류기 | 보호자가 보고한 배고픔·졸림 등의 라벨 예측 실험 |
| 생활 맥락 결합 | 최근 기록 조회·명시적 규칙·아기별 유사 사례 | 첫 시제품에서 구현 가능; 학습된 맥락 모델이라는 표현은 사용하지 않음 |
| 아기별 개선 | 동의받은 사건·행동·반응을 기록하고 유사 사례 조회 | 매 기록마다 Transformer를 재학습하지 않음 |
| 미래 울음 예측 | 울음/비울음 관측 시간과 생활 기록을 이용한 별도 실험 | 공개 울음 조각만으로는 학습할 수 없음 |

출력은 원인 후보, 판단 유보 사유, 지원 라벨, 모델 버전이다. 돌봄 행동과 원인 라벨은 일대일 관계로 강제하지 않는다. 복통 보고 라벨을 의료적 진단으로 표시하지 않는다.

## 2. 확인한 사실과 아직 확인하지 않은 것

### 확인한 사실

- 사용자가 제공한 사진: M1 Pro, 메모리 16GB.
- 현재 기본 `python3`: arm64 Python 3.10.4. 이 인터프리터에는 PyTorch가 설치돼 있지 않았다. 다른 가상환경의 설치 여부는 조사하지 않았다.
- 저장 위치 변경 후 내부 드라이브 여유 공간은 약 140.08GB였다. 변동 가능한 스냅샷이며 학습에 전부 사용하지 않는다.
- 앞선 ZIP 내부 목록 합산: BABYCRY ZIP 80,996,262,910바이트, 해제된 파일 합계 87,483,186,762바이트. WAV 107,312개, metadata.csv 355,239,650바이트. 전체 다운로드 없이 확인한 디렉터리 정보다.
- Donate-a-Cry 공식 저장소 파일 목록: 정리본 WAV 457개, 약 50.62MB. 집계한 Git tree SHA는 `6baf5aca0460964ad072653585837f968a87c2af`이다. 음원 내용 검수나 실제 디코딩 결과는 아니다.
- M2D 공식 학습 코드에는 CUDA 전용 자동 정밀도 처리, 동기화 호출, 기본 CUDA 장치 설정이 남아 있다. MPS에 맞추는 작업이 필요하다.

### 아직 확인하지 않은 것

- M2D의 실제 MPS forward/backward 성공, 최대 배치, 학습 속도, 장시간 메모리 안정성.
- Donate-a-Cry 원본 음원의 정확한 샘플레이트, 중복, 라벨 품질, 원본-정리본 대응 성공률.
- BABYCRY의 176개 측정값 정의·결측·품질. Zenodo 소개에 제공 사실은 명시되어 있지만 CSV 전체를 감사하지 않았다.
- BABYCRY 재사용 허가: 현재 공개 레코드의 License 값은 표시되지 않는다. 기존 대화에서 확인하지 못한 상태를 유지한다. 설계와 환경 준비는 진행할 수 있으며 BABYCRY 실학습 전 사용 조건 확인 결과를 기록한다.
- Baby Chillanto 접근·이용 조건. 확보 전에는 완료된 학습 데이터로 계산하지 않는다.

## 3. 출발 체크포인트

기본값은 공식적으로 추가 사전학습을 지원하는 다음 모델로 제안한다.

`m2d_vit_base-80x608p16x16-221006-mr7/checkpoint-300.pth`

- M2D/0.7, AudioSet 사전학습, ViT-Base 계열.
- 16kHz 입력, log-Mel 80개 주파수 대역, 학습 창 608프레임, 16×16 패치.
- 추가 사전학습을 위해 공식 배포의 **전체 체크포인트**를 보관한다. `enconly`는 인코더만 사용한 특징 추출·분류에는 적합하지만 학습용 네트워크 상태를 모두 갖추지 않는다.
- 추론과 분류에는 인코더를 추출해서 사용한다. 기본 주파수 결합 방식에서는 시간별 특징이 3,840차원이고 이를 시간 평균하여 파일/창 표현을 만든다. 실제 로더의 출력 형태를 검사한다.
- 첫 비교에서는 같은 초기 모델을 고정한다. M2D-CLAP이나 M2D-X로 변경하는 실험은 별도 이름과 평가로 관리한다.

새 도메인 학습을 시작할 때는 모델 상태를 초기값으로 로드하고 optimizer와 학습 횟수는 새로 시작한다. 중단된 같은 실험을 재개할 때는 optimizer·스케줄·EMA·난수·데이터 진행 상태까지 복구한다. 공식 체크포인트의 epoch 300을 새 실험의 시작 횟수로 착각하지 않는다.

근거: [공식 모델 목록](https://github.com/nttcslab/m2d#pre-trainedfine-tuned-weights), [응용 가이드](https://github.com/nttcslab/m2d/blob/master/app/Guide_app.md), [인코더 로더](https://github.com/nttcslab/m2d/blob/master/examples/portable_m2d.py).

## 4. 맥북용 환경과 MPS 조정

### 환경 구성

1. 프로젝트 전용 arm64 Python 3.11 가상환경을 만든다. 기존 시스템 Python과 다른 프로젝트 환경은 유지한다.
2. PyTorch, 오디오 디코더, NumPy, librosa, nnAudio, scikit-learn 등 실제 필요한 의존성만 설치한다.
3. M2D 공식 저장소 버전과 외부 MAE 파일 버전을 고정한다. 공식 코드는 MAE를 가져와 패치하는 설치 과정이 있으므로 저장소를 받는 것만으로 학습기가 완성됐다고 간주하지 않는다.
4. 공식 requirements의 `timm==0.4.5`와 현대 PyTorch의 호환을 검사한다. 인코더 로더와 학습 모델의 state_dict 대응을 확인한 뒤 확정한 버전을 잠근다.
5. MPS 가용성을 확인하고, 음성 전처리는 처음에는 CPU에서 수행한다. M2D 인코더와 학습 텐서는 MPS에 둔다.

### 필요한 코드 조정

- `device=mps`, 단일 프로세스, 초기 `num_workers=0`, `pin_memory=False`.
- CUDA 전용 autocast/GradScaler를 첫 검증에서는 비활성화하고 FP32로 forward/backward를 확인한다.
- CUDA 동기화·메모리 통계·분산 집계·자동 GPU 평가 실행을 MPS/단일 프로세스 경로로 바꾼다. 소요 시간 측정 구간에는 MPS 동기화를 사용한다.
- NumPy에서 넘어오는 float64는 float32로 맞춘다. 미지원 연산 때문에 CPU로 이동하면 연산·시간을 기록한다. 전체 학습이 조용히 CPU로 전환되는 상태를 정상 GPU 학습으로 보고하지 않는다.
- `trainable` 파라미터만 optimizer에 등록한다. 목표 네트워크에는 기울기를 저장하지 않는다.
- 공식 데이터셋 초기화의 여러 샘플 일괄 적재 방식은 메모리를 크게 쓸 수 있으므로, 정규화 통계가 필요할 때 훈련 데이터만 작은 묶음으로 순차 집계한다.
- FP32가 안정적으로 실행된 다음에만 혼합 정밀도를 별도 비교한다. 반정밀도 메모리 절감과 M1의 속도 향상을 사전에 보장하지 않는다.

`model.to('mps')` 한 줄만 바꾸면 공식 학습 명령 전체가 작동한다고 가정하지 않는다. [PyTorch MPS](https://docs.pytorch.org/docs/stable/notes/mps.html), [공식 학습 패치](https://github.com/nttcslab/m2d/blob/master/patch_m2d.diff).

## 5. 내부 드라이브의 저장공간 구성

| 위치 | 내용 | 예산·처리 방식 |
|---|---|---|
| 내부 드라이브 | BABYCRY 원본 WAV + CSV | 파일 크기 합계 약 87.48GB |
| 내부 드라이브 | 가변 길이 log-Mel FP32 캐시 | 총 음성 길이로 추산하면 약 16GB. 실제 변환 후 확정 |
| 내부 드라이브 | Donate-a-Cry 선택 원본·목록·검증 기록 | 정리본은 약 50.62MB; 원본은 선택 범위의 실제 합계를 먼저 확인 |
| 내부 드라이브 | 환경, 코드, 고정 초기 가중치, 최신·최선 학습 상태 | 10~15GB 계획 예산. 설치·체크포인트 저장 후 실측 |
| 내부 드라이브 | 운영체제 및 작업 여유 | 최소 15~20GB를 남기는 운영 목표 |

약 16GB 추산은 공개 평균 길이 4.60초 × 107,312개 × 초당 약 100프레임 × 80대역 × float32 4바이트에 근거한다. 모든 파일을 미리 608프레임으로 고정해 한 창씩만 저장해도 20.88GB이며 긴 파일을 여러 창으로 만들면 달라진다. **원래 길이의 스펙트로그램을 한 번 저장하고 학습 때 창을 자르는 방식**을 기본으로 한다.

전체 16kHz WAV 사본을 별도로 추가 저장하지 않는다. 원본 → 메모리에서 리샘플링 → log-Mel로 변환한다. 원본은 보존하고 재생성 가능한 캐시만 용량 정책으로 관리한다. 현재 스냅샷에서는 원본·캐시·환경·가중치에 약 114~119GB를 사용하는 구상이지만, 실제 캐시와 체크포인트 크기가 기준이다. 남길 여유 공간을 침범하면 캐시 범위를 줄이고 원본을 자동 삭제해서 공간을 마련하지 않는다.

현재 여유 약 140GB는 ZIP과 해제 파일을 함께 두는 데 필요한 약 168.48GB보다 작다. 따라서 내부 드라이브를 사용해도 **ZIP 전체를 저장하지 않고 수신과 동시에 해제**하는 방식을 유지한다. 사전에 충분한 추가 공간을 확보한 경우에는 일반 다운로드·해제도 선택할 수 있다.

BABYCRY 수신기는 앞서 확인한 HTTP 부분 읽기를 활용해 ZIP 항목을 순차 해제·저장하도록 구현한다. 항목별 CRC와 압축 해제 크기를 검증하고 임시 파일 완료 후 이름을 확정한다. 공개 ZIP의 MD5와 항목별 검증은 구분한다. 항목별 검사만 수행하고 전체 ZIP MD5 검증까지 했다고 기록하지 않는다. 원본 레코드·파일 버전·목록 해시·진행 상태를 보관하고 중단 후 완료 항목을 재검사해 이어받는다. 이 수신기는 아직 구현되지 않았다.

이미 준비된 원본을 읽는 학습에는 네트워크가 필요하지 않다. 데이터가 없거나 손상되면 마지막 유효 체크포인트에서 중단하고 해당 파일을 성공한 것으로 처리하지 않는다.

## 6. 데이터 준비와 평가 분할

### 6.1 Donate-a-Cry: 자기지도학습 뒤 사용할 지도학습 자료

공식 저장소의 정리본 목록을 직접 집계한 결과:

| 원본 범주 | 파일 수 |
|---|---:|
| hungry | 382 |
| tired | 24 |
| discomfort | 27 |
| belly_pain | 16 |
| burping | 8 |
| 합계 | 457 |

항상 hungry로 답하는 분류기도 약 83.6% 정확도를 얻는다. 일반 정확도 하나로 성공을 판단하지 않는다. 정리본은 8kHz이며 일부 범주의 병합·제거가 포함되어 있다. [공식 정리본 설명](https://github.com/gveres/donateacry-corpus/tree/master/donateacry_corpus_cleaned_and_updated_data)

진행 방법:

1. 정리본의 파일·원인 목록을 출발점으로 사용한다. 가능하면 같은 녹음의 원본 CAF/3GP와 연결해 원래 대역폭을 활용한다. 연결 실패 시 정리본을 사용했다는 출처를 남긴다.
2. 원본과 정리본을 독립 표본으로 중복 포함하지 않는다. 파일 해시와 디코딩한 음원의 중복·근접 중복을 검사한다.
3. 동일 앱 설치 UUID와 동일 녹음 조각은 같은 그룹에 둔다. UUID는 아기 ID가 아니다. 이 분할 결과를 '새로운 아기에서 검증된 정확도'라고 부르지 않는다.
4. 초기에는 그룹 기준으로 약 20%를 최종 평가용으로 예약하고 나머지에서 3개 그룹 교차검증을 구성한다. 클래스별 독립 그룹 수가 적으면 성립하는 분할 수를 줄이고 그 한계를 보고한다. 교차검증으로 최종 테스트를 반복 열어보지 않는다.
5. 처음에는 정리본의 5개 라벨을 보존해 연구용 분류기를 만든다. 지원하기 어려운 범주를 데이터 수 확보 없이 제품 기능으로 발표하지 않는다. '기타'나 '판단 유보'에 이질적인 라벨을 임의로 몰아넣지 않는다.
6. 클래스 가중치는 훈련 분할에서만 계산한다. 첫 실험은 역제곱근 빈도 가중 CE로 제안하며 무가중 기준과 비교한다. 오버샘플링이나 증강으로 독립된 아기 수가 늘었다고 계산하지 않는다.

### 6.2 BABYCRY: 원인 라벨 없는 추가학습

1. 이용 조건을 확인한 뒤 baby ID를 기준으로 800/100/100명 목표의 훈련/검증/보류 집합을 고정한다. 실제 ID 수·파일 수는 수신 및 메타데이터 검증 후 확정한다.
2. 같은 아기의 모든 파일과 파생 창은 같은 집합에 둔다. 보류 아기의 오디오는 자기지도 추가학습에서도 제외한다.
3. 훈련 아기들에 걸쳐 대표성 있게 1,000개 점검용, 10,000개 예비 실험용, 전체 훈련 파일 목록을 만든다. 처음 발견한 1,000개 파일만 택하지 않는다.
4. 한 아기의 많은 파일이 훈련을 지배하는지 확인하고, 필요하면 아기별 샘플링 가중치를 사용한다. 재표집을 쓰면 1 epoch의 실제 의미를 N회 추출로 기록한다.
5. 출생·신체 메타데이터는 분할 감사와 하위집단 평가에 사용할 수 있지만 첫 오디오 원인 분류기의 입력 정답으로 사용하지 않는다.

### 6.3 다른 자료와 서비스 데이터

- Baby Chillanto는 확보와 라벨 정의 확인 후 외부 평가 후보로 편입한다. 질병/통증/배고픔 라벨을 Donate-a-Cry의 라벨과 무조건 합치지 않는다.
- 울음 감지기를 위해 사용 조건을 확인한 성인 말소리·TV·웃음·생활 소음·무음 자료가 별도로 필요하다. 첫 감지기 검증은 공개 비울음 후보와 직접 수집 동의 자료를 묶되 음원 단위로 분리한다. BABYCRY만으로 감지기 학습이 완료되지 않는다.
- 실사용 수유·수면·기저귀 맥락은 공개 울음 파일에 임의로 붙이지 않는다. 같은 사건에 실제로 연결된 자료가 쌓인 뒤 맥락 모델을 학습한다.

## 7. 전처리 규칙

1. 디코딩 성공 여부, 원본 샘플레이트/채널/길이, 무음, 잘림, 클리핑과 출처를 기록한다.
2. 모델 입력은 mono 16kHz. 8kHz 정리본을 16kHz로 바꿔도 사라진 고주파 정보가 복구되지는 않는다.
3. 공식 M2D와 동일하게 25ms 창, 10ms 간격, 80 mel 대역, 50~8,000Hz, 파워 스펙트럼의 자연로그를 사용한다. 별도의 dB 변환으로 바꾸지 않는다.
4. 전체 음원의 log-Mel을 가변 길이로 보관한다. 학습 시 최대 608프레임 창을 무작위로 뽑는다. 평가는 고정 창과 고정 집계 방식으로 수행한다.
5. 짧은 파일을 이어 붙여 실제로 없던 울음 리듬을 만들지 않는다. 패딩은 유효 길이와 함께 기록하며, 패딩만 있는 패치는 pooling과 자기지도 손실·마스킹 대상에서 제외하는 경로를 검증한다. 반사 패딩을 사용하는 전처리의 경계와 이후 무음 패딩을 혼동하지 않는다.
6. 장시간 파일을 영구적으로 앞 30초만 남기지 않는다. 공식 변환기의 기본 길이 제한을 그대로 적용하지 말고 전체를 변환하거나 창 시작 위치 목록을 보존한다. 원본 확장자 `.WAV`도 처리한다.
7. 첫 실험의 정규화는 체크포인트의 mean/std를 동일하게 사용한다. 새 도메인 통계를 시험할 경우 훈련 자료만 순차 집계하고 기준 모델에도 같은 정규화를 적용하는 대조 실험을 둔다. 검증 집합 자체 통계로 다시 정규화하지 않는다.
8. 무음 구간은 일괄 삭제하지 않는다. 최초 증강은 작은 잡음·녹음 조건 변화 위주이며, 음높이를 크게 바꾸는 증강이나 울음 사이 순서를 섞는 증강은 제외한다.

공식 전처리와 대조할 작은 샘플에서 특징값·출력 형태·임베딩 일치 여부를 확인한 뒤 전체 캐시를 만든다. [M2D 전처리](https://github.com/nttcslab/m2d/blob/master/wav_to_lms.py)

## 8. 주 학습 경로: BABYCRY → Donate-a-Cry

모든 수치는 첫 실험 제안이다. 설정은 검증 집합에서 선택하고 기록한다. 실제 학습 순서는 아래 S0 → S1 → S2 → S3이다.

### S0. 실행·메모리 점검

- 출처와 권한을 확인한 BABYCRY 작은 표본으로 batch 1에서 시작해 자기지도 forward/backward를 점검한다. 환경 자체 검사는 작은 합성 입력으로도 가능하다.
- batch 1 → 2 → 4를 차례로 비교한다. 메모리 부족이면 낮춘다.
- 준비 실행 20회 후 실제 데이터 학습 100개 미니배치를 측정한다. EMA 업데이트 검사는 최소 5 optimizer step 이상 이어간다.
- 기록: 샘플/초, 데이터 읽기·전처리·모델 시간, CPU RSS, MPS 텐서 및 드라이버 메모리, 스왑 변화, 손실·기울기의 유한성.
- 초기 운영 목표는 학습 프로세스 약 8~10GB 이내와 지속적인 스왑 증가 없음이다. 보장되는 필요 메모리 수치가 아니다. 전체 시스템 메모리 압박도 함께 확인한다.
- CPU와 MPS의 고정 입력 결과·기울기 차이를 허용 오차 내에서 확인하고 체크포인트 저장·재개도 검증한다.

### S1. BABYCRY로 M2D 자기지도 추가학습

원인 정답 없이 울음의 일부를 가린 뒤 그 부분의 표현을 예측하도록 **M2D 자체를 학습**한다.

- 구조: 온라인 인코더 + masked representation 예측기 + EMA 목표 인코더.
- 온라인 인코더와 예측기는 기울기로 갱신하고 목표 인코더는 온라인 가중치의 이동평균으로 갱신한다.
- 초기에는 일반 M2D로 진행한다. 별도 고정 교사까지 추가하는 M2D-X는 더 많은 메모리와 스케줄 검증이 필요하므로 후속 비교로 둔다.
- 첫 값: 80×608 입력, mask ratio 0.7, FP32, microbatch 2, 누적 32회로 유효 batch 64. 안정적으로 batch 4가 되면 누적 16회로 같은 유효 batch를 유지한다.
- AdamW, 실제 peak LR 3e-5를 중심으로 1e-5/3e-5를 예비 비교. weight decay 0.05, clip 1.0, 준비 구간은 총 optimizer step의 5%, 이후 cosine 감소.
- EMA는 optimizer step마다 한 번만 갱신한다. 첫 예비 값은 0.99 → 0.999로 제안한다. 이는 작은 배치용 탐색값으로 공식 대규모 설정의 재현 주장이 아니다. 목표 표현의 분산·랭크를 함께 확인한다.
- batch/누적/LR/EMA 관계를 함께 검증한다. 누적만 크게 하면 논문의 대규모 배치 결과가 재현된다고 가정하지 않는다. 마지막 불완전 누적 구간도 실제 샘플 수로 정규화하여 처리한다.
- 1,000개: 실행·메모리 점검. 10,000개: 3 epoch부터 예비 실행. 전체 훈련 파일: 예비 실행에서 추산한 시간과 안정성을 확인한 뒤 3~5 epoch부터 확장한다. 최종 학습 횟수는 검증 결과로 정한다.
- 검증 울음의 고정된 마스킹 조건에서 손실과 표현의 분산을 확인한다. 온라인 출력이 서로 거의 같아지는 표현 붕괴가 보이면 이전 상태로 되돌린다.
- 산출물은 **BABYCRY를 추가 학습한 M2D 인코더**와 재개 가능한 전체 학습 상태다. 배고픔/졸림을 이미 학습했다고 표현하지 않는다.

### S2. S1 인코더를 이어받아 Donate-a-Cry 지도학습

**S1 인코더의 학습된 가중치를 유지**하고 뒤에 원인 분류층을 붙인다. 목표 인코더와 자기지도 예측기는 S2에서 사용하지 않는다.

| 항목 | 첫 설정 |
|---|---|
| 입력 | 같은 16kHz/80 mel 전처리 및 정규화 |
| 인코더 | S1의 BABYCRY 추가학습 결과 |
| 표현 | 시간 특징을 모아 3,840차원으로 집계; 패딩 제외 |
| 분류층 | 3,840 → K, 첫 검수 범주는 5개 |
| 정답 | 검수된 Donate-a-Cry 보호자 보고 라벨 |
| 손실 | 훈련 집합 빈도로 계산한 가중 Cross Entropy |
| 준비 학습 | 인코더 고정, 분류층만 3 epoch, batch 32, LR 1e-3 |
| 추가 조정 | 마지막 Transformer 블록 2개 + 분류층 |
| 추가 조정 배치 | batch 2 × 누적 8 = 유효 16 |
| 추가 조정 학습률 | 인코더 1e-5, 분류층 1e-3 |
| 나머지 | AdamW, weight decay 0.01, clip 1.0, 최대 20 epoch, patience 5 |

분류층 준비 학습은 S2 안에서 진행한다. 그 다음 인코더 일부도 라벨에 맞게 조정한다. 전체 인코더를 풀어 학습하는 실험은 작은 라벨 데이터의 과적합과 MPS 자원을 확인한 뒤 별도 설정으로 비교한다.

BABYCRY 체크포인트로 초기화한 뒤 Donate-a-Cry용 optimizer를 새로 만든다. 각 교차검증 fold는 동일한 S1 인코더에서 시작하고, 직전 fold에서 라벨을 학습한 모델을 이어받지 않는다. 검증 집합만으로 설정·중단 시점을 고른다. 이 결과가 원인 후보를 출력하는 최종 오디오 모델이다.

### S3. 평가와 최소 대조 실험

- 주 모델: `초기 M2D → BABYCRY → Donate-a-Cry`.
- 대조 모델: `같은 초기 M2D → 같은 Donate-a-Cry 지도학습`.
- Donate-a-Cry 분할, 입력, 지도학습 설정과 seed를 맞춘다. 이 비교로 BABYCRY를 거친 효과를 확인한다.
- 전체 원인 분류 성능을 고른 뒤 최종 테스트를 한 번 연다. BABYCRY 손실만 낮아지고 원인 분류가 개선되지 않았다면 그 결과를 그대로 보고한다.
- 설정 탐색 중 S1 체크포인트의 품질을 확인하고 싶으면 Donate-a-Cry **훈련·검증** 자료만 사용한 작은 probe를 별도 실행할 수 있다. 최종 테스트는 접근하지 않는다.

### R. 연구 결과를 활용하는 후속 실험

- R1 추가 입력: S2 표현에 같은 창의 F0 중앙값·변동 폭, 발성 비율, 상대 에너지 변화, spectral flatness, 구간 내 발성/쉼 길이 등 8~12개 후보를 붙인다. 추정 실패는 결측 플래그로 표시한다.
- R2 보조 과제: S1의 자기지도 손실 또는 S2의 분류 손실에 음향 특징 예측 손실을 더한다. lambda 0/0.1/0.3은 검증할 예비값이다. 분류층만이 아니라 인코더에도 해당 기울기가 전달돼야 인코더 보조학습이다.
- F0 추정 범위·신뢰성은 실제 울음 표본으로 확인한다. 절대 소리 크기를 아픈 정도로 변환하지 않는다.
- 같은 창의 실제 오디오에서 측정한 목표를 사용한다. 긴 파일 전체의 176개 측정값을 임의로 잘린 6초 창의 정답으로 사용하지 않는다.
- 연구의 평균값으로 원인 정답을 생성하지 않는다. BABYCRY 항목에는 원인 분류 손실을 계산하지 않는다.
- 각 변경은 같은 동결 범위·학습 조건을 가진 주 모델과 비교한다. 처음부터 모든 연구 특징을 넣는 것을 S1/S2 실행의 선행 조건으로 두지 않는다.

## 9. 학습 시간과 중단 기준

**예상 학습 시간 = 실제 훈련 샘플 수 × epoch 수 ÷ 실제 학습 샘플/초 + 전처리·검증·저장 시간.**

아래는 속도를 가정한 계산 예시다. M1 Pro 측정 결과가 아니다.

| 예시 속도 | 10,000개 1회 | 100,000개 1회 |
|---|---:|---:|
| 초당 1개 | 약 2.78시간 | 약 27.78시간 |
| 초당 2개 | 약 1.39시간 | 약 13.89시간 |
| 초당 5개 | 약 0.56시간 | 약 5.56시간 |

추론 속도로 자기지도학습 시간을 계산하지 않는다. 짧은 점검 후 장시간 실행에서도 성능이 유지되는지 확인한다. 전원 연결·절전 방지를 준비하고 체크포인트를 남겨 여러 날 나누어 진행할 수 있게 한다.

- 메모리 부족: 배치 감소 → 누적 조절 → 활성값 재계산 방식 검토 → 작은 학습 범위로 복귀.
- 장시간 느림: 읽기/전처리/모델 중 병목을 구분. 이미 내부 SSD를 사용하므로 저장장치 교체를 첫 해결책으로 삼지 않는다.
- 시간 예산 초과: BABYCRY 학습 표본 수·epoch를 줄여 S1 → S2의 주 경로를 유지하고, 실제 사용한 표본 수를 보고한다. 향후 환경 이전이 필요하면 동일 설정·분할·가중치를 재사용한다.
- 학습 중 비정상 수치, 지속적인 메모리 증가, 디스크 부족: 마지막 유효 상태를 보존하고 명시적인 사유로 중단한다.

## 10. 평가와 채택 기준

### 점수

- 다수 클래스 상수 예측과 간단한 음향 특징 분류기를 기준으로 둔다.
- 주 지표: macro-F1, 클래스별 precision/recall/F1, 혼동행렬, 클래스별 실제 지원 표본·그룹 수.
- 동일 분할에서 seed 3개로 비교하고 가능하면 그룹 단위 불확실성 구간을 보고한다. 학습 변동과 데이터 표본 부족을 따로 설명한다.
- 녹음 장치·원본 샘플레이트·월령별 성능을 표본 수와 함께 확인한다. 정보가 없으면 '미확인'이다.
- 확률 보정 및 판단 유보 경계는 검증 집합에서만 선택하고, 유보한 비율과 남은 예측의 성능을 함께 보고한다. 낮은 softmax 점수가 모든 미지의 소리를 잡아주는 것은 아니다.
- 최종 테스트는 모델 선택 후 한 번 확인한다. 결과를 보고 모델을 다시 선택하면 새 독립 테스트가 필요하다.

### 채택

새 실험은 같은 대조 모델보다 macro-F1이 일관되게 개선되고, 지원하려는 소수 클래스가 무너져 있지 않으며, 제품의 입력 품질·판단 유보 동작과 지연 목표를 만족할 때 채택한다. 한 번의 우연한 최고 점수나 자기지도 손실 감소로 채택하지 않는다. 개선 근거가 약하면 더 단순한 모델을 유지한다.

감지기는 원인 분류기와 별도로 비울음 입력에 대한 오탐, 울음 누락, 사건 단위 성능과 실제 관측 시간당 오탐을 평가한다. 비울음 자료가 없는 상태에서 감지 기능 검증 완료라고 보고하지 않는다.

## 11. 서비스 전달과 자동 실행 단위

최종 전달물:

- 추론용 인코더와 분류층 가중치. 자기지도 목표 인코더·예측기·optimizer는 추론 패키지에서 제외한다.
- 전처리 설정, 정규화, 라벨 매핑, 음향 특징 정의, 결측 처리, 판단 유보 경계.
- 평가 결과, 지원 데이터 범위, 데이터/모델 이용 조건, 모델 버전과 해시.
- 서버 CPU와 맥북에서 동일한 고정 음원으로 결과를 비교하는 검증 자료.
- 중단된 학습을 재개할 full checkpoint와 새 학습의 초기 가중치를 구분한다.

서비스에서는 `quality_status`, `cry_detected`, `candidate_scores`, `abstain_reason`, `model_version`, `preprocess_version`을 전달하도록 기존 API 설계와 연결한다. 공개 데이터로 학습하지 않은 생활 맥락은 기록 조회·규칙의 근거로 따로 표시한다. 보호자 행동과 반응은 검수 대상 자료로 축적하며 곧바로 정답으로 확정하지 않는다.

향후 구현할 자동 실행 단위는 다음과 같다. 아래는 **예정된 작업 단위**이며 현재 존재하는 실행 명령이 아니다.

1. 환경 검사·의존성 준비·MPS 점검
2. 내부 저장 위치·남은 공간 검사·데이터 수신·무결성 확인
3. 음원 감사·원본 대응·중복 검사·그룹 분할
4. 전처리·MPS 동작 및 메모리 점검
5. S1 BABYCRY 1,000/10,000/전체 단계 실행·중단·재개
6. S2 같은 인코더를 이어받은 Donate-a-Cry 지도학습
7. S3 대조 평가 및 선택적인 R 연구 특징 실험
8. 실험 비교 보고서·추론 모델 내보내기

한 번 실행하면 각 단계의 상태와 실패 원인이 기록되도록 한다. 사람이 파일 10만 개를 개별 다운로드하거나 옮기는 절차로 설계하지 않는다. `pending → running → verified`와 `failed / skipped(reason)`을 사용하고, 파일이 존재한다는 이유만으로 검증 완료로 바꾸지 않는다.

### 구현 완료 기준

- 원본 개수·용량·항목 무결성과 전처리 성공/실패 목록을 설명할 수 있다.
- 그룹·중복·원본 녹음이 분할을 넘지 않는지 검사 결과가 있다.
- MPS에서 S1/S2의 forward/backward·학습·재개가 실제로 검증됐다.
- 실제 샘플/초와 메모리 측정에 기반한 S1 전체 실행 견적이 있다.
- S1/S2/S3 및 R 중 실행한 것과 실행하지 않은 것이 명확하고 같은 대조 조건으로 비교됐다.
- 채택 모델, 지원하지 않는 기능·라벨, 아직 확보하지 못한 자료가 명시됐다.
