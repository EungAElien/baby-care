# A-02 ① 브라우저 오디오 기기 시험표

상태: **Windows Chrome 일부 화면 흐름만 관찰, 실제 마이크 인수 미완료**. 2026-09-20 Chrome 153.0.8010.48에서 개발용 목 화면의 `idle` → 시작 클릭 후 `requesting` → 권한 요청 중 중지 후 `stopped` → 화면 이탈·복귀 후 `idle`을 관찰했다. 브라우저 권한 프롬프트를 제어할 수 없어 허용·거부 뒤 AudioWorklet/MediaRecorder 값과 마이크 표시를 확인하지 못했다. 기기별 권한·잠금·통화·30분 시험은 여전히 미실행이다. [격리 인수 기록](./verification/a-acceptance-local-2026-09-20.md)을 참고한다. 이 표는 A-02 전체, AC04~AC07, SEC25~26·33·60의 통과 증거가 아니다.

코드 검증(Windows 로컬 Worktree, 2026-09-20): `npm ci`, `npm run typecheck`, `npm run lint`, `npm run build` 성공, 최신 `develop` 통합 후 `npm test` 23개 파일·95개 테스트 통과. 자동 테스트는 브라우저 오디오 API를 가짜 객체로 대체해 시작 전 권한 요청 없음, 권한 거부/API 미지원, Worklet/Recorder 값 분리, 트랙 종료·범위 전환·이탈 이벤트 정리, 늦은 권한 승인 시 트랙 폐기, 자동 재개 없음과 개발 모드 React Strict Mode의 effect 재설치 후 측정 시작 가능 여부를 확인했다. 개발 서버의 목 사용자 화면에서 초기 `idle` → 시작 클릭 후 `requesting` → 권한 요청 중 중지 후 `stopped`를 확인했지만 마이크 권한을 부여하지 않았다. 실제 오디오 프레임·코덱·OS 중단은 검증하지 않았다.

## 준비와 공통 절차

1. `apps/web/`에서 `npm ci`, `NEXT_PUBLIC_ENABLE_MOCK_NAV=true`를 개발 환경에 설정한 뒤 `npm run dev`를 실행한다. 다른 기기에서는 HTTPS로 접속한다. 브라우저에서 마이크 권한이 가능한 보안 컨텍스트인지 확인한다.
2. `/login`에서 개발용 목 사용자로 아기 홈에 들어가 `/babies/{baby_id}/detect`의 **개발용 오디오 측정 화면 열기**를 선택한다. 실제 계정으로 시험할 때는 현재 아기 멤버십이 필요하다. 이 화면은 개발 빌드에서만 열린다.
3. 시작 전 브라우저의 마이크 사용 표시가 꺼져 있고 화면 값이 모두 `확인할 수 없음`인지 확인한다. **측정 시작**을 한 번 누르고 권한을 처리한다. 권한 허용 뒤 AudioWorklet 값과 MediaRecorder 결과값을 각각 기록한다. MediaRecorder 길이가 미확인이면 그대로 미확인으로 적는다.
4. 중지 또는 각 중단 상황 뒤 마이크 사용 표시가 꺼지는지, 돌아왔을 때 자동 재개하지 않는지 확인한다. 다시 시작하려면 반드시 버튼을 새로 눌러야 한다. 시험 중 음성 내용이나 Blob을 녹화·내보내기·콘솔에 기록하지 않는다.

AudioWorklet의 `첫/마지막 오디오 시계`는 벽시계가 아닌 `AudioContext` 프레임 시각이다. 처리 샘플 수는 마지막으로 수신한 Worklet 보고까지의 실제 프레임 수다. MediaRecorder 길이는 Blob의 미디어 메타데이터를 브라우저가 읽은 경우에만 표시한다. 두 값의 차이를 자동으로 성공/실패로 판정하지 않는다. 권한 표시, `track ended`, 잠금·통화 동작은 OS와 브라우저마다 달라 직접 관찰해야 한다. 브라우저 API가 잠금·통화 자체를 항상 알리지는 않는다.

### 상황별 재현

- **권한 거부:** 사이트 권한을 초기화하고 시작 버튼을 누른 뒤 거부한다. `error`와 미확인 측정값, 마이크 표시 꺼짐을 확인한다. 권한을 다시 허용해도 버튼을 다시 누르기 전에는 시작하지 않아야 한다.
- **장치 변경:** 청취 중 입력 장치를 OS/브라우저 설정에서 바꾸거나 마이크를 분리한다. 기존 트랙이 `ended`를 내는지와 중단·마이크 표시 해제를 기록한다. 브라우저가 트랙을 유지하면 그 사실과 측정값의 변화도 기록한다. 장치 변경만으로 모든 브라우저가 `ended`를 내는 것으로 가정하지 않는다.
- **숨김·잠금:** 청취 중 다른 탭/앱으로 이동하고, 별도 회차에서 화면을 잠근다. 복귀 뒤 상태·권한 표시·자동 재개 여부를 기록한다. 잠금 중 `visibilitychange`가 오지 않으면 OS 권한 표시와 샘플 증가 여부를 별도로 기록한다.
- **통화·연결 중단:** 청취 중 전화/화상 통화로 마이크를 점유하고, 별도 회차에서 헤드셋 연결을 끊는다. `ended` 또는 숨김 이벤트가 발생하는지, 발생하지 않으면 브라우저가 중단을 감지하지 못한 구간을 기록한다. 시험 뒤 사용자가 중지하고 다시 시작한다.
- **전경 30분:** 화면을 계속 켜 두고 0/10/20/30분의 Worklet 샘플 수·오디오 시계·샘플레이트를 적는다. MediaRecorder는 첫 약 3초 클립만 측정한다. 시작/끝의 마이크 표시와 중지 뒤 트랙 종료, 자동 재개 없음을 확인한다. CPU·배터리나 ONNX 성능 판정은 이 시험 범위가 아니다.
- **계정·아기 전환/로그아웃/화면 이탈:** 청취 중 아기 전환, 로그아웃, 다른 라우트 이동, 브라우저 뒤로가기를 각각 재현한다. `PrivateScope` 정리와 컴포넌트 해제 뒤 마이크 표시가 꺼지는지, 원래 화면으로 돌아와도 자동 시작하지 않는지 확인한다.

실패·미확인 상황에서는 브라우저의 오디오 측정을 지원 완료로 표시하지 않는다. 직접 녹음·파일 입력은 후속 A-05에서 제공하며, 이 시험 화면은 업로드나 분석의 대체 경로를 구현하지 않는다.
