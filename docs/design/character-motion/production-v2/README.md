## 실제 사용한 제작 경로

Figma 벡터 편집 → SVG 가져오기 → Lottie Creator 타임라인 → Creator Export의 표준 Lottie JSON 다운로드 → lottie-web 5.13.0 SVG 재생을 사용했다. Creator UI 버전은 v1.113.0으로 표시됐다. 공식 `@lottiefiles/creator-mcp` 0.2.2로 편집기의 부위 키프레임을 조작했고, 내보내기는 Creator UI에서 직접 수행했다. After Effects·Illustrator·Bodymovin은 사용하지 않았다.

`sources/*.svg`는 실제 Figma 출력이다. PNG에서 초기 색면을 추출한 뒤 Figma의 벡터 경로를 편집했다. 머리, 몸통, 팔·손과 보호자 옷의 거친 윤곽을 정리하고 겹침을 보완했다. Creator 가져오기에 앞서 전체 캔버스를 감싼 최상위 그룹 하나만 해제했다. 경로 데이터는 그대로 유지했다. 기존 React 그림의 도형을 Lottie로 변환한 작업이 아니다.

`exports/*.json`은 Creator가 다운로드한 파일 그대로다. 수작업으로 Lottie 도형이나 키프레임 JSON을 생성하지 않았다. 파일 내부에 사용하지 않는 시험 precomposition이 포함되어 있으나 재생 루트는 해당 실제 장면을 참조한다. 외부 이미지·폰트 종속 자산은 없다. 공개 웹 파일은 이 JSON과 바이트 단위로 동일하다.

현재 확인한 출력 기능은 벡터 경로·색면, 그룹 겹침, 위치·회전·크기 키프레임과 easing이다. 마스크, 임의 효과·표현식, 경로 morph의 편집기/웹 일치는 이번 출력으로 검증하지 않았다. 눈 감김은 눈 모양의 세로 크기 키프레임으로 만들었으며 별도 눈꺼풀 경로 리그는 미제작이다.

## 시각 검수와 남은 차이

1. **시안 → 원본:** [편안함](review/observation-calm-comparison.png), [배고픔](review/ai-hungry-comparison.png), [안아줌](review/action-holding-comparison.png)을 직접 열어 비교했다. 각 열은 같은 실제 픽셀 크기다. 분홍=시안, 청록=원본, 보라=겹친 실루엣이다. 색 임계값으로 윤곽을 잡아 안아주기 내부에 오검출 선이 있으며 정량 유사도 자료가 아니다. 둥근 머리·볼·쉼표 컬·얼굴 배치·황토 옷·손 위치·보호자 팔의 큰 곡선을 유지했다. PNG의 미세한 명암은 평면색으로 줄었고 보호자 바지와 목 일부 윤곽은 더 정리해야 한다. 최종 외형 승인을 선언하지 않는다.
2. **Creator → Lottie:** 편안함 눈 위치가 잘못 이동한 첫 출력 전 초안을 수정한 뒤 실제 JSON을 내보냈다. 배고픔은 Creator 34f에서 손·머리 접촉을 확인했다. 웹의 대응 프레임에서 얼굴·손·색면이 유지되는 것을 확인했다. 편집기 프레임의 픽셀 차이 자동 검사는 수행하지 않았다.
3. **JSON → 실제 웹:** `review/frames/`의 PNG는 웹 검토 화면에서 lottie-web이 그린 SVG를 직접 추출했다. 편안함 0·30·43·95f, 배고픔 0·34·55f를 확인했다. 320px에서 얼굴·관절에 큰 이탈을 보지 못했다. 240px와 로그 56~72px는 별도 검수 기록에 수행 여부를 남긴다. 안아주기는 실제 Lottie 프레임이 없으므로 접촉 모션 검수 완료로 처리하지 않는다.

`posters/observation-calm.png`와 `posters/ai-hungry.png`는 각각 실제 0f 출력이다. `action-holding-source.png`는 Figma 정지 원본을 400×400 투명 캔버스에 배치한 출력이며 Lottie 프레임이 아니다. 로그용 56·64·72px PNG를 별도로 만들었다. 홈 원본의 경로를 줄이지 않았다. 로그 파생본은 크기 변환 단계이며 별도 도형 단순화는 아직 하지 않았다.

## 막힌 단계와 인계

Creator에서 안아주기의 아기와 지지 팔을 묶은 중첩 그룹에 키프레임을 넣을 때 `attempted to take ownership of Rust value while it was borrowed` 오류가 반복됐다. 다시 열기, SVG 재가져오기, 중첩 그룹 없이 각 부위에 같은 위치 키프레임을 넣는 방법도 시도했으나 탭 응답이 멈췄다. 도구가 성공 응답을 반환한 뒤 저장이 남지 않은 경우가 있어 마지막 JSON을 완성했다고 보고하지 않는다.

복구 후 먼저 Figma의 현재 SVG를 가져와 별도 Creator 프로젝트에서 접촉 부위를 편집하고 저장·다시 열기를 검증해야 한다. 동일 문제가 지속되면 After Effects와 Bodymovin 접근이 필요하다. 안아주기 실제 출력과 접촉 검수를 통과하기 전 나머지 19종을 확장하지 않았다. 하품·눈 비비기·배 감싸기·누운 자세·수유 등은 아직 제작하지 않았다.

## 웹 구현·계약 경계

기존 `scene-state`의 최신성·출처·저장 시작/성공·중복 방지·실행 ID·중단·범위 정리를 재사용했다. 렌더러는 `LottieStage`로 교체했다. 진행 중 요청은 abort하고 이전 재생 인스턴스를 destroy한다. 동작 줄이기와 로그는 플레이어를 만들지 않는다. 탭 숨김은 즉시 pause하고 상태 제어기가 대기열을 비운다. 실패는 같은 대표 PNG로 전환하고 조치 대기열을 막지 않는다. 제작하지 않은 범주는 제작 중 안내를 표시한다.

완료 장면 제어는 시험용 1회 자산 fixture로 단위 검증했다. 실제 완료 조치 Lottie가 없으므로 안아주기 JSON 재생을 제품에서 검증했다는 뜻이 아니다. 실제 FastAPI 저장 성공·삭제·권한 회수 구독을 이 검토 화면에 연결하지 않았다.

관찰 8종은 현재 계약에 존재한다. 완료 조치의 DIAPER_CHECK/SLEEP_PREPARATION과 사용자 범주 v2는 일대일 대응하지 않는다. 토닥임·재워줌·트림 완료 등의 확인 조건과 AI 포즈 표시 계약은 별도 정리가 필요하다. API enum이나 완료 조건을 임의로 추가하지 않았다. 계약/목/API 변경과 자산 추가는 별도의 후속 작업이다.
