## 실제 제작 경로

**PNG 참고 → Figma 부위별 벡터 편집 → SVG 가져오기 → Lottie Creator 타임라인 → 실제 내보내기 → lottie-web 5.13.0 SVG 재생**을 사용했다. Creator는 v1.113.0, 공식 `@lottiefiles/creator-mcp` 0.2.2로 편집기 키프레임을 조작했다. 내보내기는 Creator UI에서 수행했다. After Effects·Illustrator·Bodymovin은 사용하지 않았다.

`sources/*.svg`는 실제 Figma 출력이다. 초기 색면 추출 뒤 머리·몸·손·팔의 경로를 Figma에서 수정하고 겹침을 보완했다. Creator 가져오기 전 전체 캔버스를 감싼 최상위 그룹 하나만 해제했고 path 데이터는 유지했다. 기존 웹 그림을 Lottie JSON으로 포장하지 않았다.

편안함·배고픔·안아주기는 표준 JSON 다운로드 원본이다. 추가 AI 5종은 [Creator 표준 dotLottie 출력](exports/baby-care-ai-expansion-v2.lottie)의 `a/*.json`을 바이트 변경 없이 추출했다. 별도 코드로 도형/키프레임 JSON을 생성하지 않았다. 웹 JSON과 보관 JSON은 해시로 일치를 검사한다. 외부 이미지·폰트 의존성은 없다.

확인한 기능은 벡터 경로·색면·겹침, 위치·회전·크기 키프레임과 easing이다. 임의 효과·표현식·마스크·path morph의 출력 일치는 검증하지 않았다. 눈 감김은 눈 모양의 세로 크기로 편집했으며 독립적인 눈꺼풀 경로 리그는 아직 없다.

## 리그와 동작

[rig-snapshots.json](rig-snapshots.json)에 Creator 레이어 이름, 앞뒤 순서(0이 맨 앞), 경계와 변환 상태를 보존했다. Figma 계층과 SVG ID에도 부위 이름을 유지한다. 머리·컬·눈·눈썹·입·귀, 몸통, 상완·팔뚝·손, 다리와 주요 주름을 나눴다. 작은 움직임에 필요한 관절 겹침을 채웠지만 모든 큰 회전·가려진 부분까지 검수한 범용 리그는 아니다.

- 편안함: 작은 호흡·손 이동·눈 깜박임 뒤 휴식.
- 배고픔: 입가 손과 배 위 손의 이동, 고개 회전, 눈 깜박임.
- 졸림: 눈 비비기와 내려간 눈, 하품하는 입을 연결하고 시작 자세로 복귀. 대표 34f.
- 트림 필요: 세운 몸통의 작은 호흡, 가슴 위 손과 고개의 연결된 이동, 답답한 표정 유지.
- 배 불편함: 배를 감싼 손, 당기는 무릎, 작은 웅크림. 원인을 뜻하는 아이콘 없음.
- 일반적인 불편함: 양팔과 다리의 시차 있는 작은 뒤척임.
- 판단 어려움: 특정 감정·원인을 단정하지 않는 정지 자세. 실제 화면에서는 플레이어를 생성하지 않고 같은 출력의 PNG 사용.
- 안아줌: 아기와 지지 팔·앞팔·손 주름을 동일한 작은 경로로 이동시켜 접촉 유지. 자동 미소·잠듦 없음.

AI 문구와 배지는 그림 밖에 표시한다. 반복 시작/끝에 기본 자세로 머무는 구간을 두었다. 내부 장면의 기본 길이가 53f로 들어온 트림·불편함은 96f로 연장하고 부위 표시 구간도 맞췄다.

## 세 단계 시각 검수

1. **PNG → Figma 원본:** `review/*-comparison.png`는 동일 픽셀 크기 비교와 윤곽 겹침이다. 분홍=시안, 청록=편집 원본, 보라=겹침. 색 임계값 윤곽에는 내부 오검출이 있어 유사도 점수로 쓰지 않는다. 둥근 머리·볼·컬·얼굴 배치·손 위치·황토 옷·보호자 팔 곡선을 대조했다. PNG의 미세 명암은 줄었다. 배 불편함의 옷 외곽과 발 주름, 보호자 바지·목의 세부 윤곽은 추가 정리가 필요하다.
2. **Creator → 출력:** 대표/중간 프레임을 Creator에서 직접 확인하고 출력 대응 프레임과 대조했다. 안아주기는 중첩 그룹의 Rust 오류를 피하도록 각 접촉 부위를 편집하고, 저장 탭과 MCP 연결을 맞춰 실제 JSON 출력을 복구했다. 편집기/웹의 자동 픽셀 차이 검사는 수행하지 않았다.
3. **출력 → 웹:** `review/frames/`는 실제 lottie-web SVG에서 추출한 PNG다. 표의 프레임에서 표정·손·무릎·관절과 접촉을 확인했다. 관찰한 프레임에서 큰 분리·관통은 발견하지 못했으나 모든 연속 프레임의 최종 승인 검수는 남아 있다. 홈 240·320px와 로그 56·64·72px 파생본을 확인했다. 작은 표정에는 범주 문구를 함께 표시해야 한다.

`posters/*.png`는 실제 대표 프레임이며 졸림만 34f, 나머지는 0f다. 로그 PNG는 같은 프레임의 별도 크기 파생본이다. 홈 원본의 경로는 줄이지 않았다. 로그용 도형 단순화는 아직 하지 않았다. `action-holding-source.png`는 이전 정지 원본 이력이며 현재 대표 자산은 `action-holding.png`다.

## 웹 상태 제어와 API 경계

기존 `scene-state`의 최신성·출처·새 저장 성공·중복 방지·실행 ID·중단·범위 정리를 유지한다. `LottieStage`는 자산을 재생하고 CSS는 배치와 주변 UI를 맡는다. 요청은 abort, 이전 플레이어는 destroy한다. 동작 줄이기·과거 로그·로딩 실패는 동일 원본 PNG를 사용한다. 숨겨진 탭은 pause하고 제어기가 대기열을 비우며 복귀 때 밀린 조치를 재생하지 않는다. 종료·건너뛰기는 최신 유효 관찰로 돌아가고 돌봄 성공을 추론하지 않는다.

안아주기 실제 자산 등록 후 시험용 자산 가정을 제거하여 실제 레지스트리로 수명주기 단위 검증한다. 검토 화면의 1회 종료 표시도 마지막 프레임으로 고쳤다. 실제 FastAPI 저장 성공·삭제·권한 회수 구독은 아직 연결하지 않았다.

현재 계약에 관찰 8종은 존재한다. DIAPER_CHECK/SLEEP_PREPARATION과 범주 v2는 일대일 대응하지 않는다. 토닥임·재워줌·트림 완료의 확인 조건과 AI 표시 계약은 별도 정리가 필요하다. API enum이나 완료 조건은 임의 추가하지 않았다. 실제 API·권한·모바일 기기·마이크 병행 성능·배터리 검증은 수행하지 않았다.
