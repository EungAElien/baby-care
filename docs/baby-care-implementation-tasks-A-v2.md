# A 실행 태스크 — 윤정님 · 웹·브라우저·캐릭터 (업무 분담 v2.1)

담당: 윤정님(A)  

협업 상대: 예준님(B, API·데이터·ML·LLM)  

기준: [PRD v2](./baby-care-prd-v2.docx), [기능명세 v2](./baby-care-functional-spec-v2.docx), [개발계약 v1.1.1](../contracts/개발계약.md), [OpenAPI 계약](../contracts/openapi계약.json), [목 응답·시험 사용자 배치](../contracts/목%20응답과%20시험%20사용자%20배치.json)

보안 참고: [보안 설계 v1.1](./security/보안%20설계서.md), [A·B 보안 작업 연결표](./security/AB%20보안%20작업%20연결표.md), [62개 보안 시험표](./security/62개%20보안%20시험표.md)

이 문서는 구현 체크리스트다. 제품 범위는 PRD v2, 기능 동작과 인수 조건은 기능명세 v2, 웹 연동 필드·상태·HTTP 오류·권한의 구체값은 개발계약 v1.1.1과 OpenAPI 계약을 따른다. A는 화면, 브라우저 오디오, 상태 표현, 웹 통합 시험을 주도한다. 권한의 최종 판정이나 모델 결과의 생성은 브라우저에서 하지 않는다. 계약 간 충돌이 보이면 A가 임의로 정하지 않고 B와 변경을 합의한다.

## 윤정님께 전달 — 이번에 달라진 점

기존에 나눈 **A는 웹·브라우저, B는 API·데이터·ML**이라는 역할은 그대로입니다. 세 대화에서 구체화한 상담·캐릭터·보안을 실행 항목으로 넣었습니다. A가 LLM 호출이나 서버 권한 검사까지 맡는 방식으로 역할을 넓힌 것은 아닙니다.

| 변경 사항 | 이전 문서와 달라진 점·이유 | 윤정님이 추가로 할 일 | B가 먼저 제공하거나 함께 확인할 것 |

## 이번 개정의 범위와 역할 연결

업무 분담의 개정 번호 v2.1과 API 계약 버전 1.1.1은 별개다. 계약 1.1.0에는 B-04 재인증·세션 회수·아동 정보 처리 게이트가, 1.1.1에는 B-09 변경 조회 의미가 추가됐다. 상담 API와 캐릭터 자산이 구현되었다는 뜻은 아니다. 기존 A-01~A-11과 완료 기록은 유지하고 캐릭터 제작 A-12, 개인화 상담 A-13을 추가한다. B의 상세 업무는 [B 실행 태스크](./baby-care-implementation-tasks-B-v2.md)를 따른다.

| 반영 영역 | A가 맡을 일 | B에게 받을 것 | 범위 |
| --- | --- | --- | --- |
| 개인화 상담 | A-13: 아기별 개인 채팅·근거 보기·기록 확인·개인 기억 관리 | B-14: 권한 있는 기록 조회·대화 API·답변 근거·복구/삭제 계약 | 이번에 추가한 개발 작업. 기존 첫 통합 시연과 별도 인수 |
| 부모·아기 캐릭터 | A-07의 상태 그래픽을 유지하고 A-12에서 캐릭터 원본·모션·플레이어 제작 | B-06·B-07: 분석 후보, 확인된 행동·관찰, ID·버전·시각·출처 | F18 기본 표현은 기존 P0. 상세 모션의 완료 여부는 별도 기록 |
| 보안 | A-01~A-11·A-13의 브라우저 노출·전환·안내·복구 검증 | B-01~B-13·B-14: 서버 권한·외부 전송·수명·삭제 강제 | 기존 계약의 보호 규칙과 새 계약이 필요한 제안을 구분 |

현재 OpenAPI에는 상담 경로가 없다. A-13·B-14에서 팀 계약·OpenAPI·목 응답·화면 매핑·관련 인수 조건을 함께 확장하는 작업을 먼저 한다. 그전에도 합성 자료로 화면 시안을 만들 수 있으나 이를 확정 API 연동이나 기능 완료로 표시하지 않는다. 기존 P0와 AC01~AC44 및 첫 통합 시연 목표는 바꾸지 않는다.

## 담당 표시와 완료 원칙

- **[Codex]**: 저장소에서 코드·테스트·목 응답·문서를 작성하고 빌드/자동 검증까지 맡길 일.
- **[직접]**: B와의 합의, 제품·안전 문구 판단, 본인 계정/기기에서의 실제 시험, 서비스 설정·비밀값 관리처럼 A가 책임질 일. 계약 초안·자료 조사·시험 자동화는 Codex가 지원할 수 있다. 이미 승인된 범위에 새로운 승인 절차를 만드는 표시는 아니다.
- **[Codex → 직접 확인]**: Codex가 먼저 구현하고 A가 실제 흐름·권한·표현을 확인한 뒤 완료할 일. 코드가 작성되었다는 이유만으로 체크하지 않는다.

Codex에게 맡길 때는 아래의 **한 번에 맡길 범위**처럼 작은 단위로 나누는 것을 권한다. 기존 P0 계약은 확정됐지만 신규 상담·보안 확장 계약과 실제 서버·계정 검증은 별도 작업이다. 기존 계약으로 만들 수 있는 화면은 먼저 진행하고, 새 서버 기능은 B가 계약과 목 응답을 마련하면 연결한다. 각 구현 요청에는 관련 인수 조건, 완료 기준, 필요한 검증, 변경 파일과 남은 위험 보고를 포함한다. 이 문서의 구현 요청 예시는 이번 문서 수정 요청을 코드 작성·배포 지시로 확대하지 않는다.

보안 설계 v1.1은 전체 시험 계획이다. B-03/B-04가 일부 SEC의 로컬 DB·API·STANDARD Storage 하위 조건을 실행했지만 A의 브라우저·운영·TUS·기존 재생 URL을 포함한 전체 SEC 통과는 아니다. A는 계약 1.1.0의 서버 상태를 연결하고, 아직 계약에 없는 제안은 B와 보완한 뒤 사용한다.

### A-03 실제 초대·동의·재인증·세션 회수 연결 (2026-09-20)

- 실제 API 경로: OWNER 초대 발급·재발급은 `CREATE_INVITE` challenge → 새 이메일 OTP 세션 → 5분 proof → 같은 UUID 멱등 요청으로 연결했다. 링크는 최초 응답에서만 탭 메모리에 표시하고, 링크가 유실되면 재발급을 안내한다. `/invite/[inviteId]`는 서버의 실제 fragment 링크를 열어 주소에서 즉시 비운 뒤 지정 이메일로 OTP 로그인·SHARED_USE 수락을 이어간다. 목 `/invite/accept`는 별도 미리보기로 남긴다.
- 동의: `/consents`의 범위별 상태와 개인 동의 이력을 조회하고, 현재 버전으로 철회한다. 새 동의는 공개 환경 설정에 **승인된** 문구와 정확한 `policy_version`이 함께 있을 때만 표시한다. 아기 학습 참여는 `/child-data-verification`의 `production_processing_allowed`와 `ENABLE_BABY_TRAINING` 새 OTP proof가 모두 있어야 한다. 탈퇴 뒤 `/account?baby_id=...`에서 본인 학습 동의를 조회·철회하며 새 동의는 막는다.
- 계정: 일반 로그아웃은 CURRENT, 계정 화면은 OTHERS/ALL 회수를 요청한다. 로컬 로그아웃과 제공자 회수 실패·결과 불명을 구분해 표시하며 OTHERS는 서버 작업 ID로 상태를 다시 조회한다. 로그아웃 시작 시 화면 초안을 비우고 공유 내용을 가린다.
- 합성 자동 검사·타입·린트·목 플래그 양쪽 빌드는 이 브랜치의 코드 연결 증거다. 승인 정책 값과 실제 OTP 두 계정·로컬 Supabase/FastAPI 세션이 없어 실제 초대·동의·재인증·회수 브라우저 인수와 SEC14~24 전체 통과는 아직 주장하지 않는다. 실제 정책 출처와 버전, 두 계정, 이메일 전송 경로 및 로컬 API가 필요하다.

- [ ] **[Codex → 직접 확인]** 아기 표정은 마지막 확인 관찰과 시각을 유지한다. 후속 반응이 없으면 ‘반응 미확인’, 30분 경과 시 정지 그림과 경과시간을 표시한다. 삭제·권한 회수·아기 전환 시 모션·이전 상태를 정리하고 현재 유효한 기록을 다시 조회한다.

## A-13. 아기 기록을 활용하는 개인화 상담 화면

선행: B-14가 상담 계약·목 응답·안전/외부 전송 조건을 제공한다. 그전에는 합성 대화 시안을 만들고, 새 경로·상태값을 현재 OpenAPI에 있는 것처럼 구현하지 않는다.

정규화·상담의 선택 모델은 OpenAI GPT-5.6 Terra (`gpt-5.6-terra`)다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-terra) 확인과 모델 선택은 실제 키 등록·API 호출·인수 시험 통과와 별개다. API key는 B의 서버 설정이며 A가 사용자에게 키 입력을 요구하거나 브라우저에서 OpenAI를 직접 호출하지 않는다.

착수와 전체 완료는 구분한다. 먼저 일반 질문·분석 없는 기록 질문·후속 질문·조회 실패의 합성 시안을 만들 수 있다. B-14 ① 계약이 확정되면 준비된 조회 도구를 사용하는 읽기 중심 대화를 연결하고, B-07 확인 저장·B-08 사례·B-11 집계는 각 실제 결과가 준비될 때 추가한다. 상세 단계와 실제 전송 조건은 B-14의 작업 단위 표를 따른다. 일부 연결을 전체 상담 인수로 표시하지 않으며 기존 첫 통합 시연 순서는 유지한다.

- [ ] **[Codex → 직접 확인]** 현재 아기와 본인 전용 대화임을 분명히 표시하고 아기별 대화 목록·새 대화·이어보기·삭제를 만든다. OWNER도 다른 보호자의 상담을 볼 수 없으며 공동 돌봄 기록과 개인 대화 화면을 구분한다.
- [ ] **[Codex → 직접 확인]** 일반 육아 정보·간단한 고민 대화, 개인 기록 질문, 기록 남기기를 지원한다. 질문 전에 녹음이나 분석 완료를 요구하지 않는다. B가 전달한 답변·개인 기록 근거·일반 정보 출처·추가 질문·기록 후보를 구분하고, 아기 기록을 쓰지 않은 일반 답변을 개인화 결과처럼 표시하지 않는다.
- [ ] **[Codex → 직접 확인]** 입력·응답 대기·완료·중단·복구·실패·한도 초과·외부 상담 비활성·기록 부족을 구별한다. B가 정한 동일 메시지·실행 식별자로 상태를 조회해 응답 유실을 복구한다. 중단 버튼은 서버 취소 확인과 연결하며 화면 정지만으로 호출·저장·비용까지 취소됐다고 표시하지 않는다.
- [ ] **[Codex → 직접 확인]** 지정 기간에 기록이 없는 상태와 조회 실패·도구 미준비·일부 결과 누락을 서버 결과에 따라 구분한다. 실패를 '기록 없음'이나 0으로 바꾸지 않고 조회한 범위·확인하지 못한 범위와 복구 경로를 보여준다. LLM 실패 때 성공 말풍선이나 STUB 응답을 대신 만들지 않는다.
- [ ] **[Codex → 직접 확인]** 답변의 근거 기록·관찰 시각·조회 기간과 일반 정보의 출처·검토일을 보여준다. 현재 권한으로 원본을 조회하고 수정·삭제된 근거는 오래된 인용으로 열지 않는다. 기록 부족은 추가 질문·한계 표시로 처리하며 과거 행동 뒤의 반응을 효과의 입증으로 단정하지 않는다.
- [ ] **[Codex → 직접 확인]** 대화에서 추출한 행동·상태·반응 후보는 A-07의 확인 카드로 연결한다. ‘분유 먹였어’는 수행 후보, ‘먹일까?’는 계획/질문으로 구분하고, 수정·확인 후 기존 기록 API로 한 번만 저장한다. 일반 대화마다 확인을 요구하거나 상담 답변을 수행 라벨로 자동 저장하지 않는다.
- [ ] **[Codex → 직접 확인]** 최근 대화와 사용자 저장 선호/기억을 구분해 보여주고 본인이 저장·수정·삭제하도록 한다. 대화 삭제·기억 삭제·공동 기록 삭제의 범위를 안내한다. 상담과 개인 기억을 자동으로 다른 보호자에게 공유하거나 학습 동의로 간주하지 않는다.
- [ ] **[Codex → 직접 확인]** 대화에서 '지금 말씀하신 내용'과 확인된 기록의 근거를 구분한다. 단순 발언이나 앞선 LLM 설명을 프로필·확인 기록·장기 기억으로 자동 저장하지 않으며, 기록 확인과 개인 기억 저장은 별개 동작으로 제공한다. 후속 질문의 대상이 모호하거나 기록과 진술이 다르면 B가 반환한 확인 질문과 차이를 표시한다.
- [ ] **[Codex → 직접 확인]** 정규화보다 넓어진 전송 범위인 질문·관련 과거 기록·대화 맥락을 목적·보관 안내와 연결한다. B의 상담 허용 조건이 충족되지 않으면 실제 전송은 비활성화하고 기존 기록 입력 경로는 유지한다.
- [ ] **[Codex → 직접 확인]** 아기/계정 전환·권한 회수 때 요청·표시·캐시·미전송 텍스트를 정리하고 늦은 답변을 버린다. 미전송 질문은 자동 공유 기록으로 저장하지 않는다. 개인 대화 초안 저장을 제공하려면 B-14에 수명·권한을 별도로 정의한다.
- [ ] **[Codex → 직접 확인]** 답변은 안전한 텍스트로 표시하고 모델이 낸 HTML·외부 이미지·임의 링크를 실행하지 않는다. 검수된 도움 안내가 필요한 응답은 일반 대화와 구분해 표시하고, 확신형 진단·치료 약속이나 챗봇의 실시간 감시를 암시하지 않는다.

전달물: 상담 화면·기록 확인 카드·근거/기억 관리·실패/전환 복구 화면과 검증 기록. 완료 기준: 일반 질문이 가능하고 ‘과거 기록 질문 → 근거 확인 → 대화 이어가기 → 실제 행동 초안 확인 저장’이 이어지며, 타 보호자·타 아기 자료와 삭제된 근거가 노출되지 않는다. 아래 CHAT01~CHAT10과 B-14를 함께 통과해야 실제 상담 완료로 표시한다.

첫 요청 예시: “PRD v2·기능명세 v2·`contracts/개발계약.md`·`contracts/openapi계약.json`·`contracts/목 응답과 시험 사용자 배치.json`과 `docs/security/`의 설계·연결·시험표를 기준으로 **A-01의 ①만** 구현해 줘. 보안 문서의 새 API 제안은 아직 확정 계약이 아니니 경로·오류를 지어내지 마. 실제 API·시험 계정은 준비됐다고 가정하지 말고 제공된 계약과 합성 fixture를 사용해. 관련 자동 테스트와 빌드를 실행하고 변경 파일·검증 결과·SEC09/34/51/57/58에서 내가 확인할 항목을 보고해 줘. A-01의 ②와 배포는 이번 요청에서 하지 마.”

보안 보강은 위의 관련 기능 요청 안에서 하나씩 처리한다. A-01의 ①에는 공개/비공개 데이터 경계와 영구 캐시 금지를 포함하고, A-03의 ②에는 초대 토큰·전환 안전성을, A-05의 ②에는 TUS·재생 URL 안전성을, A-11의 ②에는 CSP·preview/증거 점검을 포함한다. 범위가 커지면 다음 번호를 합치지 말고 **같은 번호의 보안 보강을 별도 요청**으로 나눈다.

## 보안 시험과 완료 판정

- A 단독 주관: **SEC32, SEC34, SEC57, SEC58, SEC60**. 아기/계정 전환 격리, 텍스트 주입·CSP, Next.js 응답·캐시, 오프라인 재전송, 운영 빌드의 마이크/WASM 호환성을 실제로 확인한다.
- A+B 공동: **SEC05, SEC07, SEC14, SEC16, SEC17, SEC19, SEC21, SEC24, SEC28, SEC33, SEC38, SEC44, SEC48, SEC51, SEC56, SEC59, SEC61, SEC62**. B의 서버·Storage·권한 결과와 A의 화면·브라우저 결과를 같은 시나리오로 대조한다.
- 나머지 보안 시험은 B 또는 운영 책임자가 주관하더라도 A-03~A-11의 실제 인수에 영향을 주면 결과를 확인한다. [A·B 연결표](./security/AB%20보안%20작업%20연결표.md)의 작업별 대표 SEC 번호와 [62개 시험표](./security/62개%20보안%20시험표.md)의 기대값을 사용한다. B-03·B-04·B-09와 B-13 격리 로컬 검사에서 관련 하위 조건은 일부 실행됐지만, 이 표의 SEC 전체 단위와 A 브라우저·운영 인수의 통과 판정은 별도로 남아 있다. 특히 Realtime SEC30·SEC31은 미실행이다.

## 첫 통합 시연 목표

A-03~A-08을 B의 대응 작업과 합쳐 **두 보호자 로그인 → 녹음 → 실제 분석 또는 정직한 유보 → 행동·상태 확인 기록 → 다른 보호자 화면 반영**을 먼저 완주한다. 제공 fixture나 STUB으로 확인한 흐름은 개발 연결 확인일 뿐, 실제 분석을 포함한 통합 시연 완료가 아니다. 활성 감지·요약·학습 후보는 이후에도 P0 완료 전까지 구현·검증해야 한다.

권장 진행: 기존 첫 통합 시연 → 전체 P0 인수 → 추가 상담·상세 모션 통합 인수. A-12 자산 제작과 A-13/B-14 계약·합성 시안은 앞 단계와 나란히 준비할 수 있다. 상담 API나 정교한 캐릭터 제작을 기존 첫 시연의 새 선행 조건으로 만들지 않는다.

## 추가 기능의 공동 인수 조건

아래 ID는 이번 업무 분담의 시험 계획이며 기존 AC·SEC 번호나 API enum을 바꾸지 않는다. 모두 미실행이다. B 문서에도 같은 기대값을 싣고, A는 화면·브라우저 증거를, B는 권한·저장·조회·외부 호출 증거를 맡는다.

| ID | 함께 확인할 상황과 통과 기준 | 주 담당 |
| --- | --- | --- |
| CHAT01 | 다른 아기·다른 보호자 대화/기억/인용/도구 인자를 요청해도 자료가 노출되지 않고 OWNER 예외가 없음 | B, A 화면 확인 |
| CHAT02 | 기록 부족·수정·삭제·권한 회수 후 새 답변과 저장된 답변·요약·기억·인용이 오래된 근거를 재노출하지 않음 | B+A |
| CHAT03 | 권유·계획·부정은 수행으로 저장되지 않으며, 실제 행동 후보를 사용자가 확인하면 기존 기록에 한 번만 저장 | A+B |
| CHAT04 | 응답 유실·재시도·중단·아기 전환·늦은 답변·한도 초과에서 중복 저장과 이전 범위 답변 노출이 없음 | A+B |

| CHAT06 | 상담 게이트가 꺼지면 위조 DEMO 요청도 외부 호출 0건이며, 켜진 환경은 처리 조건·최소 전송·로그 제거 증거가 있음 | B+운영, A 안내 확인 |

| CHAT08 | 기간·아기 시간대·자정 통과·수유량 미상·빈 기록을 포함한 답변의 숫자가 서버 집계와 일치하고, 기록 없음·미상·실제 0 및 보류 사유를 보존함 | B, A 표시 확인 |

| CHAT10 | 조회 실패·도구 미준비·일부 결과 누락이 기록 없음으로 표시되지 않고, 일반 정보와 개인화 답변을 구분하며 LLM 실패를 STUB 성공으로 대체하지 않음 | B+A |
