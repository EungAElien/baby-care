# A 실행 태스크 — 윤정님 · 웹·브라우저·캐릭터 (업무 분담 v2.1)

담당: 윤정님(A)  

협업 상대: 예준님(B, API·데이터·ML)  

기준: [PRD v2](./baby-care-prd-v2.docx), [기능명세 v2](./baby-care-functional-spec-v2.docx), [개발계약 v1.0.0](./개발계약.md), [OpenAPI 계약](./openapi계약.json), [목 응답·시험 사용자 배치](./목%20응답과%20시험%20사용자%20배치.json)  

보안 참고: [보안 설계 v1.1](./보안/보안%20설계서.md), [A·B 보안 작업 연결표](./보안/AB%20보안%20작업%20연결표.md), [62개 보안 시험표](./보안/62개%20보안%20시험표.md)

이 문서는 구현 체크리스트다. 제품 범위는 PRD v2, 기능 동작과 인수 조건은 기능명세 v2, 웹 연동 필드·상태·HTTP 오류·권한의 구체값은 개발계약 v1.0.0과 OpenAPI 계약을 따른다. A는 화면, 브라우저 오디오, 상태 표현, 웹 통합 시험을 주도한다. 권한의 최종 판정이나 모델 결과의 생성은 브라우저에서 하지 않는다. 계약 간 충돌이 보이면 A가 임의로 정하지 않고 B와 변경을 합의한다.

## 윤정님께 전달 — 이번에 달라진 점

기존에 나눈 **A는 웹·브라우저, B는 API·데이터·ML**이라는 역할은 그대로입니다. 세 대화에서 구체화한 상담·캐릭터·보안을 실행 항목으로 넣었습니다. A가 LLM 호출이나 서버 권한 검사까지 맡는 방식으로 역할을 넓힌 것은 아닙니다.

| 변경 사항 | 이전 문서와 달라진 점·이유 | 윤정님이 추가로 할 일 | B가 먼저 제공하거나 함께 확인할 것 |
| --- | --- | --- | --- |
| 개인화 상담 추가 | LLM의 역할이 기록 정규화에서 아기 기록을 참고하는 대화로 확장됨 | **A-13**: 개인 채팅, 답변 근거, 대화 속 기록 확인 카드, 개인 기억 관리, 중단·복구 화면 | **B-14**: 상담 계약·목 응답, 기록 검색, 답변/근거, 권한·삭제·외부 전송 조건 |
| 캐릭터 제작 구체화 | A-07의 상태 그래픽만으로는 원본 제작부터 실제 모션 연결까지의 순서가 부족했음 | **A-12**: 부모·아기 시안 → 부위별 원본 → 한 장면 → 웹 재생 → 실제 기록 연결 | **B-06·B-07**: 분석 후보와 확인 행동·관찰을 구분한 실제 데이터·ID·버전 |
| 표현의 의미 분리 | 분석 후보·돌봄 행동·관찰 반응을 한 표정으로 표현하면 추정을 사실로 오해할 수 있음 | 분석은 ‘가능성’ 문구/아이콘, 부모 행동은 확인 저장 후 1회, 아기 표정은 확인 관찰에 연결 | 상태 매핑·관찰 시각·출처·삭제 후 유효성. 수유 저장만으로 진정 표정을 만들지 않음 |
| 보안 책임 구체화 | 포괄적인 권한·캐시 항목을 실제 노출·실패 상황과 담당자로 나눔 | 전환·권한 회수 때 요청/캐시/재생 정리, 안전한 텍스트 표시, 마이크 중단, 브라우저 증거 확인 | B가 API·DB·Storage·세션 회수·삭제를 강제하고 서버 시험 증거 제공 |
| ‘착수 조건’ 표현 수정 | 실제 자료·외부 LLM·Realtime 활성화 조건 때문에 모든 개발이 멈추는 오해를 줄임 | 합성 자료·목 화면은 진행. 토큰 보관 방식은 브라우저 결정으로 분리 | 새 재인증·아동 처리·초안 만료 계약은 B가 보완. 기존 `normalizer_available`은 의미부터 확인 |
| 공동 변경 전달 | Realtime 회수가 검증되기 전 사용할 경로를 분명히 함 | **A-08**: 전경 5초 조회, 숨김 중지, 복귀 즉시 조회, 실제 지연 측정 | **B-09**: 기존 `/changes` 제공, SEC30~31 통과 시에만 Realtime 활성화 |
| 완료 판정 보강 | 설계·목 화면·실제 시험을 같은 완료로 취급하지 않도록 정리 | 기존 AC/SEC와 새 CHAT/CHAR 시험의 실제 결과를 분리해 확인 | B는 서버 결과, A는 화면/기기 결과를 확인. 기존 P0·첫 통합 시연 조건 유지 |

먼저 A-01의 남은 화면 작업과 A-02 기기 선검증을 이어갈 수 있습니다. A-12는 합성 장면으로 시작할 수 있고, A-13은 B-14와 필요한 화면·근거·오류 상태를 맞추며 준비합니다. 상담 API 경로, 신규 보안 오류, 보관 기간을 화면에서 먼저 임의로 확정하지 않습니다.

**문서 상태도 함께 정리했습니다.** 전달받은 원본보다 최신인 저장소의 계약·보안 연결 내용과 A-01 ① 완료 기록을 보존했습니다. 새 상담·캐릭터·보안 작업은 모두 미완료이며, 이번 수정으로 기존 코드나 실기기 시험을 다시 검증한 것은 아닙니다. 파일명은 기존 연결을 위해 `v2`를 유지하고 업무 분담 개정만 v2.1로 표시했습니다.

## 이번 개정의 범위와 역할 연결

업무 분담의 개정 번호 v2.1과 API 계약 버전 1.0.0은 별개다. 이번에는 **실행할 일·전달물·완료 기준을 갱신**한다. 상담 API, 보안의 신규 상태·오류, 캐릭터 자산이 이미 구현되었다는 뜻은 아니다. 기존 A-01~A-11과 완료 기록은 유지하고 캐릭터 제작 A-12, 개인화 상담 A-13을 추가한다. B의 상세 업무는 [B 실행 태스크](./baby-care-implementation-tasks-B-v2.md)를 따른다.

| 반영 영역 | A가 맡을 일 | B에게 받을 것 | 범위 |
| --- | --- | --- | --- |
| 개인화 상담 | A-13: 아기별 개인 채팅·근거 보기·기록 확인·개인 기억 관리 | B-14: 권한 있는 기록 조회·대화 API·답변 근거·복구/삭제 계약 | 이번에 추가한 개발 작업. 기존 첫 통합 시연과 별도 인수 |
| 부모·아기 캐릭터 | A-07의 상태 그래픽을 유지하고 A-12에서 캐릭터 원본·모션·플레이어 제작 | B-06·B-07: 분석 후보, 확인된 행동·관찰, ID·버전·시각·출처 | F18 기본 표현은 기존 P0. 상세 모션의 완료 여부는 별도 기록 |
| 보안 | A-01~A-11·A-13의 브라우저 노출·전환·안내·복구 검증 | B-01~B-13·B-14: 서버 권한·외부 전송·수명·삭제 강제 | 기존 계약의 보호 규칙과 새 계약이 필요한 제안을 구분 |

현재 OpenAPI에는 상담 경로가 없다. A-13·B-14에서 팀 계약·OpenAPI·목 응답·화면 매핑·관련 인수 조건을 함께 확장하는 작업을 먼저 한다. 그전에도 합성 자료로 화면 시안을 만들 수 있으나 이를 확정 API 연동이나 기능 완료로 표시하지 않는다. 기존 P0와 AC01~AC44 및 첫 통합 시연 목표는 바꾸지 않는다.

업무 기준은 [A 실행 태스크 기준본](./baby-care-implementation-tasks-A-v2.md)에 두고, 이름으로 된 전달본은 같은 내용을 유지한다. 이후 변경은 기준본에 먼저 반영한 뒤 전달본을 맞춘다.

## 담당 표시와 완료 원칙

- **[Codex]**: 저장소에서 코드·테스트·목 응답·문서를 작성하고 빌드/자동 검증까지 맡길 일.
- **[직접]**: B와의 합의, 제품·안전 문구 판단, 본인 계정/기기에서의 실제 시험, 서비스 설정·비밀값 관리처럼 A가 책임질 일. 계약 초안·자료 조사·시험 자동화는 Codex가 지원할 수 있다. 이미 승인된 범위에 새로운 승인 절차를 만드는 표시는 아니다.
- **[Codex → 직접 확인]**: Codex가 먼저 구현하고 A가 실제 흐름·권한·표현을 확인한 뒤 완료할 일. 코드가 작성되었다는 이유만으로 체크하지 않는다.

Codex에게 맡길 때는 아래의 **한 번에 맡길 범위**처럼 작은 단위로 나누는 것을 권한다. 기존 P0 계약은 확정됐지만 신규 상담·보안 확장 계약과 실제 서버·계정 검증은 별도 작업이다. 기존 계약으로 만들 수 있는 화면은 먼저 진행하고, 새 서버 기능은 B가 계약과 목 응답을 마련하면 연결한다. 각 구현 요청에는 관련 인수 조건, 완료 기준, 필요한 검증, 변경 파일과 남은 위험 보고를 포함한다. 이 문서의 구현 요청 예시는 이번 문서 수정 요청을 코드 작성·배포 지시로 확대하지 않는다.

보안 설계 v1.1은 구현 전 검토와 시험 계획이다. **SEC01~SEC62는 모두 미실행**이며, 설계서의 추가 제안은 개발계약·OpenAPI의 확정 사항으로 간주하지 않는다. A는 이미 합의한 보안 기본값을 구현하고, 새 서버 기능이나 상태값이 필요한 항목은 B와 계약을 보완한 뒤 연결한다.

## 시작 전 계약 — 확정된 결정과 남은 확인

- [x] **[직접·계약 확정]** 아기당 OWNER 1명, CAREGIVER 권한, 탭별 `baby_id` 선택, 초대·탈퇴·삭제 흐름을 개발계약 2·3·10장으로 확정했다. 실계정 권한 시험은 아직이다.
- [x] **[직접·계약 확정]** 상태·필드·401/403/404/409/410 등 오류 코드·UUID 중복 방지 키를 OpenAPI 계약으로 확정했다. 성공/오류 분기는 서버 `code`를 기준으로 한다.
- [x] **[직접·계약 확정]** 브라우저 직접 연결은 Supabase Auth·등록된 private Storage 업로드·비공개 Realtime 신호로 한정했다. P0 업무 테이블의 Supabase Data API·RPC 직접 호출 목록은 비어 있고, 업무 데이터 조회·변경은 FastAPI를 통한다.
- [x] **[직접·계약 확정]** 목 응답과 시험 사용자 별칭을 받았고 `inference_mode=REAL|STUB`, `data_origin=USER|DEMO`의 두 출처 축을 분리하기로 했다. 목은 가상 데이터이며 실제 모델·계정 실행의 증거가 아니다.
- [x] **[직접·계약 확인]** 제공된 [정적 검증 결과](../contracts/validation.json)는 OpenAPI 54개 경로·63개 작업·117개 스키마와 목 시나리오 46개 검증 통과를 보고한다. 실제 FastAPI·RLS/Storage·OTP 계정·모델·브라우저 E2E는 검증 대상에 남아 있다.
- [ ] **[Codex → 직접 확인]** 확정된 경계대로 프런트엔드를 구현한다. 공개 환경값에는 Supabase URL·publishable key·FastAPI 주소만 두고 `service_role`/secret·LLM·DB 자격증명을 넣지 않으며, A가 번들·환경값을 확인한다.
- [ ] **[Codex → 직접 확인]** 제공된 목 응답을 같은 API 클라이언트에 연결하고, 개발 설정에서만 목을 켠다. 실제 API 장애 시 목으로 자동 전환하지 않으며 A가 시연 출처 표시를 확인한다.
- [ ] **[직접]** B에게 개발 FastAPI 주소, `owner_a`·`caregiver_a`·`owner_b`·`invited_a`·`removed_a`에 대응하는 실제 Supabase 시험 계정의 로그인 방법·역할 배치, Storage/Realtime 시험 환경을 받아 연동 시험을 예약한다. 제공된 이메일은 `.invalid` 예시이며 실제 계정이 아니다.

파일명 주의: 개발계약 본문과 생성·검증 스크립트의 `openapi.json`·`fixtures.json`은 원래 산출물 이름이다. A가 참조할 현재 기준 파일은 저장소 `contracts/`의 `openapi계약.json`과 `목 응답과 시험 사용자 배치.json`이다. 스크립트를 그대로 다시 실행하기 전에 입출력 경로를 확인한다.

## 보안 계약 확정 및 실제 데이터·기능 활성화 조건

이 조건은 해당 기능의 실사용 활성화 조건이다. 계약 초안, 목 화면, 합성 자료 개발과 시험 준비는 계속할 수 있다.

- [ ] **[직접·B-01 연계]** 최근 재인증 challenge/`REAUTH_REQUIRED`, 서버 세션 회수, 아동 정보 처리 확인, 미확인 초안 수명·만료 응답의 서버 계약과 화면 분기를 맞춘다. 새 경로·필드·오류는 현재 계약에 있는 것으로 가정하지 않는다. 초안 최대 7일·재인증 시간·토큰 수명은 보안 문서의 제안값이며 확정할 값과 구분한다.
- [ ] **[직접]** 브라우저 토큰 보관 방식은 별도 구현 결정으로 정한다. 탭 세션 저장 방식은 후보이며, 갱신·새로고침·다중 탭·XSS 노출을 시험한다. 탭 세션이라는 이유만으로 새 API나 안전한 비밀 저장소라고 설명하지 않는다.

## A-12. 아기·양육자 캐릭터 제작과 애니메이션

## A-13. 아기 기록을 활용하는 개인화 상담 화면

선행: B-14가 상담 계약·목 응답·안전/외부 전송 조건을 제공한다. 그전에는 합성 대화 시안을 만들고, 새 경로·상태값을 현재 OpenAPI에 있는 것처럼 구현하지 않는다.

- [ ] **[Codex → 직접 확인]** 현재 아기와 본인 전용 대화임을 분명히 표시하고 아기별 대화 목록·새 대화·이어보기·삭제를 만든다. OWNER도 다른 보호자의 상담을 볼 수 없으며 공동 돌봄 기록과 개인 대화 화면을 구분한다.
- [ ] **[Codex → 직접 확인]** 입력·응답 대기·완료·중단·복구·실패·한도 초과·외부 상담 비활성·기록 부족을 구별한다. B가 정한 동일 메시지·실행 식별자로 상태를 조회해 응답 유실을 복구한다. 중단 버튼은 서버 취소 확인과 연결하며 화면 정지만으로 호출·저장·비용까지 취소됐다고 표시하지 않는다.
- [ ] **[Codex → 직접 확인]** 답변의 근거 기록·관찰 시각·조회 기간과 일반 정보의 출처·검토일을 보여준다. 현재 권한으로 원본을 조회하고 수정·삭제된 근거는 오래된 인용으로 열지 않는다. 기록 부족은 추가 질문·한계 표시로 처리하며 과거 행동 뒤의 반응을 효과의 입증으로 단정하지 않는다.
- [ ] **[Codex → 직접 확인]** 대화에서 추출한 행동·상태·반응 후보는 A-07의 확인 카드로 연결한다. ‘분유 먹였어’는 수행 후보, ‘먹일까?’는 계획/질문으로 구분하고, 수정·확인 후 기존 기록 API로 한 번만 저장한다. 일반 대화마다 확인을 요구하거나 상담 답변을 수행 라벨로 자동 저장하지 않는다.
- [ ] **[Codex → 직접 확인]** 최근 대화와 사용자 저장 선호/기억을 구분해 보여주고 본인이 저장·수정·삭제하도록 한다. 대화 삭제·기억 삭제·공동 기록 삭제의 범위를 안내한다. 상담과 개인 기억을 자동으로 다른 보호자에게 공유하거나 학습 동의로 간주하지 않는다.
- [ ] **[Codex → 직접 확인]** 정규화보다 넓어진 전송 범위인 질문·관련 과거 기록·대화 맥락을 목적·보관 안내와 연결한다. B의 상담 허용 조건이 충족되지 않으면 실제 전송은 비활성화하고 기존 기록 입력 경로는 유지한다.
- [ ] **[Codex → 직접 확인]** 아기/계정 전환·권한 회수 때 요청·표시·캐시·미전송 텍스트를 정리하고 늦은 답변을 버린다. 미전송 질문은 자동 공유 기록으로 저장하지 않는다. 개인 대화 초안 저장을 제공하려면 B-14에 수명·권한을 별도로 정의한다.
- [ ] **[Codex → 직접 확인]** 답변은 안전한 텍스트로 표시하고 모델이 낸 HTML·외부 이미지·임의 링크를 실행하지 않는다. 검수된 도움 안내가 필요한 응답은 일반 대화와 구분해 표시하고, 확신형 진단·치료 약속이나 챗봇의 실시간 감시를 암시하지 않는다.

전달물: 상담 화면·기록 확인 카드·근거/기억 관리·실패/전환 복구 화면과 검증 기록. 완료 기준: ‘과거 기록 질문 → 근거 확인 → 대화 이어가기 → 실제 행동 초안 확인 저장’이 이어지고, 타 보호자·타 아기 자료와 삭제된 근거가 노출되지 않는다. 아래 CHAT 인수 조건과 B-14를 함께 통과해야 실제 상담 완료로 표시한다.

첫 요청 예시: “PRD v2·기능명세 v2·`contracts/개발계약.md`·`contracts/openapi계약.json`·`contracts/목 응답과 시험 사용자 배치.json`과 `docs/security/`의 설계·연결·시험표를 기준으로 **A-01의 ①만** 구현해 줘. 보안 문서의 새 API 제안은 아직 확정 계약이 아니니 경로·오류를 지어내지 마. 실제 API·시험 계정은 준비됐다고 가정하지 말고 제공된 계약과 합성 fixture를 사용해. 관련 자동 테스트와 빌드를 실행하고 변경 파일·검증 결과·SEC09/34/51/57/58에서 내가 확인할 항목을 보고해 줘. A-01의 ②와 배포는 이번 요청에서 하지 마.”

보안 보강은 위의 관련 기능 요청 안에서 하나씩 처리한다. A-01의 ①에는 공개/비공개 데이터 경계와 영구 캐시 금지를 포함하고, A-03의 ②에는 초대 토큰·전환 안전성을, A-05의 ②에는 TUS·재생 URL 안전성을, A-11의 ②에는 CSP·preview/증거 점검을 포함한다. 범위가 커지면 다음 번호를 합치지 말고 **같은 번호의 보안 보강을 별도 요청**으로 나눈다.

## 보안 시험과 완료 판정

- A 단독 주관: **SEC32, SEC34, SEC57, SEC58, SEC60**. 아기/계정 전환 격리, 텍스트 주입·CSP, Next.js 응답·캐시, 오프라인 재전송, 운영 빌드의 마이크/WASM 호환성을 실제로 확인한다.
- A+B 공동: **SEC05, SEC07, SEC14, SEC16, SEC17, SEC19, SEC21, SEC24, SEC28, SEC33, SEC38, SEC44, SEC48, SEC51, SEC56, SEC59, SEC61, SEC62**. B의 서버·Storage·권한 결과와 A의 화면·브라우저 결과를 같은 시나리오로 대조한다.
- 나머지 보안 시험은 B 또는 운영 책임자가 주관하더라도 A-03~A-11의 실제 인수에 영향을 주면 결과를 확인한다. [A·B 연결표](./security/AB%20보안%20작업%20연결표.md)의 작업별 대표 SEC 번호와 [62개 시험표](./security/62개%20보안%20시험표.md)의 기대값을 사용한다. **현재 62개 모두 미실행**이다.

## 첫 통합 시연 목표

A-03~A-08을 B의 대응 작업과 합쳐 **두 보호자 로그인 → 녹음 → 실제 분석 또는 정직한 유보 → 행동·상태 확인 기록 → 다른 보호자 화면 반영**을 먼저 완주한다. 제공 fixture나 STUB으로 확인한 흐름은 개발 연결 확인일 뿐, 실제 분석을 포함한 통합 시연 완료가 아니다. 활성 감지·요약·학습 후보는 이후에도 P0 완료 전까지 구현·검증해야 한다.

권장 진행: 기존 첫 통합 시연 → 전체 P0 인수 → 추가 상담·상세 모션 통합 인수. A-12 자산 제작과 A-13/B-14 계약·합성 시안은 앞 단계와 나란히 준비할 수 있다. 상담 API나 정교한 캐릭터 제작을 기존 첫 시연의 새 선행 조건으로 만들지 않는다.

## 추가 기능의 공동 인수 조건

아래 ID는 이번 업무 분담의 시험 계획이며 기존 AC·SEC 번호나 API enum을 바꾸지 않는다. 모두 미실행이다. B 문서에도 같은 기대값을 싣고, A는 화면·브라우저 증거를, B는 권한·저장·조회·외부 호출 증거를 맡는다.

| CHAT01 | 다른 아기·다른 보호자 대화/기억/인용/도구 인자를 요청해도 자료가 노출되지 않고 OWNER 예외가 없음 | B, A 화면 확인 |
| CHAT02 | 기록 부족·수정·삭제·권한 회수 후 새 답변과 저장된 답변·요약·기억·인용이 오래된 근거를 재노출하지 않음 | B+A |
