# 아기 울음 육아 도우미 기능명세서

> 이전 버전 보관본입니다. 현재 제품·API 기준은 [문서 안내](../../README.md)의 v2 문서와 계약을 따릅니다. 본문은 당시 기획을 보존하며 현재 구현 상태를 뜻하지 않습니다.

버전 1.1 · 2026년 9월 16일 · PRD 버전 1.1 대응

이 문서는 개발자가 해커톤 시제품을 구현하고 QA가 완료 여부를 확인하는 기준이다. 사용자 입력, 화면 동작, 상태 전이, 기록의 접근 권한과 작성자, API와 오류 처리를 정의한다. P0 기능은 실제 입력부터 다음 기록 활용까지 연결한다. 아직 학습하지 않은 모델이나 가상 시연 자료는 실제 분석 결과와 구분한다.

수치가 명시된 제한과 임계값은 첫 구현을 위한 운영 기본안이다. 의료 기준이나 모델 성능 보장이 아니다. 배포 설정과 모델 검증 결과에 따라 버전을 올려 변경한다.

### 이번 개정의 추가 범위

선택지·자연어를 함께 쓰는 행동 및 상태 입력, LLM 라벨 정규화와 확인, 상태 그래픽, 학습 후보 내보내기, 공동양육자 계정 연동을 P0에 포함한다. F17~F20과 SC09~SC10을 추가하며 옹알이 등 다양한 발성의 자동 기분 추론은 E04로 둔다.

## 1 범위와 공통 용어

### 사용자와 권한

P0는 아기별 관리 보호자 OWNER 1명과 공동양육자 CAREGIVER를 지원한다. 각자는 별도 계정으로 로그인하며 BabyMembership의 ACTIVE 참여 관계로 같은 아기의 기록을 공유한다. 계정당 직접 생성 아기 1명, 초대받은 아기 추가 참여와 활성 아기 선택을 지원한다. 엄마·아빠·조부모·기타는 표시용 관계이며 권한을 결정하지 않는다. 운영자는 배포와 익명화된 오류 지표를 관리하며, 별도 권한 없이 보호자 오디오와 기록을 열람하는 관리 화면을 만들지 않는다.

| 용어 | 의미 | 혼동하면 안 되는 값 |
|---|---|---|
| 울음 사건 | 시간상 이어지는 하나의 울음 묶음 | 잘린 음원 조각 수 |

| 맥락 스냅샷 | 분석 당시 알려진 생활 기록의 고정 사본 | 현재 수정된 최신 기록 |

### 공통 데이터 원칙

모든 시간은 서버에서 UTC로 저장하고 표시할 때 아기 설정의 시간대로 변환한다. 실제 발생 시각 occurred_at, 시스템 수신 시각 recorded_at, 수정 시각 updated_at을 분리한다. 과거 기록은 입력할 수 있으며 서버 시각보다 5분을 초과한 미래 시각은 저장하지 않고 기기 시각 확인을 안내한다. 모르는 시각이나 수량은 null이며 0으로 바꾸지 않는다.

쓰기 요청은 client_request_id로 중복을 방지한다. 수정은 version을 비교한다. 서버가 저장 완료를 확인한 뒤 ‘저장했어요’를 표시한다. 접속이 끊긴 입력은 현재 화면의 미저장 초안으로 남기며 P0에서 백그라운드 자동 동기화를 약속하지 않는다.

결과의 추천 버튼과 ‘다른 행동을 했어요’는 같은 행동 입력 흐름을 연다. 기록 폼은 필수 항목을 먼저 보여주고 양, 메모 등의 상세 항목은 펼쳐 입력한다. 사건 없이 만든 기록도 이후 동일 아기의 사건에 연결할 수 있다.

### 공통 화면 상태

- 로딩: 무엇을 불러오는지 설명하고 중복 실행 버튼을 막는다.
- 빈 화면: ‘기록이 없어요’와 첫 입력 버튼을 제공한다. 통계 0과 기록 없음은 다르다.
- 오류: 실패한 작업, 저장 여부, 가능한 복구 행동을 한 문장씩 표시한다.
- 미저장: 초안을 유지하고 나가려는 경우에만 버림 여부를 확인한다.
- 접근성: 핵심 조작 영역 44px 이상을 목표로 하고 키보드 초점, 폼 이름, 오류 연결, 상태 알림을 제공한다. 색상만으로 감지 및 저장 상태를 구별하지 않는다.

## 3 기능별 상세 동작

### F01 로그인과 아기 설정

연결 요구사항 R01 · P0 · 화면 SC01 SC08

입력은 이메일과 로그인용 일회용 코드, 아기 별칭, 생년월일, 수유 방식, 시간대다. Supabase 이메일 OTP 한 가지 방식으로 시작한다. 코드 발송과 검증의 제한 및 만료는 인증 제공자 설정을 따른다. 실제 발송 도메인과 재전송 제한을 시연 전에 검증한다.

인증 후 ACTIVE 참여 아기 목록을 조회하고 계정별 마지막 활성 아기를 복원한다. 참여 아기가 없으면 만들기 또는 초대 참여를 제공한다. 별칭은 필수이며 생년월일은 미래일을 허용하지 않는다. 수유 방식은 모유, 분유, 혼합, 미설정이다. 지원 월령 밖이면 기록은 허용하고 원인 분류 지원 범위를 안내한다. 프로필 공통 값은 OWNER만 변경한다.

활성 아기를 바꾸면 감지 세션을 종료하고 baby_id별 캐시와 초안을 분리한다. 진행 중 분석은 원래 아기에 연결된 채 완료된다. 이전 아기의 수유 맥락이나 음원을 새 아기에게 붙이지 않는다. 새 아기를 만들 때 Baby와 OWNER 멤버십을 한 트랜잭션으로 생성한다.

코드 만료, 로그인 실패와 네트워크 실패를 구분한다. 로그아웃 시 마이크 트랙, 메모리 음원과 개인 데이터 캐시를 비운다. 세션 만료 후 쓰기는 재로그인을 요구하고 다른 계정으로 초안을 자동 전송하지 않는다.

완료 기준 AC01 AC44: 재로그인 후 참여한 아기와 기록을 조회하고 참여하지 않은 아기는 차단한다. 아기를 전환해도 이전 아기의 기록·분석·초안이 섞이지 않는다.

### F02 동의와 보관 및 삭제

연결 요구사항 R01 R10 · P0 · 화면 SC01 SC08

‘서비스 분석과 기록 처리’, ‘음원 재생을 위한 보관’, ‘공통 모델 개선 참여’를 분리한다. 서비스 처리 안내에는 자연어를 외부 LLM API에 전송해 정리한다는 점을 포함한다. 음원 보관과 학습 참여는 기본 꺼짐이다. 마이크 권한은 브라우저가 관리한다.

OWNER는 아기 단위 서비스·보관·공통 학습 설정을 관리한다. 각 참여자는 공동 기록 범위를 수락하고 본인이 작성한 내용의 공통 학습 참여를 별도로 선택한다. 공동양육 참여나 다른 가족의 동의만으로 본인의 학습 참여를 켜지 않는다. 서비스용 라벨 정리는 학습 참여와 독립적으로 사용할 수 있다.

보관 미동의 음원은 분석 종료 직후 삭제를 요청하고 실패 시 수신 후 최대 1시간 안에 지우는 정리 작업을 둔다. 보관 음원은 기본 7일 후 삭제한다. 학습 후보 연결은 저장할 수 있으나 음원이 삭제되면 오디오 학습 적격 상태를 해제한다. 적격 학습 묶음은 만료 전 별도 권한 아래 생성하고 기본 30일 보관 후 정리한다. 이 기간과 실제 제공자 보관 조건은 참여 안내와 배포 설정에 반영한다.

학습 내보내기에는 아기 설정, 음원 제공자와 포함된 행동·상태·맥락 작성자의 동의가 모두 필요하다. 한 명이라도 미동의이면 해당 조합을 보류한다. 철회 시 이후 수집과 신규 내보내기를 막고 대기 자료, 학습 사본과 파생 특징을 추적해 제거한다. 이미 배포된 공통 가중치가 즉시 되돌려진다고 안내하지 않는다.

전체 아기 데이터 삭제는 OWNER만 확인 후 요청한다. 접근을 차단하고 원시 음원, 원문, 정규화와 라벨, 기록, 특징값, 분석 및 개인화 자료를 정리한다. CAREGIVER의 나가기는 접근 해제이며 기존 공유 기록은 남는다. 본인 작성 자료 삭제는 별도 경로로 요청할 수 있고 이를 학습 정리에도 반영한다.

완료 기준 AC02 AC03 AC37 AC43: 선택 보관·학습 동의 없이 분석과 기록이 가능하다. 비구성원 접근과 해제 후 신규 파일 경로 발급이 차단된다. 철회·삭제가 후보와 내보낸 묶음까지 전파되고 미완료 정리를 완료로 표시하지 않는다.

### F03 직접 녹음과 파일 입력

연결 요구사항 R02 · P0 · 화면 SC03

‘지금 분석’은 권한을 요청한 후 녹음을 시작한다. 유효 입력 경과와 중지 버튼을 보여주고 약 15초를 기본 안내 길이로 둔다. 사용자가 먼저 중지할 수 있다. ‘분석하기’ 전에 해당 아기의 음원인지와 입력 시각을 확인할 수 있게 한다.

브라우저의 실제 입력 샘플을 수집해 길이를 계산한다. 녹음 길이를 단순 타이머나 MediaRecorder 이벤트 도착 간격으로 추정하지 않는다. 기본 녹음 최대 30초, 파일 최대 60초 및 25MB를 적용한다. WAV, MP3, M4A, WebM 중 서버가 디코딩 시험을 통과한 형식만 파일 선택 화면에 안내한다. MIME이나 확장자만 신뢰하지 않고 서버에서 다시 검사한다.

업로드 파일은 녹음 시각을 ‘지금’, ‘직접 선택’, ‘모름’으로 받는다. 시각 모름은 현재 육아 맥락과 자동 결합하지 않으며 오디오 분석과 일반 확인 목록만 제공한다. 녹음된 아기를 알 수 없는 예시 파일은 예시 모드로 처리한다.

파일은 API에서 발급한 경로로 비공개 저장소에 직접 올린다. 큰 음원을 웹 화면 제공 서버의 함수 본문으로 중계하지 않는다. 업로드 실패 시 현재 화면에 남은 음원으로 재시도할 수 있다. 화면을 닫아 사라진 음원을 복구 가능하다고 표시하지 않는다.

완료 기준 AC04 AC05: 지원한 녹음과 파일은 분석으로 진행한다. 권한 거부, 형식 오류, 길이 및 용량 초과를 구분하고 시각 모름 파일에 현재 수유 맥락을 붙이지 않는다.

### F04 활성 화면 감지 세션

연결 요구사항 R03 · P0 · 화면 SC02 SC03

사용자가 ‘감지 시작’을 누르면 선택 아기, 관찰 기기 배치, 주변 다른 울음 가능성을 확인하고 마이크를 연다. 가능한 경우 Screen Wake Lock을 요청한다. 화면 유지 기능 실패 자체를 마이크 실패로 처리하지 않으며 화면 상태를 확인하도록 안내한다.

### F08 확인 행동 안내

연결 요구사항 R05 · P0 · 화면 SC04

우선 행동 1개와 대안 최대 2개를 제공한다. 규칙 입력은 오디오 후보, 맥락 스냅샷, 보호자 관찰, 이전 사례와 누락 상태다. 출력은 action_type, 설명, evidence_refs, policy_version과 optional_question이다. 맥락과 오디오가 충돌하면 선택 질문 최대 2개를 보여주고 건너뛰기를 허용한다.

P0 규칙은 다음 순서로 적용한다. 보호자가 응급 징후를 선택한 경우 도움 요청 안내를 우선한다. 진행 중인 행동이나 방금 완료한 같은 행동은 즉시 반복 추천하지 않는다. 이후 오디오 지원 후보에 대응하는 확인 목록을 만들고 현재 기록 및 같은 아기 사례로 순서를 조정한다. 부족한 근거는 숨기지 않고 확인 목록을 넓히거나 유보한다.

권장 행동은 ‘수유 필요 신호 살펴보기’, ‘기저귀 상태 확인’, ‘졸림 신호와 주변 환경 확인’, ‘안아서 반응 관찰’ 같은 확인 중심 문구다. 수유량, 약물 용량이나 질병 처치를 자동 결정하지 않는다. 응급 안내 문구는 공식 보건 자료를 바탕으로 검토하고 연락 버튼은 실제 사용자의 지역 설정을 따른다.

추천 선택은 행동 초안을 만들 뿐 수행 완료가 아니다. ‘실제로 했어요’를 저장한 경우에만 행동 기록이 생성된다. 보호자가 추천하지 않은 행동을 기록할 수 있다.

완료 기준 AC12: 기록 수정, 판단 유보와 응급 관찰 상황에서 다른 안내 경로가 작동한다. 추천 클릭만으로 수행 기록이나 성공 라벨이 생기지 않는다.

### F10 대응 행동과 아기 상태 및 반응 입력

연결 요구사항 R07 R14 · P0 · 화면 SC04 SC05 SC06 SC09

대응 행동은 수유, 기저귀 확인·교체, 안기, 트림 돕기, 재우기, 환경 조절, 기타, 아직 행동하지 않음 중 고를 수 있다. 자유 텍스트도 입력할 수 있으며 선택지와 함께 사용할 수 있다. 여러 행동은 순서를 정하고 각각 실제 시각 또는 시각 모름을 기록한다. 아직 행동하지 않았다는 선택은 ActionAttempt를 만들지 않는다.

아기 상태는 우는 중, 칭얼거림, 진정됨, 졸려 보임, 잠듦, 깨어 있음, 즐거워 보임, 모름을 기본 선택지로 둔다. 자연어와 복수 상태 입력을 지원한다. 상태 관찰에는 행동 전·후·관련 없음·모름의 phase와 관찰 시각을 둔다. 잠듦과 즐거워 보임은 서로 다른 차원의 관찰이며 한 가지 원인 라벨로 축약하지 않는다.

행동 후 변화는 진정됨, 일부 진정, 변화 없음, 다시 욺, 확인 못함 중 선택하거나 텍스트로 설명한다. 한 행동 뒤 여러 시점의 반응을 추가할 수 있다. ‘다시 욺’이 앞선 진정을 지우지 않으며 미입력은 성공·실패로 자동 채우지 않는다. 원인 해석은 선택 항목으로 별도 입력하며 관찰을 덮어쓰지 않는다.

원문과 선택값을 먼저 입력 초안으로 저장하고 F17에서 정리한다. 선택지만 사용한 경우 고정 코드와 실제 수행 확인으로 바로 저장할 수 있다. 텍스트가 있으면 정규화 초안을 확인·수정한 다음 ‘이 내용으로 저장’을 누른다. CareEvent, ActionAttempt, StateObservation, Outcome 및 확인 라벨은 한 트랜잭션으로 생성한다. 같은 행동의 기존 care_event_id를 연결하면 일일 집계가 늘지 않는다.

작성자와 실제 행동한 사람은 별도 필드다. 다른 보호자의 행동을 대신 적을 수 있고 직접 보지 않은 설명은 reported_by_other 출처를 표시한다. 같은 아기의 다른 구성원은 후속 관찰을 추가할 수 있으나 기존 작성자의 원문을 자기 기록으로 덮어쓰지 않는다. 다음 진입 시 미확인 반응 질문은 작성자에게 사건당 한 번 보여주고 건너뛰기를 허용한다.

완료 기준 AC15 AC16 AC29: 선택·자연어·혼합 입력에서 복수 행동, 관찰 시점과 아기 상태가 보존된다. 사건 연결로 일일 집계가 중복되지 않는다.

### F11 이전 사례 활용

연결 요구사항 R08 · P0 · 화면 SC04

같은 아기의 삭제되지 않은 과거 사건을 작성자와 관계없이 공유 이력에서 조회한다. 접근은 현재 활성 구성원에게만 허용한다. 현재 사건과 미래 기록, 미확인 결과, 예시 모드와 테스트 자료를 실사용 개인화에서 제외한다. 기본 조회는 최근 30일이며 월령 차이, 시간대와 수유 및 수면 경과, 입력 품질이 비교 가능한 사건을 선택한다. 오디오 특징 유사도는 선택 구현이며 없어도 맥락 사례 조회는 동작한다.

P0는 정의된 규칙으로 유사도를 계산한다. 경과시간 차이와 시간대 차이를 같은 척도로 정규화하고 결측 항목을 일치로 계산하지 않는다. 최소 두 개의 비교 가능한 맥락 필드가 있을 때 후보에 넣고 가까운 5건 이내를 조회한다. 정확한 거리 가중치는 personalization_policy_version에 저장한다. 미확인 LLM 초안과 충돌한 관찰은 순위 조정에 사용하지 않는다. 같은 아기·맥락 버전·정책 버전에 대한 핵심 추천은 구성원에게 동일하게 제공하며 개인 화면에는 본인의 미완료 입력만 별도로 표시한다.

확인된 사례가 3건 미만이면 개인화 순위 조정을 유보한다. 3건 이상이면 사례 수와 관찰된 행동 및 반응을 요약하고 원본 기록으로 이동할 수 있다. 여러 행동을 연속 수행한 사건은 ‘복합 행동 후 관찰’로 표시하고 단일 행동의 효과에 합치지 않는다. 숫자는 규칙 동작을 위한 최소값이며 통계적 신뢰성을 보장하지 않는다.

완료 기준 AC17: 다른 아기와 예시 자료는 섞이지 않으며 기록 삭제 후 다시 조회한 사례에서 제거된다. 0건과 미확인 사례만 있는 경우 근거 없는 개인화 문장을 만들지 않는다.

### F12 오늘의 요약

### F13 기록 기반 준비 알림

연결 요구사항 R09 · P0 · 화면 SC07 SC02

기본은 꺼짐이다. 사용자가 항목별로 켜면 최근 7일의 기록에서 수유 간격 또는 깨어 있는 뒤 잠든 간격을 계산한다. 기저귀는 일정 주기를 자동 추정하지 않고 사용자가 정한 확인 알림만 지원한다. P0 알림 전달은 홈 카드와 활성 화면 안내이며 화면을 닫은 뒤 푸시 전달은 P1이다.

수유는 같은 수유 방식의 연속 기록 간격을 사용한다. 수면 준비는 깨어난 시각과 다음 잠든 시각이 연결된 구간을 사용한다. 사용자가 해당 날짜의 관련 기록을 확인한 경우에만 패턴 계산 후보로 넣는다. 기록 누락 가능성은 남으므로 완전한 실제 행동 이력이라고 표현하지 않는다.

후보 조건은 3일 이상에 걸친 유효 간격 10개 이상이다. 미래값, 음수, 겹침, 미완료와 확인하지 않은 날짜는 제외한다. 중앙값과 25~75백분위 범위를 표시한다. 사분위 범위가 중앙값의 절반보다 크면 변동이 크다고 안내하고 자동 시점 제안을 보류한다. 이는 초기 운영 규칙이며 검증 후 조정한다.

준비 시점은 마지막 관련 행동 종료 또는 시작 기준에 대표 간격을 더한 값으로 계산하되, 수유는 직전 수유 시작, 수면 준비는 직전 깨어남을 기준으로 한다. 기본 10분 전에 안내한다. 미래 시점을 예측된 욕구나 확률로 표시하지 않는다. 충분한 기록이 없으면 이유와 필요한 기록 종류를 보여준다.

같은 기준 기록에 같은 알림은 한 번만 발행한다. 사용자는 10분 미루기, 이번 알림 끄기, 항목 알림 끄기를 선택할 수 있다. 관련 행동 기록이 새로 생기면 기존 알림은 만료한다. 다시 들어왔을 때 지난 알림을 몰아서 보내지 않는다.

완료 기준 AC19 AC20: 기록 부족, 변동 과다, 조건 충족의 세 경로가 작동하고 수정 및 새 행동에 따라 시점이 갱신되며 같은 알림이 중복되지 않는다.

### F14 타임라인 수정과 삭제

연결 요구사항 R06 · P0 · 화면 SC06

실제 발생 시각 순서로 공동 생활 기록과 울음 사건을 표시한다. 작성자와 수정자를 보여주고 삭제·수정 권한은 F20을 따른다. 늦게 입력된 기록은 실제 시점에 배치하고 수정 이력을 표시한다. 사건 상세에서 입력 음원 보관 여부, 분석 버전, 참고 맥락, 추천, 행동과 반응을 볼 수 있다. 시각 모름 파일은 별도 표시하고 최근 기록처럼 끼워 넣지 않는다.

수정 시 현재 version을 전송한다. 서버 버전이 다르면 409를 반환하고 최신 값과 자신의 초안을 비교하도록 한다. 기록 삭제는 연결된 행동 및 개인화에 미치는 영향을 알리고 확인을 받는다. 삭제된 원본 내용은 과거 스냅샷과 파생 자료에서도 제거하거나 비식별 참조로 정리하며, 화면에는 ‘참고 기록 삭제됨’만 표시한다. 감사 목적을 이유로 원문을 영구 보관하지 않는다. 원문 또는 관찰을 수정하면 이전 확인 라벨은 STALE, 학습 후보는 ON_HOLD와 SOURCE_CHANGED 사유로 바꾸고 재확인 전 신규 내보내기를 막는다.

완료 기준 AC21 AC22: 충돌 수정이 다른 값을 조용히 덮어쓰지 않으며 삭제 후 요약, 맥락 재계산, 사례 조회와 음원 재생 권한이 갱신된다.

### F15 모델 버전과 시연 자료

연결 요구사항 R10 · P0 · 화면 SC04 및 내부 운영

모델 등록 정보는 학습 경로, 가중치 해시, 데이터 manifest, 라이선스 확인 상태, 지원 월령 및 라벨, 전처리와 라벨 매핑 버전, 평가 결과 위치다. 서버는 등록된 버전만 사용한다. 학습은 로컬 또는 별도 학습 환경에서 수행하고 서비스 요청으로 실행하지 않는다.

배포할 모델은 최신 M2D 주 경로를 수행했는지 명시한다. BABYCRY 이용 조건 미확인 또는 미학습이면 그 단계를 완료로 표시하지 않는다. 이전 버전 롤백은 이후 요청부터 적용하며 이미 저장된 분석의 버전은 바꾸지 않는다.

완료 기준 AC23: 모델 교체 전후의 결과에서 실제 사용 버전을 조회할 수 있고 STUB 또는 DEMO 자료를 실제 검증 결과로 집계하지 않는다.

### F16 배포와 장애 복구

연결 요구사항 R10 · P0 · 전체 화면 및 운영

웹 화면은 Vercel, 인증 및 기록과 비공개 파일은 Supabase, FastAPI와 추론은 Cloud Run을 기본안으로 한다. CPU와 메모리는 실제 M2D 입력으로 측정해 정한다. 자연어 라벨 정규화는 같은 서버의 별도 API와 LLM 제공자 어댑터에서 수행한다. LLM 장애가 이미 저장한 육아 기록이나 오디오 분석 결과를 지우지 않는다. 서비스 시작 시 가중치를 준비하고 readiness 검사에서 모델 및 전처리 버전을 확인한다. 시연 전에 예열한다.

P0 추론은 요청 처리 안에서 실행하고 결과를 저장한 뒤 응답한다. 분석 작업 행을 DB에 먼저 만들고 실행 잠금을 획득한다. 서비스 프로세스가 중단되면 상태 조회가 만료된 실행을 FAILED로 바꾸며 사용자가 재시도할 수 있다. 응답 후 메모리 안에서만 돌리는 작업은 쓰지 않는다. 대기열이 필요한 규모나 장시간 추론은 후속 내구성 작업 큐 전환 조건이다.

쓰기 실패는 성공으로 표시하지 않는다. 권한 오류는 재시도 횟수로 해결하지 않는다. 재시도는 같은 요청 식별자로 중복 저장을 막고, 새 분석을 의도한 경우에만 새 요청 식별자를 만든다. 배포 화면에는 일시적 서버 장애와 마이크 감지 중단을 서로 구별해 표시한다.

완료 기준 AC24 AC25: 응답 유실 뒤 결과 재조회가 가능하고 실행 중 서버 중단은 영구 처리 중으로 남지 않는다. 이전 모델 및 서비스 버전으로 복구하는 리허설을 통과한다.

### F17 LLM 정규화와 라벨 확인

연결 요구사항 R14 · P0 · 화면 SC05 SC09

입력은 input_mode=CHOICE 또는 TEXT 또는 MIXED, 선택 코드, raw_text, 입력 시각, 사용자가 지정한 실제 시각, baby_id와 선택 episode_id다. raw_text는 초기 2000자 이하로 제한한다. 마이크로 말한 내용을 문자로 바꾸는 기능은 P1이며 이번 자연어 입력은 키보드 텍스트다.

선택값은 고정 코드로 매핑한다. 텍스트가 있으면 NormalizerAdapter가 LLM API를 호출한다. 최소 입력과 허용 라벨 사전, 시각 기준만 전달하고 아기 프로필·연락처·전체 기록·원시 음원을 별도로 붙여 보내지 않는다. 보호자가 원문에 직접 적은 정보는 전송될 수 있음을 입력 안내와 서비스 처리 설명에 반영한다. 원인 후보와 추천도 추출 힌트로 전달하지 않는다. 사용자 텍스트는 데이터로 취급하며 그 안의 지시를 실행하거나 다른 도구를 호출하지 않는다.

출력은 actions, states, outcomes, caregiver_interpretations와 unresolved 배열이다. 각 항목은 표준 코드, 수행 여부 또는 관찰 여부, 순서, 값과 단위, 시각 및 정확도, 원문 근거, 입력 출처를 가진다. actions는 PERFORMED, PLANNED, NEGATED, UNCERTAIN을 구분한다. ‘먹일까 해요’와 ‘먹이지 않았어요’는 수행 기록을 만들지 않는다. ‘조금’, ‘아까’는 임의 수치나 정확한 시각으로 채우지 않는다.

서버는 JSON 스키마와 허용 코드, 수치·시각, 원문 근거의 실제 존재를 검사한다. 근거는 선택 항목 ID 또는 원문 인용 구간과 시작·끝 위치다. 위치는 정규화 전 원문의 Unicode 코드포인트 기준이며 해당 부분 문자열과 일치해야 한다. 없는 원인, 수량, 사람을 보충한 결과는 확인 필요 또는 실패로 처리한다. LLM이 출력한 자체 확신 점수로 정답이나 학습 적격을 자동 판정하지 않는다.

선택값과 텍스트가 충돌하면 어느 한쪽을 조용히 우선하지 않는다. 충돌 필드를 표시해 선택하게 하며 나머지는 보존한다. 여러 행동 뒤의 반응은 행동 묶음과 연결하고 원문이 특정 행동을 지목하지 않으면 단일 행동 효과로 배정하지 않는다. 선택·LLM 추출·사용자 수정 출처를 필드별로 기록한다.

SC09는 원문, 정리한 행동 순서, 상태·반응, 모르는 항목과 상태 미리보기를 보여준다. 보호자가 수정하거나 ‘이 내용으로 저장’하면 USER_CONFIRMED 또는 USER_CORRECTED 라벨이 된다. 의미를 결정하지 못하면 UNKNOWN 또는 OTHER로 확인하거나 나중에 확인할 수 있다. 확인은 보호자의 보고 내용에 대한 확인이며 객관적 원인 검증을 뜻하지 않는다.

RawCareEntry를 먼저 DB에 저장하고 NormalizationRun을 별도로 만든다. 한 요청 안에서 최대 20초 처리하고 lease 30초를 둔다. 클라이언트가 run_id를 먼저 만들어 응답 유실 후 조회한다. 시간 초과·한도·스키마 오류는 원문을 보존하고 선택지로 직접 정리하거나 명시적으로 재시도한다. 같은 입력 버전·사전·프롬프트·제공자 모델 조합의 성공 결과는 재사용한다. 원문 수정 뒤 도착한 오래된 결과는 적용하지 않는다.

완료 기준 AC29~AC33: 복합·부정·계획·불명확 시각·선택 충돌·LLM 장애·응답 유실을 처리하고 확인 전 후보가 확정 라벨이나 실제 수행 기록으로 섞이지 않는다.

### F18 아기 상태 그래픽과 애니메이션

연결 요구사항 R15 · P0 · 화면 SC02 SC04 SC05 SC06 SC09

상태별로 준비한 캐릭터 그래픽과 짧은 전환 애니메이션을 매핑한다. P0는 입력 때마다 새로운 이미지를 생성하지 않고 일관된 사전 제작 자산을 선택한다. 표시값은 visual_state_code와 visual_mapping_version이며 원인 후보 점수로 표정을 바꾸지 않는다.

| 입력 상태 | 시각 표현 | 함께 표시할 문구 |
|---|---|---|
| 우는 중 또는 칭얼거림 | 눈물 또는 불편한 표정의 짧은 전환 | 보호자가 기록한 상태와 시각 |
| 진정됨 | 편안한 표정으로 부드럽게 전환 | 진정됨으로 기록 |
| 졸려 보임 또는 잠듦 | 느린 눈깜박임 또는 감은 눈 | 졸려 보임과 잠듦을 구분 |
| 깨어 있음 또는 즐거워 보임 | 열린 눈 또는 미소 | 관찰한 상태로 기록 |

선택 입력은 즉시 미리보기를 바꾼다. 자연어는 검증된 초안이 도착한 뒤 ‘확인 전 미리보기’로 표시한다. 저장된 홈과 타임라인에는 확인한 관찰만 반영하고 ‘마지막 기록된 상태’, 관찰 시각과 작성자를 보여준다. 과거 기록을 현재 상태처럼 표시하지 않는다. 30분을 넘긴 홈 상태는 초기 정책상 정지 그림과 경과시간을 강조한다.

서로 배타적인 상태가 같은 관찰 시각에 있거나 순서를 모르면 중립 그림과 상태 목록을 보여준다. 관찰 시각이 명확히 다른 경우 마지막 확인 상태를 표시하고 이전 상태는 이력에 남긴다. 색이나 움직임 외에 텍스트와 접근 가능한 이름을 제공한다. 동작 줄이기 설정에서는 정지 그림을 사용하고 자동 소리·반복 점멸·무한 움직임을 넣지 않는다. 자산 로드 실패에도 상태 텍스트는 남는다.

완료 기준 AC34 AC35: 선택·초안·확인·수정·혼합·과거·모름 상태가 구별되고 움직임을 꺼도 정보를 이해할 수 있다.

### F19 학습 후보 구성과 검수 및 내보내기

연결 요구사항 R14 R10 · P0 · 내부 검수 및 SC08 참여 설정

확인된 라벨을 음원, 울음 사건, 분석 당시 맥락, 실제 행동과 상태·반응에 연결해 TrainingCandidate를 만든다. 입력 확인과 공통 학습 적격은 별도 상태다. 후보는 PENDING_REVIEW, ELIGIBLE, ON_HOLD, EXCLUDED 중 하나와 이유를 가진다. 음원 없는 기록은 생활 안내 개선용 후보로 남길 수 있으나 오디오 원인 분류 자료로 내보내지 않는다.

표준 작업 구분은 ACTION_RESPONSE, STATE_OBSERVATION, CAUSE_WEAK이다. ‘수유 뒤 잠듦’은 앞의 두 작업에 쓸 관찰이며 hungry 정답으로 자동 변환하지 않는다. CAUSE_WEAK는 보호자가 원인을 명시한 경우에만 후보가 되며 약한 라벨 출처를 유지하고 별도 검수 없이는 원인 분류 학습에 투입하지 않는다. 여러 행동의 복합 효과는 multi_action 표시를 유지한다.

적격 검사는 활성 학습 동의, 포함 자료 작성자의 참여, 원문과 라벨 버전 일치, 음원 이용 조건·품질·시각 연결, 확인 상태, DEMO/STUB 배제와 미해결 충돌을 포함한다. 원문과 사건 이후의 상태를 최초 울음 원인 예측 입력에 넣지 않는다. 당시 알려진 맥락만 features로 쓰고 이후 행동·반응은 targets와 후속 관찰 영역에 둔다.

공동양육자는 자기 아기의 기록을 보는 권한만으로 다른 가정의 학습 자료를 열 수 없다. P0 내보내기는 별도 TRAINING_CURATOR 권한의 내부 명령 또는 API로 수행한다. 사람 검수의 승인·보류 이유와 검수자를 남긴다. 묶음은 JSONL과 manifest로 생성하며 task, source IDs와 버전, label provenance, 모델·프롬프트·사전 버전, 동의 참조, 분할 그룹, 체크섬을 포함한다. 계정 이메일과 초대 정보는 제외하고 baby_id는 안정적인 학습용 가명 그룹으로 바꾼다. 원문과 인용 구간, 자유 메모 및 사람 이름은 기본 내보내기에서 제외한다. 내보내는 출처 정보는 원본 ID·버전·선택 코드와 검수 상태로 제한한다.

오디오가 필요한 묶음은 원시 음원의 보관 만료 전에 허용된 학습용 private 경로로 복사하고 기본 30일 만료를 붙인다. 임의 외부 URL이나 공개 링크를 담지 않는다. 음원·후보·내보내기·학습 실행의 계보를 저장한다. 원문 수정, 자료 삭제 또는 동의 철회 시 관련 묶음을 INVALIDATED로 표시하고 사본과 특징값을 정리해 재사용을 막는다. 기존 모델 학습에 이미 사용됐는지는 별도 영향 항목으로 남긴다.

동일 아기, 같은 원본과 파생 음원은 학습·검증·시험에 갈라 넣지 않는다. 가정 환경이 겹치면 가정 그룹도 함께 묶는다. 정규화 정확성은 사람이 독립 검수한 입력 표본으로 필드별 일치·허구 추가·부정 및 계획 오인식을 측정한다. 이 지표와 울음 번역 모델의 성능 지표를 구분한다.

완료 기준 AC36~AC38 AC43: 적격 자료만 내보내 재로딩할 수 있고 미동의·삭제·시각 누수·미확인 자료가 섞이지 않으며 관련 학습 묶음을 추적할 수 있다.

### F20 공동양육 계정 연동과 정보 공유

연결 요구사항 R16 · P0 · 화면 SC01 SC02 SC06 SC08 SC10

OWNER가 참여자의 이메일을 입력해 24시간 유효한 일회용 초대 링크를 만든다. 링크는 OWNER가 직접 전달한다. 토큰은 충분한 난수로 만들고 서버에는 해시만 저장한다. 초대 수락은 로그인한 검증 이메일과 지정 이메일이 일치해야 한다. 수락 시 유효기간·취소·기존 참여·공유 범위 수락을 확인하고 멤버십을 원자적으로 만든다. 비로그인 링크 미리보기에 아기 기록을 노출하지 않는다.

초대 상태는 PENDING, ACCEPTED, EXPIRED, REVOKED이며 참여 상태는 ACTIVE, LEFT, REVOKED다. 같은 사용자의 활성 멤버십은 아기당 한 개다. 만료·이미 수락·다른 이메일인 경우 다음 행동을 구분해 안내한다. 초대 재발급은 이전 토큰을 취소한다.

| 동작 | OWNER | CAREGIVER |
|---|---|---|
| 공동 기록 분석 상태 및 맞춤 안내 조회 | 가능 | 가능 |
| 행동 상태 반응 입력과 본인 기록 수정 삭제 | 가능 | 가능 |
| 다른 작성자의 공유 기록 수정 삭제 | 가능하며 수정자 보존 | 후속 관찰 추가만 가능 |
| 본인의 미공유 초안 및 학습 참여 설정 | 가능 | 가능 |
| 아기 프로필 보관 설정 전체 삭제 구성원 관리 | 가능 | 불가 |
| 공동양육에서 나가기 | 전체 공간 종료 경로 안내 | 본인 참여 해제 |

다른 사람의 원문을 수정해도 최초 작성자를 바꾸지 않는다. OWNER의 수정에는 수정자와 확인자를 별도로 남기고 라벨을 재확인한다. 법적 보호자 자격을 관계명이나 OWNER 역할만으로 검증했다고 표시하지 않는다. 소유권 이전과 세분화된 읽기 전용 역할은 후속 확장이다.

기록·분석·정규화·파일 조회·변경 구독은 서버 및 DB에서 ACTIVE 멤버십을 확인한다. 작성 user_id는 인증 문맥으로 결정한다. 공동 맞춤 안내는 baby_id와 공동 맥락 버전을 기준으로 계산한다. 알림의 패턴과 기준 기록은 공유하되 알림 켜기·미루기·확인 여부는 사용자별로 둔다.

정상 연결에서 다른 구성원의 새 기록을 p95 5초 이내 반영하는 것을 목표로 한다. 변경 이벤트 또는 5초 간격의 가벼운 버전 조회로 캐시를 무효화하고, 창 복귀 시 다시 조회한다. 연결이 끊기면 마지막 동기화 시각과 이전 기록임을 표시한다. 추천 확인 중 맥락이 바뀌면 ‘새 기록이 추가됐어요’와 다시 보기 동작을 제공한다.

수정에는 version을 요구하고 충돌하면 최신 값과 초안을 비교한다. 수면 진행 중 1건, 아기별 활성 자동 감지 1세션은 서버에서 보장한다. 감지 시작의 충돌에는 현재 세션 ID를 돌려주며 명시적 기기 전환은 기존 세션 stop 후 새 시작으로 처리한다. 서버는 마지막 유효 heartbeat 이후 30초가 지나면 잠금을 만료하고, 이전 세션의 새 업로드는 거절한다. 다른 보호자가 가까운 시각에 같은 수유를 기록하면 중복 가능성을 알려 연결·유지 여부를 선택하게 하며 자동 합치지 않는다. 같은 시점의 배타적인 상태 관찰은 병존시키고 해당 라벨은 확인 전 학습에서 보류한다.

연결 해제는 이후 API·파일 신규 발급·변경 구독을 차단한다. 활성 화면은 권한 재확인 후 아기 캐시와 미전송 내용을 비우며 자동 재전송하지 않는다. 재생 경로 유효기간은 최대 60초로 제한한다. 이미 발급한 경로는 그 만료 전까지 접근 가능할 수 있으며, 이미 내려받은 자료가 원격으로 회수된다고 안내하지 않는다. 공동양육 탈퇴만으로 학습 동의를 철회한 것으로 간주하지 않되 별도 철회 선택을 바로 제공한다.

완료 기준 AC39~AC44: 두 계정으로 초대 수락과 같은 아기 이용, 변경 반영, 동시 수정, 권한 해제, 동의 분리와 아기 전환을 검증한다.

## 4 상태 전이와 시간 정책

### 감지 상태

| 상태 | 진입 조건 | 종료와 다음 상태 |
|---|---|---|
| IDLE | 최초 또는 사용자 종료 | 시작 선택 시 REQUESTING |
| REQUESTING | 마이크 및 입력 초기화 | 성공 LISTENING 실패 ERROR |
| LISTENING | 전경과 입력 정상 | 울음 조건 CANDIDATE 숨김 PAUSED |
| CANDIDATE | 감지 조건 일부 충족 | 연속 조건 충족 CAPTURING 해제 LISTENING |
| CAPTURING | 분석 음원 구간 수집 | 업로드를 시작하고 LISTENING 유지 |
| PAUSED | 숨김 트랙 중단 입력 끊김 오프라인 | 명시적 재개 REQUESTING 종료 IDLE |
| ERROR | 초기화나 장치 오류 | 복구 선택 REQUESTING 종료 IDLE |

분석 업로드 상태와 마이크 감지 상태는 독립이다. 업로드 중에도 입력은 유효할 수 있다. 다만 P0에서 네트워크가 끊기면 신규 자동 감지를 일시중지하고 짧은 구간을 무한히 메모리에 쌓지 않는다. 이미 수집한 음원은 현재 화면에서 재시도 가능 여부를 표시한다.

### 분석 상태

READY는 음원 검증 후 요청 가능, RUNNING은 실행 잠금 획득, COMPLETE는 후보와 안내 저장 완료, ABSTAIN은 품질 또는 추정 한계로 종료, FAILED는 처리 실패다. 품질 검사와 추론 중의 단계는 stage로 별도 표시한다. 판정 유보는 네트워크 오류가 아니다.

RUNNING의 lease_expires_at이 지나면 동일 프로세스의 늦은 결과가 저장되지 않도록 실행 토큰을 검사한다. 재시도는 attempt_no를 늘리고 새로운 실행 토큰을 받는다. 과거 시도의 응답이 늦게 와도 최신 시도를 덮어쓰지 못한다.

### 입력과 라벨 상태

RawCareEntry는 DRAFT → NORMALIZING → REVIEW_READY → CONFIRMED로 진행한다. 실패하면 NEEDS_MANUAL_REVIEW로 남고 원문은 보존한다. 초안 수정 시 input_revision을 늘려 이전 정규화 결과를 STALE로 처리한다. 확인된 기록의 수정은 별도 초안에서 시작하며 재확인이 완료될 때 기존 라벨과 학습 후보를 무효화한다. LabelAnnotation은 DRAFT, USER_CONFIRMED, USER_CORRECTED, STALE, DELETED를 구분한다. 학습 후보 적격 상태는 F19가 별도로 관리한다.

LLM 실행과 확인 저장도 오디오 분석처럼 DB 상태와 실행 토큰을 사용한다. 만료된 작업의 늦은 응답은 적용하지 않으며 확인 저장에서 input_revision과 normalization_run_id를 동시에 검사한다. 선택 전용 및 수동 복구는 normalization_mode=RULE 또는 MANUAL, run_id=null을 허용하고 고정 코드 검증과 동일한 확인·출처 기록을 수행한다. 같은 확인 요청의 중복 전송은 기존 저장 결과를 돌려준다.

| audio_retention | 임시 최대 1시간 선택 보관 7일 | 정리 작업으로 강제 |
| normalization_deadline 및 lease | 20초 및 30초 | 정규화 실패와 중단 판별 |
| raw_text_max | 2000자 | 자연어 입력 상한 |
| invite_ttl 및 playback_ttl | 24시간 및 60초 | 초대와 재생 경로 만료 |
| shared_refresh_target | 정상 연결 p95 5초 | 공동 기록 변경 반영 목표 |
| training_bundle_retention | 기본 30일 | 별도 동의 학습 사본 수명 |
| state_visual_stale | 30분 | 홈 그래픽의 과거 상태 표시 |

마이크 입력 시계가 멈추면 브라우저 타이머만으로 유효 관측 시간을 늘리지 않는다. heartbeat에는 새롭게 확인한 입력 구간의 끝 시각을 포함한다. 서버는 마지막 검증된 입력 끝 뒤의 시간을 관측됨으로 채우지 않는다. 뒤늦게 도착한 heartbeat도 실제 입력 범위와 단조 증가 순서를 검증한다.

## 5 핵심 데이터 명세

### 소유권과 필수 관계

User와 Baby는 BabyMembership으로 연결되며 Baby마다 OWNER 한 명이 있다. DB 제약과 트랜잭션으로 Baby.owner_id와 활성 OWNER 멤버십의 일치를 보장하고 초대는 CAREGIVER 역할만 부여한다. Baby는 CareEvent, CryEpisode와 ObservationWindow를 가진다. CryEpisode는 AudioAsset, Analysis, ActionAttempt를 연결한다. Analysis는 ContextSnapshot과 Recommendation을 참조한다. ActionAttempt는 실제 일상 기록인 CareEvent를 참조하고 Outcome을 여러 개 가질 수 있다.

UUID 식별자를 사용한다. user_id는 인증된 서버 문맥에서 결정하며 클라이언트가 지정한 소유자를 그대로 저장하지 않는다. 모든 관련 객체는 같은 baby_id를 가리켜야 한다. 삭제 시 참조 무결성과 파생 자료 정리가 함께 수행된다.

id와 관계 필드는 UUID, 시각은 ISO 8601 timestamptz, birth_date는 date, version과 attempt_no는 양의 정수다. 수량 및 시간 길이는 음수가 아닌 decimal, 상태는 이 명세의 enum, payload 및 근거는 스키마를 검증한 JSON이다. 선택으로 명시한 값과 진행 중 종료 시각 및 판단 불가 값만 null을 허용한다. 수정 가능한 Outcome과 Reminder 설정 및 날짜별 기록 확인에도 version을 둔다.

### CareEvent payload

feeding은 mode와 선택 amount_ml, duration_minutes를 저장한다. sleep은 occurred_at과 ended_at으로 구간을 표현하고 진행 중이면 ended_at=null이다. diaper는 operation=CHECK 또는 CHANGE와 상태를 저장한다. soothe는 action_kind와 선택 메모를 저장한다. 각 종류별 허용 필드를 검사하고 관련 없는 값을 버리지 말고 오류로 알린다.

### 분석 결과 계약

필수 출력은 analysis_id, status, quality_status, cry_detected, audio_candidates, abstain_reason, model_version, preprocess_version, label_mapping_version이다. cry_detected는 true, false 또는 품질 때문에 판단하지 못한 null이다. candidate_scores는 내부 진단용이며 사용자용 API는 필요한 순위와 후보만 제공할 수 있다.

맥락 결과에는 context_snapshot_id, recommendation_id, evidence_refs와 missing_fields를 포함한다. evidence_refs는 오디오 결과, 특정 기록 버전, 이전 사례 중 어디에서 나온 것인지 가리킨다. STUB 및 DEMO 표시는 결과와 내보내기 메타데이터에서 유지한다.

CaregiverObservation은 선택 질문의 답변과 보호자가 직접 보고한 현재 상태를 저장한다. kind는 질문 또는 도움 안내 목록의 고정 ID, value는 YES, NO, UNKNOWN 또는 질문별 허용 선택값이다. 미응답은 응답 행을 만들지 않는다. 응급 안내를 여는 직접 관찰 항목은 검토한 문구 목록에서만 제공하며 의료 상태를 모델이 자동으로 확인했다고 기록하지 않는다.

### 라벨 정규화의 데이터 계약

actions 항목은 action_code, assertion, performed_by, occurred_at 또는 relative_time, sequence, amount와 unit, evidence를 가진다. states 항목은 state_codes, phase, observed_at, linked_action_ids, evidence를 가진다. outcomes는 response_code, observed_at, linked_action_ids, attribution=SINGLE 또는 MULTI 또는 UNKNOWN이다. caregiver_interpretations는 원문에 명시된 추측만 담고 certainty=CAREGIVER_REPORTED를 유지한다.

추가 필드는 input_revision, ontology_version, normalizer_model, prompt_version, schema_version, source_mode, confirmed_by, confirmed_at, review_status다. evidence는 choice_id 또는 raw_text의 span_start, span_end, quote다. unknown은 null 또는 명시된 UNKNOWN 코드이며 누락을 0이나 성공으로 채우지 않는다. 시각 미상과 상대 시각은 time_precision=EXACT 또는 RELATIVE 또는 UNKNOWN으로 구분한다. 실제 수행자 performed_by는 확인한 구성원 ID 또는 null이며 기록 작성자와 자동으로 같다고 가정하지 않는다. 입력에 나온 사람 이름을 계정 ID로 임의 매칭하지 않는다.

행동 묶음은 같은 entry_id 안의 action IDs를 가지며 묶음 반응은 하나의 Outcome으로 저장한다. action_id와 action_group_id는 둘 중 하나만 값이 있어야 한다. episode 없이 남긴 상태는 StateObservation으로 저장할 수 있다. LLM 정규화 실행은 읽기와 구조화만 수행하며 CareEvent 쓰기는 확인 저장 단계에서 수행한다.

### 정규화 예시

| 입력 | 저장할 관찰 | 만들지 않을 추정 |
|---|---|---|
| 분유 80mL 먹이고 안아줬더니 잠들었어요 | FEEDING 80mL HOLDING ASLEEP와 행동 묶음 | 배고픔 확정 원인 또는 단일 행동의 효과 |
| 기저귀는 안 갈았고 조금 있다 먹이려 해요 | DIAPER_CHANGE NEGATED와 FEEDING PLANNED | 실제 기저귀 교체와 수유 집계 |
| 안아줬지만 계속 울어요 | HOLDING PERFORMED CRYING NO_CHANGE | 진정 성공 |
| 아까 좀 먹고 지금 졸려 보여요 | FEEDING 시각·양 미상과 SLEEPY_APPEARING | 임의 수유량이나 수면 시작 시각 |

초기 표준 코드는 FEEDING, DIAPER_CHECK, DIAPER_CHANGE, HOLDING, BURPING, SLEEP_PREPARATION, ENVIRONMENT_ADJUSTMENT, OTHER다. 상태 코드는 CRYING, FUSSING, CALM, SLEEPY_APPEARING, ASLEEP, AWAKE, CHEERFUL_APPEARING, UNKNOWN이며 반응 코드는 CALMED, PARTIALLY_CALMED, NO_CHANGE, CRYING_AGAIN, UNKNOWN이다. ‘아직 행동하지 않음’은 미수행 선택으로 저장하고 ActionAttempt를 만들지 않는다. 학습 작업별 라벨 허용 범위는 ontology_version에 고정한다.

### 수정 및 삭제의 경계

맥락 스냅샷은 정상 수정에서 불변이며 새 스냅샷을 추가한다. 사용자의 삭제 요구는 예외로 원문과 파생 정보를 제거하고 삭제 표시만 남긴다. 과거 분석을 재현하지 못하게 됐다면 reproduction_status=SOURCE_DELETED로 표시한다. 삭제된 내용을 다른 감사 테이블에 그대로 복사하지 않는다.

학습 자료 생성은 당시 알려진 맥락으로 이루어져야 한다. 사용자 수정과 늦은 기록은 known_at으로 분리한다. 사건 이후 결과를 최초 입력으로 사용하거나 평가 표본을 과거 사례 검색에 넣지 않는다.

## 6 API 계약

모든 서비스 API는 /v1을 접두사로 사용한다. Bearer 토큰을 검증하며 baby_id의 활성 멤버십과 객체별 읽기·쓰기 권한을 다시 확인한다. 작성자 전용 미공유 초안은 같은 아기 구성원이어도 열 수 없다. 작성 API는 Idempotency-Key와 요청 해시를 저장한다. 같은 키와 다른 본문은 409다. 키는 사용자, 경로, 작업 단위로 구분한다. 쓰기와 관련 조회는 일관된 DB 상태에서 응답한다.

업로드 경로는 서버가 발급하며 사용자가 지정한 외부 URL을 서버가 내려받지 않는다. 저장소 소유 경로, 실제 바이트, 디코딩 결과를 검사한다. 업로드 완료만으로 분석이 자동 생성되지는 않는다. analyses 요청이 원자적으로 실행 소유권을 얻는다.

분석은 요청 안에서 최대 45초 처리한다. 클라이언트가 analysis_id를 UUID로 먼저 만들어 요청하므로 응답이 유실돼도 조회할 ID가 남는다. 서버는 동일 ID의 아기·생성 요청자와 요청 해시를 검사하고 다른 요청으로 재사용하지 못하게 한다. 결과 조회는 해당 아기의 활성 구성원에게 허용한다. 클라이언트 응답 대기 제한은 이보다 길게 설정한다. 연결이 먼저 끊겼으면 기존 analysis_id를 조회한다. RUNNING이면 중복 추론을 만들지 않고 기다림을 표시하며 lease 만료 뒤 FAILED가 되면 재시도를 제공한다. 결과가 이미 저장돼 있으면 같은 결과를 반환한다.

기존 선택 전용 기록 API는 계속 사용할 수 있고 동일 LabelAnnotation 출처 형식으로 저장한다. confirmed_by와 작성자는 서버 인증 정보로 정하며 검수 API도 임의 ELIGIBLE 지정 전에 동의·출처 검사를 다시 수행한다. raw_text가 있는 입력은 확인 계약을 거쳐야 한다. 내부 dataset API는 보호자용 인증 역할로 접근할 수 없다. 대량 내보내기는 내구성 작업으로 전환하며 P0 소규모 묶음은 제한된 요청 안에서 완료한다.

확인된 입력은 ACTIVE 구성원이 조회할 수 있다. 수정은 원기록 작성자 또는 OWNER가 POST /babies/{id}/care-entries에 supersedes_entry_id와 base_record_versions를 보내 새 초안을 만드는 방식이다. 새 초안의 author_id는 수정자이며 재확인 전까지 그 수정자만 조회한다. 기존 확정 기록은 계속 공유한다. 확인 저장은 기준 버전을 검사해 연결된 기록 ID를 유지한 채 갱신하고 최초 작성자를 보존한다. 추가·제거한 항목만 생성·삭제하며 같은 돌봄 기록을 복제하지 않는다. 이미 확인된 입력의 직접 PATCH는 409로 거절하고 수정 초안 경로를 안내한다.

### 공통 오류 규격

오류 본문은 code, message, retryable, request_id, field_errors와 필요한 기존 analysis_id를 포함한다. 401은 로그인 필요, 403은 참여 중이나 관리 권한 부족, 404는 없거나 비구성원, 410은 초대 만료, 409는 중복 또는 버전 충돌, 413은 용량 초과, 422는 입력 검증 실패, 429는 요청 한도, 503은 분석 서비스 준비 또는 일시 장애다. 사용자 메시지와 내부 로그를 분리하고 로그에 원시 음원, 토큰, 아기 별칭 및 메모를 남기지 않는다.

## 7 추천 및 개인화 규칙의 관리

### 규칙 우선순위

P0 돌봄 추천에는 검토한 문구 템플릿과 버전 관리되는 규칙을 사용한다. 자연어 라벨 정규화에는 LLM API를 사용하되, 장애 시 선택지 입력과 기존 분석·추천은 계속 사용할 수 있어야 한다. 추후 자연어 설명을 생성한다면 구조화된 근거만 입력하고 후보, 관찰과 처치 범위를 바꾸지 못하도록 출력 검증을 추가한다.

배고픔 후보에 수유 필요 신호 확인, 졸림 후보에 현재 깨어 있음과 졸림 신호 확인, 불편함 후보에 기저귀 및 환경 확인을 연결할 수 있다. 기록만으로 기저귀나 배고픔 원인을 맞혔다고 표현하지 않는다. 수유와 수면의 정상 간격을 임의의 공통 시간으로 강제하지 않는다.

## 8 관측 자료와 후속 예측 계약

유효 관측은 입력 신호 정상, 전경 지원 조건, 시간 정합성, 선택 아기 관찰 확인을 함께 기록한 범위다. 보호자 확인만으로 아기가 실제 음원에 계속 있었음을 입증한 것으로 취급하지 않는다. source_presence는 확인 방법과 불확실성을 포함한다. 품질 불량 구간은 미래 예측에서 ‘울지 않음’ 표본으로 자동 포함하지 않는다.

후속 E02의 학습 단위는 기준 시각 t까지의 기록과 이후 30분의 울음 발생 여부다. 관측이 중간에 끊긴 창은 censored로 제외하거나 그 조건을 처리하는 방법을 적용한다. 개입 여부, 알림 노출, 아기 ID, 시각과 모델 버전을 함께 저장한다. 겹치는 시간 창은 무작위로 흩어 평가하지 않고 아기와 시간 블록으로 분리한다.

현재 P0에는 future_cry_probability 사용자 출력 필드를 만들지 않는다. 확률 보정, 시간당 오경보, 사전 안내 시간, 기준 모델 대비 성능, 실제 사용 전향 평가를 통과한 뒤 계약 버전을 올린다. 예방 행동의 효과는 확률 모델 평가와 분리한다.

## 9 보안과 운영 요구사항

### 접근과 데이터 수명

Supabase 관계형 테이블과 Storage에 활성 아기 멤버십 기반 행 단위 접근 정책을 적용한다. 관리 동작에는 OWNER 조건을 추가한다. 서버 권한 키로 DB 정책을 우회하는 경로도 애플리케이션에서 같은 권한을 검사한다. 초안은 작성자 전용, 확인 저장된 입력과 기록은 아기 구성원 공유로 구분한다. 서버 권한 키는 Cloud Run 비밀 설정에만 둔다. 클라이언트용 공개 키와 인증 토큰의 역할을 구분한다. HTTPS에서 마이크를 사용하고 허용한 웹 출처에서만 API를 호출하도록 설정한다.

음원은 private bucket에 저장하고 짧게 만료하는 접근 경로를 발급한다. 공개 링크를 일일 요약이나 로그에 포함하지 않는다. 임시 및 보관 음원 정리 작업은 만료 필드를 기준으로 실행하며 실패 건을 재시도하고 알린다. 인증 세션만 바뀌었는데 이전 계정의 음원이나 기록이 남아 보이지 않도록 캐시를 비운다.

삭제 요청을 받으면 논리적으로 즉시 제외하고 원문과 파생 자료를 정리한다. 삭제 작업 실패를 완료로 표시하지 않는다. 백업이 존재하면 복원 시 삭제 목록을 재적용하며 백업 만료 기간은 실제 선택한 서비스 설정과 안내에 맞춘다. 실사용 데이터를 학습용으로 따로 복사하기 전에 접근자, 보관 기간, 철회 반영 방식을 확정한다.

### 배포와 비용 통제

개발과 시연 환경의 DB, 파일, 키와 도메인을 구분한다. 모델 가중치와 소스 버전을 고정한 컨테이너를 배포한다. 최대 인스턴스 수, 인스턴스당 동시 추론 수, 사용자별 요청량, 파일 크기와 처리 기한을 설정한다. 비용 알림이 자동으로 모든 과금을 끊는 기능이라고 가정하지 않는다.

준비 상태 확인은 모델 적재 성공과 전처리 및 레지스트리 일치 여부를 포함한다. 결과 지연, 품질 유보, 추론 오류와 삭제 실패를 각각 계측한다. 로그는 request_id와 버전 중심으로 기록한다. LLM 요청에는 최소한의 정리 대상만 보내고 원문·응답 전체를 일반 로그에 남기지 않는다. 제공자 보관·학습 사용 설정은 배포 전에 확인한다. LLM 입력·출력 한도, 사용자별 호출량과 비용 상한을 별도로 설정한다. 모델 교체 전후 smoke test와 서비스 롤백 경로를 유지한다.

### 성능과 지원 기기 검증

예열된 시연 환경에서 업로드 완료부터 결과 저장까지 p95 15초 이내를 초기 목표로 한다. 45초 처리 기한 초과는 FAILED이며 유보로 집계하지 않는다. 초기 성능 측정은 같은 입력 길이, 동시 사용자 수, 하드웨어와 모델 버전을 함께 기록한다.

지원 후보는 Mac 또는 Windows의 Chrome, Android Chrome, iPhone Safari의 전경 세션이다. 실제 시험을 통과한 운영체제와 브라우저 버전만 지원 목록에 넣는다. iPhone의 잠금, 전화 수신, 장치 전환, Wake Lock 해제, 외부 음원 파일 디코딩은 별도 재현 시험을 한다. PWA 설치 여부와 화면 잠금 중 감지 가능 여부를 같은 기능으로 표시하지 않는다.

### 모델 평가 산출물

울음 감지는 사건 단위 재현율, 유효 관측 시간당 오경보와 탐지 지연을 보고한다. 원인 후보는 데이터 분할 방법, macro F1, 범주별 재현율, 혼동행렬, 판단 유보율과 답변한 표본의 오류를 보고한다. 지원하지 않는 범주를 제외해 점수가 바뀌면 범위 변경을 함께 기록한다.

같은 음원의 잘린 조각, 증강 음원, 원본과 정리본을 독립 시험 자료로 중복 계산하지 않는다. 공개 앱 설치 ID를 실제 아기 ID로 보고하지 않는다. 오디오 단독, 맥락 단독, 결합, 사례 추가의 비교에는 같은 평가 조건과 분석 당시 알려진 기록을 사용한다.

## 11 구현 순서와 확장 계약

### 개발 순서

1. F01 F02 F20 F09 F14를 먼저 구현해 인증, 공동양육 권한, 기록 수정과 삭제를 고정한다.
2. F03 F05 F06 F10 F17 F18로 한 음원에서 선택·자연어 입력, 라벨 확인과 상태 그래픽까지 연결한다.
3. F07 F08 F11로 맥락 수정과 이전 사례가 안내에 반영되게 한다.
4. F04 F12 F13으로 활성 감지, 오늘 요약과 준비 알림을 완성한다.
5. F19로 동의·검수·내보내기를 연결하고 F15 F16 및 전체 인수 시험으로 두 계정 시연과 복구를 검증한다.

병행할 수 있는 ML 작업은 데이터 이용 조건 확인, M2D 주 경로 학습과 평가, 경량 울음 감지기 선택과 실제 브라우저 시험이다. BABYCRY 실학습과 대량 다운로드는 이용 조건과 최신 학습 계획의 준비 기준을 따른다. 화면 구현 완료와 학습 완료를 같은 상태로 표시하지 않는다.

### E01 음성 입력과 기록 질문

P1 음성 기록은 발화에서 CareEvent 초안을 생성하고 저장 전에 확인을 받는다. 공동양육의 기본 공유는 F20의 P0이며 후속에는 소유권 이전과 세분화된 역할을 확장한다. 기록 기반 질문은 조회 가능한 근거만 답변에 사용하고 기록에 없는 사실은 답변하지 않는다.

### E02 사전 예측

8장의 관측 계약을 활용해 비공개 연구를 시작한다. 출시할 경우 prediction_id, horizon, probability, calibration_version, observed_coverage, intervention_state를 갖는 별도 계약을 추가한다. 준비 알림을 이 필드에 임의로 매핑하지 않는다.

### E03 앱과 기기 연동

모바일 앱은 기존 인증 및 분석 API를 재사용한다. DeviceObservation은 device_id, baby_id, modality, captured_at, received_at, quality, presence, consent_scope를 포함한다. 적외선 영상은 입력 종류와 관찰 조건으로 기록하며 체온 측정값으로 변환하지 않는다.

가전 명령은 DeviceCommand의 proposed, confirmed, sent, acknowledged, failed, unknown 상태로 다룬다. 최초 구현은 상태 조회와 제안에 한정하고, 후속 실제 제어에서 사용자 확인 및 기기별 실행 조건을 추가한다. 특히 분유제조처럼 중복 실행이 영향을 주는 명령은 응답 유실 상태에서 맹목적으로 재전송하지 않는다.

### E04 다양한 발성과 맥락을 결합한 기분 추론

P2 연구 범위다. VocalizationEvent는 cry, babble, laugh, fuss, other, unknown 등의 발성 종류, 구간, 품질, 월령 범위와 source_presence를 포함한다. AffectInference는 상태 후보와 불확실성, audio_version, context_snapshot_id, evidence_refs, abstain_reason을 반환한다. 음성 종류와 기분, 욕구를 서로 다른 필드로 둔다.

옹알이·웃음·칭얼거림 음원과 수유·수면·상호작용 및 보호자 관찰을 시각으로 연결한 자료가 필요하다. 보호자 관찰도 추정 출처를 유지하며 옹알이를 즐거움 정답으로 자동 매핑하지 않는다. 오디오 단독 대비 맥락 결합 평가, 아기·가정·월령별 일반화와 유보 평가 후 출시한다. P0 StateObservation과 LabelAnnotation을 재사용할 수 있지만 F18 그래픽을 자동 기분 판정의 증거로 사용하지 않는다.
