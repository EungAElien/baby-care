> 이전 버전 보관본입니다. 현재 제품·API 기준은 [문서 안내](../../README.md)의 v2 문서와 계약을 따릅니다. 본문은 당시 기획을 보존하며 현재 구현 상태를 뜻하지 않습니다.

> 이후 사용자 수정 요청을 반영한 [v2 범주·표시 흐름 기획](../../product/baby-state-care-action-categories-v2.md)이 이 기획을 대체한다. 특히 완료한 조치의 포함 기준, 모델 추정 범주, 홈 전환과 정적 로그는 v2를 따른다. 이 파일은 이전 기획을 확인하기 위한 기록이다.

## 1. 분류 기준

아기 상태는 **기본 상태 7개와 모름 1개**, 양육자 대응 행동은 **구체 행동 7개와 기타 1개**로 정리한다. 아래 코드는 현재 OpenAPI에 있는 값을 그대로 사용한다. 표의 묶음은 이해를 돕기 위한 분류이며 새 API 필드나 enum이 아니다.

| 구분 | 분류하는 대상 | 예시 |
|---|---|---|
| 아기 상태 | 관찰 시점에 보호자가 보고한 아기의 모습 | 우는 중, 졸려 보임, 잠듦 |
| 양육자 대응 행동 | 양육자가 실제로 수행했다고 확인한 돌봄 | 수유하기, 안아주기, 기저귀 교체 |
| 행동 후 반응 | 행동 전과 비교해 보호자가 보고한 변화 | 진정됨, 일부 진정, 변화 없음 |
| 원인 후보·보호자 해석 | 왜 그런 상태였는지에 대한 추정 | 배고팠을 가능성, 불편했던 것 같음 |

번역 결과의 원인 후보와 아기 관찰 상태는 서로 다른 항목으로 유지한다. 배고픔이나 불편함을 추정했다고 해서 우는 중·진정됨 등의 관찰이 확인된 것은 아니다. 제품에 노출할 모델 후보는 실제 등록된 지원 라벨을 따른다. 이 문서는 모델의 지원 범주나 성능을 추가로 확정하지 않는다.

## 2. 아기 상태: 8개

| 묶음 | 사용자에게 보여줄 범주 | 기존 코드 | 의미와 포함 기준 | 구분 기준 |
|---|---|---|---|---|
| 울음·안정·정서 표현 | 우는 중 | `CRYING` | 보호자가 아기가 울고 있다고 보고한 상태 | 울음 원인이나 강도를 뜻하지 않는다. 작은 소리로 운다고 자동으로 칭얼거림에 넣지 않는다. |
| 울음·안정·정서 표현 | 칭얼거림 | `FUSSING` | 보호자가 보채거나 칭얼거린다고 표현한 상태 | 배고픔·졸림·통증 같은 원인을 포함하지 않는다. 소리 크기만으로 우는 중과 구분하지 않는다. |
| 울음·안정·정서 표현 | 진정됨 | `CALM` | 보호자가 진정되어 있거나 편안한 상태라고 보고한 모습 | 깨어 있음, 잠듦, 즐거워 보임과 각각 다르다. 특정 행동 때문에 진정됐다는 효과 판단은 별도다. |
| 울음·안정·정서 표현 | 즐거워 보임 | `CHEERFUL_APPEARING` | 보호자가 표정·반응을 보고 즐거워 보인다고 보고한 상태 | 울지 않음이나 옹알이만으로 자동 배정하지 않는다. 감정에 대한 보호자의 해석임을 유지한다. |
| 수면·각성 | 깨어 있음 | `AWAKE` | 보호자가 잠들어 있지 않고 깨어 있다고 보고한 상태 | 차분한지, 칭얼거리는지, 즐거운지는 이 값만으로 알 수 없다. |
| 수면·각성 | 졸려 보임 | `SLEEPY_APPEARING` | 보호자가 졸려 보인다고 보고했지만 잠들었다고 확인하지 않은 상태 | 재우기를 시도했다는 행동, 잠들었다는 관찰과 구분한다. 울음 모델의 피곤함 후보로 자동 배정하지 않는다. |
| 수면·각성 | 잠듦 | `ASLEEP` | 보호자가 실제로 잠들었다고 보고한 상태 | 재우기 시도나 눈을 잠깐 감은 모습만으로 추정하지 않는다. |
| 미확인 | 모름 | `UNKNOWN` | 보호자가 관찰한 상태를 판단하거나 확인할 수 없다고 명시한 경우 | 아무 기록도 없는 것과 다르다. 관찰 시각을 모르는 경우는 시각의 불확실성으로 따로 다룬다. |

### 함께 입력할 수 있는 상태

상태 8개는 모두 상호 배타적인 단일 선택 목록이 아니다. 수면·각성과 울음·정서 표현처럼 서로 다른 측면을 함께 보고할 수 있다. 새 필드를 만들지 않고 기존 `state_codes` 배열의 의미를 따른다.

- “깨어 있고 편안해 보여요”: 깨어 있음 + 진정됨.
- “졸려 보이면서 칭얼거려요”: 졸려 보임 + 칭얼거림.
- “깨어서 울고 있어요”: 깨어 있음 + 우는 중.
- “깨어 있는 건 알겠는데 기분은 모르겠어요”: 깨어 있음만 기록하고, 알려지지 않은 정서 상태를 채우지 않는다.
- “우는 중이었다가 잠들었어요”: 두 시점의 관찰로 구분한다. 한 시점의 혼합 상태로 압축하지 않는다.

같은 시점에 깨어 있음과 잠듦처럼 의미가 충돌하는 입력은 임의로 하나를 선택하지 않고 확인 대상으로 남긴다. ‘모름’은 부족한 정보를 대신 채우는 기본값으로 자동 삽입하지 않는다. 원문의 순서나 관찰 맥락을 보존한다.

## 3. 양육자 대응 행동: 8개

| 묶음 | 사용자에게 보여줄 범주 | 기존 코드 | 의미와 포함 기준 | 구분 기준 |
|---|---|---|---|---|
| 먹이기 | 수유하기 | `FEEDING` | 모유·분유 등의 수유를 실제로 한 행동 | 수유 준비, 먹일 계획, 수유 필요 추정은 실제 수유가 아니다. 수유량·시간·방식은 세부 정보다. |
| 기저귀 돌봄 | 기저귀 확인 | `DIAPER_CHECK` | 기저귀 상태를 실제로 살펴본 행동 | 교체 여부는 별도다. 깨끗함·젖음·대변 등은 기저귀 상태 정보다. |
| 기저귀 돌봄 | 기저귀 교체 | `DIAPER_CHANGE` | 기저귀를 실제로 교체한 행동 | 교체 기록에서 별도의 확인 행동을 자동 생성하지 않는다. 확인과 교체가 각각 보고된 경우에는 구분해 보존한다. |
| 안기·돌봄 | 안아주기 | `HOLDING` | 아기를 실제로 안아준 행동 | 안아줬다고 진정이나 수면을 추정하지 않는다. 안았다는 근거 없이 토닥이기만 한 경우는 이 범주로 자동 배정하지 않는다. |
| 안기·돌봄 | 트림 돕기 | `BURPING` | 트림을 돕는 행동을 실제로 한 경우 | 트림이 실제로 나왔는지와 별개다. 단순히 ‘토닥였다’는 말에서 트림 목적을 만들어내지 않는다. |
| 수면 돕기 | 재우기 시도·수면 준비 | `SLEEP_PREPARATION` | 잠자리를 준비하거나 실제로 재우기를 시도한 행동 | 아기가 잠들었다는 뜻이 아니다. ‘나중에 재울 예정’은 수행한 행동이 아니다. |
| 주변 환경 | 환경 조절 | `ENVIRONMENT_ADJUSTMENT` | 조명·주변 소리·실내 환경 등을 실제로 조절한 행동 | 환경을 바꿨다고 이전 환경이 울음 원인이었다고 판단하지 않는다. 구체적으로 무엇을 바꿨는지는 원문에서 보존한다. |
| 그 밖의 돌봄 | 기타 대응 | `OTHER` | 행동을 실제로 수행한 사실은 명확하지만 앞의 7개에 해당하지 않는 경우 | 무엇을 했는지 모른다는 뜻이 아니다. 실제 행동 여부가 불확실하면 수행 기록으로 만들지 않는다. |

기타 대응의 입력 예시는 안기나 트림 목적이 명시되지 않은 토닥이기, 말 걸기, 노래 불러주기 등이다. 이는 기록을 분류하기 위한 예시이며 새로운 권장 행동 목록이 아니다. 세부 행동을 구조화된 새 코드로 만들지는 않는다.

### 행동을 나누는 기준

- 여러 행동은 실제 보고된 순서대로 보존한다. “기저귀를 확인하고 분유를 먹였어요”는 기저귀 확인과 수유의 두 행동이다.
- 동작과 그 동작의 목적을 중복된 수행으로 늘리지 않는다. “안아서 재웠어요”는 안아주기와 잠듦 관찰을 구분하며, 재우기 목적만으로 별도의 수면 준비 행동을 자동 추가하지 않는다.
- “재우기를 시도했지만 아직 안 자요”는 수면 준비 행동과 깨어 있음 관찰을 구분한다.
- 양육자의 성별·관계에 따라 행동 코드를 나누지 않는다. 작성자와 실제 수행자가 다를 수 있고, 누가 수행했는지 모르면 임의로 채우지 않는다.
- 울음 사건에 대한 대응과 평소 돌봄에 같은 행동 분류를 사용할 수 있다. 같은 수유를 사건에 연결했다고 새 수유를 추가 집계하지 않는다.

### 수행 여부는 행동 종류와 별개

| 입력 의미 | 기존 구분 | 처리 의미 |
|---|---|---|
| 실제로 했음 | `PERFORMED` | 확인 뒤 수행 행동으로 기록 |
| 앞으로 할 예정 | `PLANNED` | 계획으로 보존, 수행 행동으로 집계하지 않음 |
| 하지 않았음 | `NEGATED` | 부정 내용으로 보존, 수행 행동으로 집계하지 않음 |
| 했는지 확실하지 않음 | `UNCERTAIN` | 불확실성을 보존, 수행 행동으로 집계하지 않음 |

‘아직 대응하지 않음’은 별도의 아홉 번째 행동이 아니다. 수행 행동이 없다는 선택이며 `ActionAttempt`를 만들지 않는다. 자연어 정규화 결과는 확인 전 초안이고, 추천 버튼을 눌렀다는 사실도 실제 수행 근거가 아니다.

## 4. 상태와 혼동하지 않을 행동 후 반응

기존 반응 범주는 다음 5개를 유지한다. 이번 작업의 두 주 분류를 늘리는 항목이 아니라, 상태와 행동의 의미를 구분하기 위한 관련 기준이다.

| 반응 범주 | 기존 코드 | 의미 |
|---|---|---|
| 진정됨 | `CALMED` | 보호자가 행동 뒤 진정되었다고 보고 |
| 일부 진정 | `PARTIALLY_CALMED` | 전보다 일부 진정되었다고 보고 |
| 변화 없음 | `NO_CHANGE` | 행동 전과 비교해 달라지지 않았다고 보고 |
| 다시 욺 | `CRYING_AGAIN` | 잠시 가라앉거나 멈춘 뒤 다시 울었다고 보고 |
| 확인 못함 | `UNKNOWN` | 해당 행동 뒤 반응을 확인할 수 없다고 명시 |

`CALM`은 관찰 시점의 상태이고, `CALMED`는 행동 전후의 변화 보고다. “먹였고 지금도 울어요”라는 말만으로 변화 없음이라고 단정하지 않는다. 일부 진정되었지만 여전히 울고 있을 수 있기 때문이다. 반응을 입력하지 않은 경우와 확인 못함을 입력한 경우도 구분한다.

잠듦은 아기 상태이며, 수면 준비는 양육자 행동이다. 어느 한쪽이 있다고 다른 쪽이나 진정 반응을 자동으로 생성하지 않는다. 여러 행동 뒤 나타난 반응은 근거 없이 마지막 행동 하나의 효과로 배정하지 않는다.

## 6. 기존 계약과의 관계

- 관련 작업: A-06 결과·행동, A-07 정규화·그래픽, B-07 정규화·확인 기록. 관련 기능: F10, F17, F18.
- 이 문서는 현재 범주의 의미와 구분 예시를 정리한다. `state_codes`, `visual_state_code`, `action_code`, 반응 코드의 허용 값은 변경하지 않는다.
- 수유 방식·양·시간, 기저귀 상태, 관찰 출처·시각·확인 여부는 기존 세부 정보다. 이번 문서의 설명을 새로운 필드가 이미 존재한다는 뜻으로 읽지 않는다. 특히 더 세밀한 수유 전달 방식이나 기타 행동 하위 코드는 여기서 신설하지 않는다.
- 상태·행동의 저장, 초안 확인, 권한, 화면 표시값의 최종 계약은 아래 기준 문서가 우선한다. 애니메이션별 장면·동작·자산, 화면 코드, API와 모델 구현은 이번 작업 범위에 포함하지 않는다.
