# 아기 상태·완료한 돌봄 조치·기록 그래프 범주 v2

> 이 문서는 사용자 선택을 반영한 범주·표시 기획입니다. 계약 1.0.0에 아직 반영되지 않은 접점은 8절에 남아 있으며, 이번 이관으로 API나 구현 상태가 바뀌지 않습니다.

작성일: 2026-09-19\
상태: 사용자 수정 요청과 추가 답변을 반영한 범주·표시 흐름 기획\
범위: 범주, 분류 기준, 홈 표시 순서, 정적 로그의 의미. 에셋·화면·API 구현은 포함하지 않음.

## 1. 이번에 정한 기준

보호자가 기록한 **관찰 상태**, 울음 분석에서 나온 **모델 추정**, 보호자가 수행한 **돌봄 조치**를 세 분류로 관리한다. 홈에서는 이 세 분류의 표현이 차례로 등장하고, 로그에서는 같은 기록을 정지 그림으로 보여준다.

사용자는 “완료한 조치는 표시하고, 조치 후 아기 상태는 별도로 기록한다”를 선택했다. 따라서 수유나 기저귀 교체 뒤에도 아기가 계속 울면 **실제 조치와 계속 우는 상태를 모두 기록·표현**한다. 완료는 돌봄이 실제 이루어졌다는 의미이며 진정에 성공했다는 뜻이 아니다.

기저귀 확인, 수유 준비, 재우기 시도, 행동 계획은 완료한 조치의 애니메이션 범주에서 제외한다. 사용자가 남긴 확인·시도 내용은 원문이나 메모로 보존할 수 있으며, 이를 ‘기타 완료 조치’로 우회 분류하지 않는다.

이 문서는 [v1 범주 기획](../archive/2026-09-product/baby-state-care-action-categories-v1.md)을 대체한다. 현재 개발 계약 1.0.0의 실제 API 형식과 일부 화면 규칙에는 아직 반영되지 않은 기획 변경이 있다. 변경 지점은 8절에 명시했다.

## 2. 보호자가 관찰해 기록하는 아기 상태: 8종

평상시 홈과 조치 후 홈은 같은 상태 목록을 사용한다. 항상 **마지막 관찰 시각·기록 출처**를 함께 보여주며, 기록이 실시간 상태를 보장하는 것처럼 표현하지 않는다.

| 표시 범주 | 현재 관찰 코드 | 포함 기준 | 구분할 내용 |
|---|---|---|---|
| 우는 중 | `CRYING` | 보호자가 울고 있다고 관찰 | 원인이나 울음 강도를 자동으로 추가하지 않음 |
| 칭얼거림 | `FUSSING` | 보채거나 칭얼거린다고 관찰 | 소리 크기만으로 우는 중과 나누지 않음 |
| 편안해 보임 | `CALM` | 차분하거나 편안하다고 관찰 | ‘울지 않음’만으로 자동 부여하지 않음. 특정 조치의 효과와는 별개 |
| 즐거워 보임 | `CHEERFUL_APPEARING` | 웃음·표정·반응을 보고 즐거워 보인다고 보고 | 보호자의 관찰·해석임을 유지 |
| 깨어 있음 | `AWAKE` | 잠들어 있지 않다고 관찰 | 기분이 좋은지, 편안한지는 별도 |
| 졸려 보임 | `SLEEPY_APPEARING` | 졸려 보이지만 아직 잠들었다고 확인하지 않음 | 모델의 피곤함 추정으로 자동 입력하지 않음 |
| 잠듦 | `ASLEEP` | 실제 잠든 것을 관찰 | 재우기 시도만으로 입력하지 않음 |
| 상태 확인 못함 | `UNKNOWN` | 보호자가 상태를 확인하거나 판단할 수 없다고 명시 | 기록 없음과 구분. 중립 표현 사용 |

‘편안해 보임’은 기존 기획의 ‘진정됨’에 대응하는 지속 상태 표현이다. 전후 변화인 ‘진정됐음’과 구별하기 위해 화면 이름을 다듬었다.

서로 다른 측면은 함께 기록할 수 있다. “깨어 있고 편안해요”는 깨어 있음 + 편안해 보임, “졸려서 보채는 것 같아요”는 보호자 확인을 거쳐 졸려 보임 + 칭얼거림으로 기록한다. 후자의 인과 해석은 관찰 사실과 별도로 보존한다.

대표 표현은 호환되는 상태 조합 안에서 **우는 중 → 칭얼거림 → 잠듦 → 졸려 보임 → 즐거워 보임 → 편안해 보임 → 깨어 있음** 순으로 선택하는 기획으로 둔다. 나머지 확인 상태는 글로 함께 표시한다. 이 순서는 증상의 심각도나 의료 우선순위가 아니라 한 캐릭터의 대표 모습을 고르는 규칙이다.

- 명시적으로 같은 시점에 깨어 있음과 잠듦처럼 충돌하면 우선순위를 적용하지 않고 중립 표현과 확인 안내를 사용한다.
- “울다가 잠들었어요”는 시점이 다른 두 상태다. 최신 관찰인 잠듦을 홈에 표시한다.
- 일부만 알면 아는 상태만 기록한다. 예를 들어 깨어 있음은 알지만 기분은 모르면 깨어 있음만 남긴다.
- 아직 관찰 기록이 없으면 ‘아직 상태 기록이 없어요’를 표시한다. 상태 확인 못함이라는 관찰을 자동 생성하지 않는다.

## 3. 울음이 감지됐을 때 모델이 표현할 범주: 원인 후보 5종

모델 범주는 관찰 상태와 별개인 **울음의 의미·원인 후보**다. 현재 프로젝트가 연구 대상으로 둔 다섯 라벨을 표현 목표로 사용한다. 다섯 범주를 실제 모델이 모두 신뢰성 있게 구분한다는 뜻은 아니며, 서비스에서는 평가를 통과하고 등록된 지원 라벨만 활성화한다.

| 표현 목표 범주 | 연구 라벨 | 사용자에게 보여줄 문구 예시 | 의미의 경계 |
|---|---|---|---|
| 배고픔 가능성 | `hungry` | 배가 고플 수 있어요 | 수유 뒤 진정됐다는 사실만으로 원인을 확정하지 않음 |
| 졸림·피곤함 가능성 | `tired` | 졸리거나 피곤할 수 있어요 | 보호자가 졸림이나 잠듦을 관찰한 기록과 구분 |
| 트림 필요 가능성 | `burping` | 트림이 필요할 수 있어요 | 트림 발생을 확인한 것은 아님 |
| 배 불편함 가능성 | `belly_pain` | 배가 불편할 수 있어요 | 복통·질병 진단으로 표현하지 않음 |
| 일반적인 불편함 가능성 | `discomfort` | 불편한 점이 있을 수 있어요 | 기저귀·온도·외로움 등 구체 원인을 임의로 붙이지 않음 |

**판단 어려움**을 별도 대체 표현으로 준비한다. 이것은 여섯 번째 원인 정답이 아니라 모델이 원인 후보를 제시하지 못한 상황이다. 캐릭터나 대체 텍스트가 배고픔 등 특정 원인을 암시하지 않도록 한다.

추가로 ‘울음 감지·분석 중’, ‘분석 실패’, ‘울음 확인 안 됨’은 시스템 표시 상태다. 아기의 감정이나 원인 범주에 합치지 않는다. 분석 완료, 판단 유보, 처리 실패의 구분은 기존 계약을 유지한다.

모델 결과가 `COMPLETE`이고 지원 범위에 해당할 때 1순위 후보를 대표 표현에 연결한다. 다른 후보가 있으면 함께 확인할 수 있게 하되, 여러 후보를 원인이 확정된 혼합 상태로 만들지 않는다. `ABSTAIN`에는 원인 후보를 만들지 않으며, `FAILED`를 판단 어려움으로 바꾸지 않는다. 알 수 없는 라벨에는 중립 표현을 사용한다.

모든 모델 표현에는 **AI 추정 · 분석 시각**을 표시한다. 내부 후보 점수를 실제 원인 확률처럼 백분율로 표시하거나 보호자 관찰 기록으로 자동 저장하지 않는다.

프로젝트의 다섯 연구 라벨은 [기존 기능명세](../archive/2026-09-product/baby-care-functional-spec-v1.md)의 F04와 [학습 계획](../research/m2d/m2d-local-training-plan-2026-09-15.md)에 기재되어 있다. 참고 데이터인 Donate-a-Cry의 원본 설명은 기여자가 직접 라벨을 붙였으며 원인을 추정한 것이라고 명시한다. 라벨의 존재가 객관적 원인이나 제품 성능의 검증을 뜻하지 않는다. [원본 저장소 설명](https://github.com/gveres/donateacry-corpus)

## 4. 양육자의 완료한 돌봄 조치: 기본 7종 + 기타 1종

조치 이름은 실제로 무엇을 했는지 표현한다. ‘아기를 진정시킴’처럼 결과만 있는 이름을 행동 범주로 사용하지 않는다.

| 표시 범주 | 포함·완료 기준 | 제외하거나 별도로 기록할 내용 |
|---|---|---|
| 수유함 | 실제 수유를 했다고 확인 | 수유 준비·먹일 계획 제외. 먹인 양·방식·시간은 세부 정보이며 다 먹음·배부름을 자동 추정하지 않음 |
| 기저귀 갈아줌 | 실제 기저귀를 교체했다고 확인 | 확인만 함은 제외. 교체 뒤에도 울면 우는 상태를 함께 기록 |
| 안아줌 | 실제 아기를 안아 돌봤다고 확인 | 안으려 했다는 표현은 제외. 진정·잠듦 여부는 별도 |
| 토닥여줌 | 실제 토닥이는 돌봄을 했다고 확인 | 안기·트림·수면 목적을 임의로 추가하지 않음. 말 걸기만 한 경우와 구분 |
| 트림시킴 | 트림을 돕는 돌봄을 했고 실제 트림이 나왔다고 확인 | 트림을 시도했지만 나오지 않은 경우는 이 범주에서 제외. 실제 토닥임·안기가 있었다면 해당 행동으로 기록 가능 |
| 재워줌 | 보호자가 재우는 돌봄을 했고 실제 잠들었다고 확인 | 재우기 시도·잠자리 준비 제외. 다른 조치 뒤 우연히 잠든 사실만으로 이 행동을 추가하지 않음 |
| 환경 바꿔줌 | 조명·소리·실내 환경을 실제로 바꿨다고 확인 | 환경 확인·조절 계획 제외. 무엇을 바꿨는지 보존하고, 진정 효과나 기존 환경이 원인이었다고 추정하지 않음 |
| 기타 완료 조치 | 위에 속하지 않는 구체적인 돌봄을 실제로 수행 | 옷 갈아입히기·씻겨주기·놀아주기 등의 구체 내용 필요. ‘뭔가 했다’, 확인·계획·시도를 넣는 통으로 사용하지 않음 |

이 목록은 **기록·표현을 위한 분류**다. 모델 후보마다 특정 행동을 자동으로 권장하거나 실행했다고 판정하는 대응표가 아니다.

### 행동과 결과를 나누는 기준

- 수유·교체·안기·토닥임·환경 변경은 행동의 수행 사실을 기준으로 한다. 아기가 계속 울어도 해당 조치를 표현한다.
- ‘트림시킴’과 ‘재워줌’은 이름 자체에 결과가 포함되어 있으므로 트림·잠듦 확인까지 필요하다. 시도 기록만으로 완료 표현을 만들지 않는다.
- “안고 토닥이며 재웠어요”는 재워줌 한 장면에 안기·토닥임이라는 수행 방식을 붙일 수 있다. 같은 돌봄을 표현 태그 수만큼 중복 집계하지 않는다. 독립된 여러 행동이라고 보고한 경우는 순서대로 보존한다.
- “수유했더니 잠들었어요”는 수유함 + 조치 후 잠듦이다. 별도의 재워줌 행동이나 배고픔 정답을 만들지 않는다.
- “트림을 시도했지만 안 나와서 등을 토닥였어요”는 트림시킴으로 분류하지 않는다. 명시된 토닥임은 실제 수행한 조치로 기록할 수 있다.
- 여러 조치 뒤의 상태는 조치 묶음에 연결할 수 있다. 어떤 한 행동이 효과를 냈는지 근거 없이 고르지 않는다.
- 작성자와 실제 수행자를 구분한다. 양육자의 관계·성별은 행동 범주를 늘리는 기준으로 쓰지 않는다.

## 5. 조치 후 상태와 변화

새 돌봄 기록에서는 **수행한 조치 + 조치 후 관찰 상태**를 함께 확인한다. 상태를 확인하지 못했으면 ‘상태 확인 못함’을 선택할 수 있다. 과거 기록에 상태 정보가 없다고 상태나 반응을 만들어 채우지 않는다.

조치 후 상태에는 2절의 동일한 8종을 사용한다. 별도 보고가 있는 경우에만 기존 전후 반응 5종을 덧붙인다.

| 전후 반응 | 뜻 |
|---|---|
| 진정됨 | 보호자가 전후를 비교해 진정됐다고 보고 |
| 일부 진정 | 전보다 일부 가라앉았다고 보고 |
| 변화 없음 | 전후가 달라지지 않았다고 보고 |
| 다시 욺 | 잠깐 가라앉은 뒤 다시 울었다고 보고 |
| 확인 못함 | 변화 여부를 확인하지 못했다고 명시 |

‘조치 후에도 우는 중’만으로 ‘변화 없음’을 자동 선택하지 않는다. 일부 진정됐지만 여전히 울 수도 있다. 저장 화면에서 전후 반응까지 매번 중복 입력하게 만들 필요는 없다.

## 6. 홈의 표시 순서

**마지막 보호자 관찰 상태 → 울음 감지·분석 중 → 모델 추정 → 조치와 후속 상태 확인 저장 → 조치 표현 → 최신 보호자 관찰 상태**

| 구간 | 화면에서 표현할 것 | 다음 단계 조건 |
|---|---|---|
| 평상시 | 마지막 확인된 보호자 관찰 상태와 관찰 시각 | 새로운 울음이 감지됨 |
| 울음 감지 직후 | 울음 감지·분석 중임을 나타내는 공통 표현 | 분석 결과 수신. 아직 원인별 표현을 선택하지 않음 |
| 분석 결과 | AI 추정 배지를 붙인 원인 후보 표현, 또는 유보·실패 안내 | 보호자가 조치와 후속 상태를 기록하거나 사건을 닫음 |
| 기록 확인 | 실제 조치와 조치 후 상태의 입력·확인 | 저장 성공. 입력 중 초안은 확정 표현을 바꾸지 않음 |
| 조치 표현 | 이번에 확인 저장한 조치, 여러 건이면 보고한 순서 | 표현이 끝나거나 사용자가 건너뜀 |
| 관찰 상태로 복귀 | 해당 조치 후 상태를 포함해 가장 최근 시점의 확인 관찰 상태 | 다음 관찰이나 새로운 울음 감지 |

표시할 모델 결과는 현재 아기·현재 울음 사건에 속해야 한다. 과거 관찰과 AI 추정은 각각 유지하고, 화면 전환을 위해 한쪽 기록을 다른 쪽으로 덮어쓰지 않는다.

- 조치 애니메이션이 끝났다고 웃는 얼굴이나 잠든 상태를 자동으로 보여주지 않는다. 실제 기록한 조치 후 상태로 돌아간다.
- 조치 후 새 관찰을 저장한 뒤 과거 울음 분석이 늦게 도착해도 홈을 과거 추정으로 되돌리지 않는다. 결과는 해당 사건의 로그에서 확인할 수 있다.
- 조치 표현 중 새로운 울음이 감지되면 새 사건의 감지·분석 표시를 우선한다. 이전에 저장한 조치 기록은 유지한다.
- 과거 기록을 추가·수정하거나 로그를 스크롤한다고 홈에서 당시 조치를 다시 재생하지 않는다. 기록 시각보다 관찰·수행 시각을 기준으로 최신성을 판단한다.
- 저장 응답 재수신·새로고침·다른 양육자의 기록 동기화만으로 같은 조치 표현을 반복하지 않는다. 동기화된 최신 관찰 상태는 갱신한다.
- 기록된 관찰이 30분을 넘으면 기존 계약대로 정지 그림과 경과시간을 강조한다. 해결하지 않은 추정 역시 분석 시각을 유지하고 오래된 결과를 현재 상태처럼 표현하지 않는다.
- 판단 유보와 실패는 해당 사건의 안내로 유지한다. ‘울음 확인 안 됨’으로 끝난 경우에는 감지 기록을 보존하고 마지막 관찰 화면으로 복귀한다. 모델이 아기가 편안하다고 확인한 것은 아니다.
- 동작 줄이기를 선택한 사용자는 같은 의미의 정지 표현을 거쳐 조치 후 상태로 이동한다. 아기·계정 전환과 권한 회수 시 이전 아기의 표시와 임시 재생 상태를 정리한다.

## 7. Git 그래프 느낌의 로그와 공통 에셋

**시간을 따라 이어지는 중심선에 보호자 관찰을 놓고, 울음 사건별 가지에 감지·추정·조치를 묶는다. 조치 후 관찰을 중심선에 연결한다.** 가지의 합류는 후속 상태 기록이 생겼다는 뜻이며, 울음 해결이나 모델 추정의 정답 확인을 뜻하지 않는다.

| 로그의 표시 항목 | 연결·표현 의미 | 사용할 정지 표현 |
|---|---|---|
| 보호자 관찰 | 해당 시점에 보고된 상태 | 관찰 상태 캐릭터 + 관찰 배지 |
| 울음 감지 | 울음 사건의 시작 | 감지 표시 + 발생 시각 |
| 모델 추정 | 해당 울음에서 나온 원인 후보 | 원인 후보 캐릭터·기호 + AI 추정 배지 |
| 완료한 조치 | 해당 사건과 연결된 실제 돌봄 | 양육자·아기 조치 장면 + 수행자 |
| 조치 후 관찰 | 돌봄 뒤 보고된 상태. 중심선에 한 번만 배치 | 같은 관찰 상태 캐릭터 + 조치 후 배지 |

개념 예시의 시간은 위에서 아래로 흐른다. 실제 로그는 최신 기록부터 표시하고 스크롤로 과거를 읽을 수 있게 한다.

```text
● 14:00 편안해 보임 · 보호자 관찰
│
├── 14:05 울음 감지
│   ◇ 14:06 배고픔 가능성 · AI 추정
│   ■ 14:10 수유함 · 보호자 A
│   ■ 14:12 트림시킴 · 보호자 A
│   │
●───┘ 14:15 잠듦 · 조치 후 관찰
│
```

14:15 관찰이 ‘우는 중’이어도 같은 방식으로 연결한다. 조치 후 관찰이 없으면 가지를 억지로 합치지 않고 ‘후속 상태 미기록’으로 남긴다. AI 추정 없이 수행한 평소 돌봄도 시간선에 기록할 수 있다.

에셋은 **같은 범주의 움직이는 표현과 대표 정지 포즈**를 한 쌍으로 관리한다. 관찰·추정·조치의 분류를 유지한 채 캐릭터 외형과 공통 부품을 재사용한다. 임의의 첫 프레임을 잘라 쓰기보다 작은 크기에서도 의미가 드러나는 대표 포즈를 정한다. 이번 단계에서는 실제 그림이나 동작을 제작하지 않는다.

추정은 AI 배지·점선 테두리, 확인된 관찰·조치는 출처·실선 테두리처럼 글과 형태로도 구분한다. 색만으로 의미를 나누지 않는다. 로그의 정지 그림에는 상태·조치 이름과 대체 텍스트를 붙인다.

- 가지는 **울음 사건** 단위다. 보호자마다 별도의 아기 상태가 있는 것처럼 분기시키지 않고, 수행자는 각 조치에 표시한다.
- 연결선은 기록의 순서·연관성을 뜻한다. ‘수유가 울음의 원인을 해결했다’는 인과관계 증명으로 사용하지 않는다.
- 실제 입력에 없는 행동을 모델 후보에 맞춰 채우거나, 가까운 시간이라는 이유만으로 관계없는 기록을 연결하지 않는다.
- 하나의 수유나 조치 후 관찰이 사건과 시간선 양쪽에 연결돼도 동일한 원본 기록을 참조한다. 횟수나 상태 기록을 복제하지 않는다.
- 로그 스크롤·과거 항목 선택은 홈의 현재 표현을 바꾸지 않는다. 확인·시도에 관한 일반 메모는 보존할 수 있지만 완료 조치 그림은 붙이지 않는다.

## 8. 현재 개발 계약과의 차이 및 후속 반영 범위

이번 작업은 **범주 구체화와 표시 기획**이다. [팀 계약 1.0.0](../../contracts/개발계약.md), [OpenAPI](../../contracts/openapi계약.json), [목 응답](../../contracts/목%20응답과%20시험%20사용자%20배치.json)을 새 계약으로 부분 변경하지 않았다. 아래는 기획을 실제 구현 계약으로 반영할 때 함께 바꿔야 할 접점이다.

| 현재 계약에서 확인한 사항 | 이번 기획의 변화 | 계약 반영 시 필요한 작업 |
|---|---|---|
| 관찰 상태 8종과 `visual_state_code` 존재 | 관찰 목록은 유지, 지속 상태 이름과 대표 표현 기준 구체화 | 화면 문구·상태 매핑 버전·조합 사례 일치 |
| `DIAPER_CHECK`, `SLEEP_PREPARATION`, 넓은 의미의 `BURPING` 포함 | 확인·시도를 완료 조치 표현에서 제외, 트림·수면 완료 기준 추가 | 기존 행동 기록을 보존하며 표시 자격·완료 근거 정의. 기존 코드를 그대로 ‘성공’으로 재해석하지 않음 |
| 토닥임은 전용 행동 코드 없이 `OTHER` 등에 들어감 | 토닥여줌을 별도 표현 범주로 분리 | 정규화·확인 입력·표현 매핑의 구조화 방식 결정 및 일치 |
| 수면 기록의 시작과 종료, 안기 등 수행 기록이 별도로 존재 | 재워줌과 수행 방식을 표현하되 중복 집계 금지 | 재우기 완료와 잠에서 깬 시점을 혼동하지 않는 연결·집계 규칙 |
| 모델 후보 코드는 자유 문자열, 실제 사용 범위는 등록된 지원 라벨로 제한 | 다섯 연구 라벨의 화면 의미와 유보 표현 지정 | 모델 능력 정보·라벨 매핑·지원하지 않는 값의 대체 표현 일치 |
| 홈은 마지막 확인 관찰만 표시하고 후보 점수로 표정을 선택하지 않음 | 모델 추정과 조치 표현을 별도 표시 단계로 추가 | 현재 관찰을 보존하는 홈 단계·출처·늦은 응답 규칙을 화면 매핑과 목에 반영 |
| 타임라인 항목은 `CARE_EVENT`, `EPISODE`, `STATE_OBSERVATION` | 사건 안의 감지·분석·행동·후속 관찰을 그래프처럼 표현 | 기존 식별자·관계·상세 조회로 공급 가능한지 확인하고 필요한 응답만 함께 확장 |

관련 업무는 A-04 기록·타임라인, A-06 결과·행동, A-07 정규화·그래픽, A-10 활성 감지, B의 분석·정규화·기록·타임라인 접점이다. 구현 계약으로 반영할 때는 [개발 원칙](../../DEVELOPMENT_PRINCIPLES.md)에 따라 팀 계약·OpenAPI·목 응답·화면 매핑·관련 검증을 같은 변경으로 맞춘다. 이 문서의 표시 항목은 새로운 API enum이 이미 추가됐다는 뜻이 아니다.

## 9. 범주·표시 흐름을 확인할 사례

| 입력·상황 | 기대되는 분류·표현 |
|---|---|
| 기저귀를 확인했더니 깨끗했어요 | 확인 메모. 완료 조치 애니메이션 없음 |
| 기저귀를 갈았지만 계속 울어요 | 기저귀 갈아줌 표현 → 우는 중 |
| 수유했고 조금 진정됐지만 아직 울어요 | 수유함 표현 → 우는 중. 전후 반응은 일부 진정 |
| 재우려 했지만 아직 깨어 있어요 | 재워줌 없음. 깨어 있음 관찰. 실제 안기·토닥임이 따로 보고됐다면 그 조치만 분류 |
| 안아서 재웠어요 | 재워줌, 수행 방식은 안기 → 잠듦. 같은 돌봄 중복 집계 없음 |
| 수유했더니 잠들었어요 | 수유함 → 잠듦. 재워줌·배고픔 정답을 자동 생성하지 않음 |
| 등을 토닥여 트림시켰지만 계속 울어요 | 트림시킴, 수행 방식은 토닥임 → 우는 중 |
| 조치는 했는데 이후 상태는 못 봤어요 | 구체적으로 확인된 조치 표현 → 상태 확인 못함 |
| 현재 사건의 배고픔 후보가 도착했어요 | 지원 범위·완료 상태 확인 후 AI 추정으로 표현. 보호자 관찰은 유지 |
| 모델이 판단을 유보하거나 실패했어요 | 유보와 실패를 구별. 특정 원인 표현 없음 |
| 조치 후 상태 저장 뒤 이전 분석이 도착했어요 | 홈의 새 관찰 유지. 분석은 과거 사건에 연결 |
| 로그를 과거로 스크롤했어요 | 정적 인포그래픽만 표시. 홈 상태 변경·조치 재생 없음 |

위 표는 향후 구현에서 확인할 기대 사례다. 실제 화면·API·권한·기기·모델 검증을 실행하거나 통과했다는 보고가 아니다.
