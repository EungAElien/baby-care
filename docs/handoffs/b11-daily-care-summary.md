# B-11 날짜별 생활 기록 집계 1차 인계

## 구현 범위

- 기존 `GET /v1/babies/{baby_id}/summary?date=...&timezone=...` 계약을 FastAPI에 연결했다. 현재 세션·멤버십·아기 상태를 DB에서 재확인하고, 요청 시간대가 현재 아기 설정과 다르면 409를 반환한다.
- 요약 조회는 반복 읽기 스냅샷에서 권한·맥락 리비전·기록을 함께 읽는다. 아기 행에 `FOR SHARE`를 걸면 PostgreSQL의 UPDATE RLS가 적용되어 일반 양육자의 행이 숨겨지므로 행 잠금을 사용하지 않는다.
- 활성 CareEvent 원본만 조회 시 계산한다. 아기 현지 날짜의 UTC 경계를 사용해 수면 원본 하나를 날짜별로 나누며, 진행 중 수면은 조회 시각까지만 계산하고 종료 시각 미상을 표시한다. 시간 미상 기록을 저장 시각의 날짜에 임의 배정하지 않는다.
- 수유 횟수·양이 알려진 횟수·양 미상 횟수·기록된 수유량·모유 수유 시간을 분리한다. 양을 모르면 합계는 `null`, 실제 입력한 0mL은 `0`이다. 기저귀 확인·교체는 각각 센다.
- 기록 범위의 확인 값이 없으면 빈 기록을 실제 0으로 단정하지 않고 `missing_fields`에 남긴다. 수유 0건이 명시적으로 확인된 날짜의 합계는 0으로 반환한다. 요약은 저장하지 않아 CareEvent 수정·삭제 후 다음 조회에서 다시 계산된다. `build_daily_summary`를 B-14가 재사용할 수 있다.

## 후속 경계

- `latest_confirmed_state`는 B-07의 상태 관찰 저장과 삭제 연결이 완료될 때까지 `null`이다. 기존 `record_coverage`의 `SLEEP_PREPARATION` 종류는 응답의 `SLEEP`으로 매핑한다. 확인 범위를 설정하는 API는 아직 구현 전이다.
- B-08 맥락·이전 사례와 준비 알림, 아기 상태 관찰, A의 실제 화면 연결은 이 변경에 포함되지 않는다.
- 단위 시험과 계약 경로 검사를 수행했다. 실제 Auth·Postgres·RLS 통합 시험은 전용 Supabase 시험 환경에서 실행해야 한다. 추가한 B-04 통합 시험은 수정·삭제 재집계, 멤버십 거절, 시간대 불일치를 검증한다.
