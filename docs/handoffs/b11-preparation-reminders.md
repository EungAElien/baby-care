# B-11 준비 패턴·개인 알림 인계

## 구현 범위

- `GET /v1/babies/{baby_id}/patterns`: 최근 7일의 활성·정확 시각 생활 기록과 날짜 확인 범위를 읽어 매번 계산한다. 수유는 같은 방식의 연속 시작 시각, 수면 준비는 깨어난 시각부터 다음 잠든 시각을 유효 간격으로 삼는다. 확인되지 않은 날짜를 건너뛴 간격과 미완료 수면은 제외한다. 확인한 날짜 3일·유효 간격 10개 미만 또는 IQR이 중앙값의 절반 초과면 시점 제안을 보류한다. 기저귀 패턴은 항상 수동 간격 전용이다.
- `PUT /v1/babies/{baby_id}/record-coverage`: 작성자별 날짜 확인을 버전·멱등키로 저장한다. 여러 보호자가 서로 다르게 확인한 날짜는 패턴에서 보수적으로 제외한다.
- `GET/PUT /v1/babies/{baby_id}/reminder-settings`: 설정 행이 없으면 해당 항목은 꺼짐이다. 수신자 본인만 설정을 읽고 바꾸며, 기저귀 알림을 켤 때 수동 간격을 요구한다.
- `GET /v1/babies/{baby_id}/reminders`: 수신자 본인의 알림만 계산·조회한다. 예정 시점은 생활 기록 기준 시점보다 10분 앞서며, 해당 시점부터 30분이 지나면 만료한다. 오래된 알림을 재방문 때 발행하지 않고, 기준 기록과 근거·시점이 같은 알림은 다시 만들지 않는다. 새 기록·수정·삭제·설정 끄기·근거 부족은 기존 활성 알림을 만료한다.
- `PATCH /v1/reminders/{reminder_id}`: 도착 알림의 10분 미루기, 이번 알림 끄기, 확인 시각 기록을 수신자 본인에게만 허용한다. 확인은 수행 행동을 생성하지 않는다. 이 API는 활성 화면과 홈 카드용 조회 경계이며 화면 밖 푸시는 포함하지 않는다.

## 검증과 남은 연결

- 패턴 단위 시험은 확인 날짜, 유효 간격, 변동성, 같은 수유 방식, 깨어남 기준, 기저귀 수동 전용을 검사한다.
- 실제 Auth·DB 통합 시험은 두 보호자 설정 분리, 타인 알림 접근 거절, 미루기·이번 끄기·중복 방지, 새 기록·삭제 후 만료를 검사하도록 추가했다. 로컬 Supabase가 있는 환경 또는 CI에서 실행해야 한다.
- B-08 안내·이전 사례와 A-09 홈 카드/활성 화면 연결 및 실제 두 기기 인수는 별도 남았다. 알림을 울음 예측 확률로 표시하지 않는다.
