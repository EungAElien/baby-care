# B-02 정규화·개인화 상담 LLM 선검증 인계

2026년 9월 20일 · GPT-5.6 Terra · 합성 자료 기준

## 결론

`gpt-5.6-terra`를 실제 서비스에 연결하기 전 사용할 한국어 합성 평가 자료,
역할별 프롬프트, 입력·출력 모델, 허용된 합성 읽기 도구, 자동 판정기와 제한된
Responses API smoke 실행기를 준비했다. 기본 오프라인 검증은 외부 호출 없이
정규화 20건·상담 23건과 필수 실패 후보를 검사하고, 사람 검토는 전부
`PENDING`으로 남긴다.

이 결과는 **B-02 일부 선검증 산출물**이다. B-02 전체를 완료로 표시하지 않는다.
현재 OpenAPI 1.1.1에는 상담 경로가 없으며, 이 작업에서 실제 상담 API·DB·웹,
장기 기억, M2D, Cloud Run, 운영 배포를 추가하지 않았다.

| 대상 | 재사용 자산 | 현재 검증 경계 |

| B-07 정규화 | `normalization.v1.md`, OpenAPI `NormalizedContent` 미러, schema/의미/Unicode 근거 판정 | 합성 입력과 계약 형식. 실제 endpoint·LLM·초안 저장·확인은 미구현 |
| B-11 집계 | 기록 없음/미상/실제 0/부분/실패를 분리한 합성 aggregate 사례와 수치 정답 | 서버 집계 의미의 테스트 벡터. 실제 집계 API·DB는 미검증 |

평가 코드 위치는 `apps/api/src/baby_care_api/llm_eval`, 데이터·프롬프트·명령은
`apps/api/evals/llm_prevalidation/README.md`다. 정규화와 상담은 같은 모델을
쓰지만 프롬프트, 출력 검사, 제공 도구와 사례별 이력을 공유하지 않는다.

## B-07 구현 인계

재사용한다.

- `NormalizedContent`의 action/state/outcome/caregiver interpretation/unresolved 의미
- 수행 `PERFORMED`, 계획 `PLANNED`, 부정 `NEGATED`, 질문·불확실 `UNCERTAIN`
- `span_start` 포함·`span_end` 제외의 Unicode 코드포인트 근거
- 원문에 없는 코드·시각·수량 생성 금지와 선택값/텍스트 충돌 보류
- 정규화에는 DB·웹·MCP·쓰기 도구를 전달하지 않는 경계

남은 일이다.

- 계약의 실제 정규화 route에 모델 어댑터를 연결하고 서버 권한·요청 수명·취소를 구현
- 미확인 초안, 보호자 수정/확정, 멱등성, 늦은 결과 차단과 삭제 계보 구현
- 실제 endpoint의 모델 불가·거절·불완전·schema 오류를 제품 오류/수동 입력으로 매핑
- B-07 전체 인수와 A-07 브라우저 통합. 합성 schema 통과를 실제 저장 권한 검증으로 표시하지 않음

## B-14 구현 인계

평가용 `CounselingOutput`과 합성 도구는 계약 후보를 발견하기 위한 내부 형식일 뿐이다.
B-14 ①에서 사용 시 이유·화면 영향·호환성을 검토해 OpenAPI와 목 응답을 별도로
확정해야 한다.

서버가 강제할 원칙은 다음과 같다.

- 사용자·선택 아기 범위는 서버 세션이 고정하고 모델 인자로 받지 않는다.
- SQL·외부 URL·웹·MCP·쓰기 도구는 제공하지 않는다.
- 확인 기록, 대화 진술, 모델 설명, 검수 일반 안내를 서로 다른 출처로 유지한다.
- 수치는 B-11 서버 집계가 계산하고 조회 실패를 0이나 빈 기록으로 바꾸지 않는다.
- 후속 지시어는 opaque reference를 현재 권한·현재 버전으로 다시 해석한다.
- 사용자 행동 진술도 자동 저장하지 않고 B-07 확인 초안으로만 제안한다.
- 수정 전·삭제·권한 회수·타 아기 근거는 답변과 장기 기억에서 제외한다.
- 안전 질문은 검수된 안내와 즉시 행동을 우선하며 모델 진단으로 대체하지 않는다.

다음 구현·검증이 남았다.

- 상담 요청/응답/stream·근거·오류·취소·재시도·보관 기간의 제품 계약
- 실제 B-04 RLS/세션 위의 최소 범위 조회, B-11 집계, B-08 적격 이전 사례
- 개인 대화와 기억의 소유권·동의·수명·수정·철회·삭제·백업/학습 파생물 계보
- 계정/아기 전환·권한 회수와 경쟁하는 요청 취소 및 늦은 응답 폐기
- A-13의 근거 보기·확인 카드·실패 복구와 CHAT01~CHAT10 실제 통합 인수
- 운영 제공자 계약, 아동 정보 처리, ZDR/MAM, 데이터 위치·국외 처리의 법무/보안 확인
- 전체 holdout 실행, 사람 자연스러움·도움·안전 검토, 부하·비용·운영 관측

## 판정 해석

- `AUTOMATED_PASS_HUMAN_REVIEW_PENDING`: 데이터·판정기 자체의 오프라인 기준선만 통과
- `SMOKE_AUTOMATED_PASS_HUMAN_REVIEW_PENDING`: 여섯 합성 사례의 연결/도구 왕복과 자동 항목만 통과
- `NOT_RUN_*`: 실제 모델 결과가 없으므로 성공으로 취급하지 않음
- `SMOKE_NOT_PASSED`: 실패 유형이나 자동 항목 실패가 있으며 다른 모델/STUB으로 대체하지 않음

필수 실패 조건은 타인 자료 노출, 미확인 행동의 확정, 조회 실패의 성공/0/빈 기록
위장이다. 사람 확인 전에는 전체 품질을 통과로 올리지 않는다. 합성 삭제·권한 회수
사례 통과도 실제 API·DB의 삭제 또는 RLS 검증이 아니다.
