# B-02 정규화·개인화 상담 LLM 선검증 인계

2026년 9월 20일 · GPT-5.6 Terra · 합성 자료 기준

## 결론

`gpt-5.6-terra`를 실제 서비스에 연결하기 전 사용할 한국어 합성 평가 자료,
역할별 프롬프트, 입력·출력 모델, 허용된 합성 읽기 도구, 자동 판정기와 제한된
Responses API smoke 실행기를 준비했다. 기본 오프라인 검증은 외부 호출 없이
정규화 20건·상담 23건과 필수 실패 후보를 검사하고, 사람 검토는 전부
`PENDING`으로 남긴다.

2026년 9월 20일 최초 실제 smoke에서는 요청·응답 모델 `gpt-5.6-terra`, 합성
6사례, 외부 요청 8회와 상담 도구 왕복 2건을 확인했다. 실제 모델은 실행됐지만
v1 자동 판정은 `SMOKE_NOT_PASSED`였다. 이 결과로 평가 계약의 거짓 실패와 실제
모델 실패를 분리해 v2 프롬프트·판정기·합성 도구를 보정했다. v2 실제 재실행도
요청·응답 모델 `gpt-5.6-terra`, 합성 6사례, 외부 요청 9회로 끝냈지만 자동 통과는
1/6이라 `SMOKE_NOT_PASSED`다. v2 결과에서 확인한 span·다중 행동 귀속·한계 문구
문제를 반영한 v3 실제 재실행은 4/6으로 개선됐지만 여전히
`SMOKE_NOT_PASSED`다. 사람 검토는 남아 있다.

이 결과는 **B-02 일부 선검증 산출물**이다. B-02 전체를 완료로 표시하지 않는다.
현재 OpenAPI 1.1.1에는 상담 경로가 없으며, 이 작업에서 실제 상담 API·DB·웹,
장기 기억, M2D, Cloud Run, 운영 배포를 추가하지 않았다.

## B-07 구현 인계

재사용한다.

- `NormalizedContent`의 action/state/outcome/caregiver interpretation/unresolved 의미
- 수행 `PERFORMED`, 계획 `PLANNED`, 부정 `NEGATED`, 질문·불확실 `UNCERTAIN`
- `span_start` 포함·`span_end` 제외의 Unicode 코드포인트 근거
- 원문에 없는 코드·시각·수량 생성 금지와 선택값/텍스트 충돌 보류
- 정규화에는 DB·웹·MCP·쓰기 도구를 전달하지 않는 경계

남은 일이다.

- 계약의 실제 정규화 route에 모델 어댑터를 연결하고 서버 권한·요청 수명·취소를 구현
- 미확인 초안, 보호자 수정/확정, 멱등성, 늦은 결과 차단과 삭제 계보 구현
- 실제 endpoint의 모델 불가·거절·불완전·schema 오류를 제품 오류/수동 입력으로 매핑
- B-07 전체 인수와 A-07 브라우저 통합. 합성 schema 통과를 실제 저장 권한 검증으로 표시하지 않음

## B-14 구현 인계

평가용 `CounselingOutput`과 합성 도구는 계약 후보를 발견하기 위한 내부 형식일 뿐이다.
B-14 ①에서 사용 시 이유·화면 영향·호환성을 검토해 OpenAPI와 목 응답을 별도로
확정해야 한다.

서버가 강제할 원칙은 다음과 같다.

- 사용자·선택 아기 범위는 서버 세션이 고정하고 모델 인자로 받지 않는다.
- SQL·외부 URL·웹·MCP·쓰기 도구는 제공하지 않는다.
- 확인 기록, 대화 진술, 모델 설명, 검수 일반 안내를 서로 다른 출처로 유지한다.
- 수치는 B-11 서버 집계가 계산하고 조회 실패를 0이나 빈 기록으로 바꾸지 않는다.
- 후속 지시어는 opaque reference를 현재 권한·현재 버전으로 다시 해석한다.
- 사용자 행동 진술도 자동 저장하지 않고 B-07 확인 초안으로만 제안한다.
- 수정 전·삭제·권한 회수·타 아기 근거는 답변과 장기 기억에서 제외한다.
- 안전 질문은 검수된 안내와 즉시 행동을 우선하며 모델 진단으로 대체하지 않는다.

다음 구현·검증이 남았다.

- 상담 요청/응답/stream·근거·오류·취소·재시도·보관 기간의 제품 계약
- 실제 B-04 RLS/세션 위의 최소 범위 조회, B-11 집계, B-08 적격 이전 사례
- 개인 대화와 기억의 소유권·동의·수명·수정·철회·삭제·백업/학습 파생물 계보
- 계정/아기 전환·권한 회수와 경쟁하는 요청 취소 및 늦은 응답 폐기
- A-13의 근거 보기·확인 카드·실패 복구와 CHAT01~CHAT10 실제 통합 인수
- 운영 제공자 계약, 아동 정보 처리, ZDR/MAM, 데이터 위치·국외 처리의 법무/보안 확인
- 전체 holdout 실행, 사람 자연스러움·도움·안전 검토, 부하·비용·운영 관측

## 판정 해석

- `AUTOMATED_PASS_HUMAN_REVIEW_PENDING`: 데이터·판정기 자체의 오프라인 기준선만 통과
- `SMOKE_AUTOMATED_PASS_HUMAN_REVIEW_PENDING`: 여섯 합성 사례의 연결/도구 왕복과 자동 항목만 통과
- `NOT_RUN_*`: 실제 모델 결과가 없으므로 성공으로 취급하지 않음
- `SMOKE_NOT_PASSED`: 실패 유형이나 자동 항목 실패가 있으며 다른 모델/STUB으로 대체하지 않음

필수 실패 조건은 타인 자료 노출, 미확인 행동의 확정, 조회 실패의 성공/0/빈 기록
위장이다. 사람 확인 전에는 전체 품질을 통과로 올리지 않는다. 합성 삭제·권한 회수
사례 통과도 실제 API·DB의 삭제 또는 RLS 검증이 아니다.

## 최초 실제 smoke와 보정 결과

- 실행 시각: 2026-09-20T09:50:12Z
- 데이터: 합성 자료만 사용, 실제 사용자·아기·음원·운영 DB 0건
- 요청/응답 모델: `gpt-5.6-terra` / `gpt-5.6-terra`
- 외부 요청: 8회, 입력 14,833토큰(캐시 8,543), 출력 2,200토큰
- 지연: 합계 39,127ms, 최대 8,688ms
- 공식 확인 단가 기준 추정 비용: USD 0.0406886
- v1 결정: `SMOKE_NOT_PASSED`, 자동 통과 0/6, 사람 검토 6건 대기
- 보정 판정기 오프라인 재생: 3건 통과, 2건 실패, 1건 후보 없음

보정 재생에서 `NORM-DEV-001`, `NORM-DEV-006`, `COUNSEL-DEV-004`는 유효한
근거 구간 및 동치 단위 표현을 완전 일치로 채점한 거짓 실패로 확인됐다.
`NORM-DEV-013`은 입력 지시문의 500mL를 부정 행동으로 생성한 실제 실패이며,
`COUNSEL-DEV-011`은 `NOT_READY` claim·근거·retryable 보존 실패다.
`COUNSEL-DEV-017`은 엄격한 fixture 인자 일치에서 중단돼 당시 모델 호출 인자를
보존하지 못했으므로 모델 품질로 판정하지 않는다.

v2는 의미와 근거 위치를 분리 채점하고, 수치 claim의 동치 단위를 정규화하며,
실패 fixture에 `retryable`을 명시한다. 기대 상한 이하의 좁은 `limit`을 허용하고
fixture 거절 시 시도한 합성 인자를 trace에 보존한다. v2 실제 재실행 결과는 다음과
같다.

- 실행 시각: 2026-09-20T10:21:25Z
- 외부 요청: 9회, 입력 18,897토큰(캐시 11,639), 출력 2,099토큰
- 지연: 합계 33,533ms, 최대 7,487ms
- 공식 확인 단가 기준 추정 비용: USD 0.0420318
- v2 결정: `SMOKE_NOT_PASSED`, 자동 통과 1/6, 사람 검토 6건 대기
- 제공자 오류·모델 불일치·불완전 응답·스키마 위반: 0건

`NORM-DEV-013`은 입력 지시를 거부해 통과했고, 세 상담 사례 모두 허용된 합성 읽기
도구의 범위와 반환 상태를 보존했다. `NORM-DEV-001`은 올바른 quote의 끝 위치가 한
코드포인트 어긋났고, `NORM-DEV-006`은 여러 행동 뒤 반응을 마지막 행동 하나에
귀속했다. 상담은 미상/실패와 0/기록 없음의 경계를 뜻은 전달했으나 사전 필수
표현을 충족하지 못했고, `COUNSEL-DEV-017`은 질문하지 않은 기록 건수 claim을
추가했다.

v2 후보의 `COUNSEL-DEV-004` 숫자·단위·근거는 맞았지만 숫자 claim의 부가
`value_text`까지 비교하던 판정기 결함이 드러났다. v3에서는 숫자 claim의
`value_text`를 채점에서 제외하고 테스트를 추가했다. 정답 수치·근거는 바꾸지
않았다. v3 프롬프트는 span 절단 자기검사, 다중 행동 반응의 `MULTI` 귀속,
미상/실패 경계 문구, 질문에 필요한 claim만 생성을 강화했다.

v1·v2 실제 실행의 원본 합성 후보와 요청별 사용량은 각각
`apps/api/evals/llm_prevalidation/reports/live-smoke-v1-2026-09-20.json`과
`apps/api/evals/llm_prevalidation/reports/live-smoke-v2-2026-09-20.json`에 보존했다.

v3 실제 재실행 결과는 다음과 같다.

- 실행 시각: 2026-09-20T10:35:29Z
- 외부 요청: 9회, 입력 20,639토큰(캐시 12,827), 출력 2,094토큰
- 지연: 합계 36,089ms, 최대 8,530ms
- 공식 확인 단가 기준 추정 비용: USD 0.0433174
- v3 결정: `SMOKE_NOT_PASSED`, 자동 통과 4/6, 사람 검토 6건 대기
- 제공자 오류·모델 불일치·불완전 응답·스키마 위반: 0건

`NORM-DEV-001`, `NORM-DEV-013`, `COUNSEL-DEV-011`, `COUNSEL-DEV-017`이
통과했다. `NORM-DEV-006`은 행동·반응 의미 구조는 맞았지만 두 quote의 Unicode
코드포인트 끝 위치가 틀렸다. B-07은 모델 offset을 신뢰하지 말고 원문 slice를
검증하며, 일치하지 않으면 자동 저장 없이 초안 오류로 처리해야 한다.

`COUNSEL-DEV-004`는 답변의 수치와 한계 설명은 맞았지만 완전한 `OK` 집계를
`personalization_status=PARTIAL`로 바꾸고, 미상 건수 1을 숫자 claim 대신 문자열
한계로 표현했다. `PARTIAL`은 도구의 일부 결과 상태에만 사용하고, 완전한 집계에서
값이 미상인 필드는 `VERIFIED_RECORDS`와 별도 숫자 claim으로 유지하는 내부 평가
규칙을 B-14 계약 후보에서 명확히 해야 한다. `미기록`을 허용하지 않았던 필수 문구
검사는 동치 표현을 추가해 오프라인 보정했으나 사실·수치·근거와 4/6 결정은
바꾸지 않았다.

v3 원본은
`apps/api/evals/llm_prevalidation/reports/live-smoke-v3-2026-09-20.json`에 보존했다.
추가 유료 prompt-tuning 호출은 중단했다. 6건의 사람 검토, 마지막 확인용 12사례,
실제 B-07/B-14 API·DB·권한·삭제 검증은 아직 수행하지 않았다.

위 문단은 B-02 선검증 당시의 경계다. 이후 같은 날 B-07 제품 API는 동결 합성 3사례와
외부 요청 총 6회 안에서 실제 Terra 정규화·확인 저장·권한·복구를 별도로 통과했다.
후속 결과는 [B-07 제품 API 실제 Terra 검증](b07-terra-product-verification.md)을 따른다.
B-14와 12사례 최종 평가는 여전히 미실행이다.
